# Tooltip auto-size and overflow

Last synced: 2026-11-11

`UiPopupAutoSize.None/Width/Height/Both` selects viewport sizing in `ArrangeMeasured`. The fixed-size `Arrange` API rejects auto-size. `UiPopupMeasureRequest` now supplies nullable Width, Height, MaxWidth and MaxHeight. Enabled axes clear prior inline dimension/max values at the start, then target-width matching runs before offset/flip. After shifting, available space updates caps and explicit dimensions when needed. Changed measured dimensions reset coordinates while retaining flip history, offset data and arrow state. Arrow-only resets retain coordinates and rerun cover/shift. Negative available CSS dimensions are ignored as invalid style values.

Migration: `IUiPopupMeasurement<T>.Measure` now returns `UiPopupContentMeasure(Size, ContentSize)`. Size is the positive finite visible body; ContentSize is the nonnegative finite scroll extent after wrapping at the resolved width. Respect requested dimensions/caps and any intrinsic border/padding minimum. A one-argument result constructor uses the same extent for both. `UiPopupLayout.Measurement` records final constraints and ContentSize records overflow. The sample measures actual Type200 text at each width and clips paint to the body.

Each visible tooltip maintains its own `ScrollOffset`, clamps it after content changes and resets it on release. Pointer hover and both wheel axes use the frontmost root-clipped tooltip body from the previous paint. Equal tiers follow paint order. An immovable axis remains available to the enclosing viewport without scrolling an occluded tooltip. Escape requests take priority over tooltip wheel handling. Presentations translate content by `ScrollOffset` and clip it to their viewport. `UiTooltipOptions.ScrollStep` defaults to 48 logical units.

Set `UiTooltipOptions.ShowScrollbars = true` to draw overlay scrollbars on overflowing axes. The controls use the tooltip's viewport and theme, and leave its measured size and text wrapping intact. Press a track to scroll or drag its thumb, including outside the viewport. The active tooltip owns the pointer until release, dismissal, Escape or loss of that scrollbar. The custom contract FBA opts in. The bars are Duxel overlays. Browser scrollbar geometry remains open.

An accessible visible tooltip with overflowing content exposes the Windows UIA Scroll pattern even when its overlay bars are hidden. `Scroll` uses `ScrollStep` for a small increment and the measured viewport for a large increment. `SetScrollPercent` uses 0–100 for each scrollable axis and `-1` to leave an axis alone. Actions apply before painting and publish the resulting position in the same frame. A fitting or dismissed tooltip loses its Scroll pattern. [Microsoft Scroll pattern](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingscroll).

When the tooltip remains visible, UIA receives property changes for the new scroll percentages, view sizes, scrollability and Scroll pattern availability. If the content shrinks to fit, both axes report `-1` percent, `100` view size and `false` scrollability on the same tooltip.

With `Positioning.RightToLeft`, horizontally overflowing content starts at its right edge. UIA reports `0` at the right and `100` at the left, and the vertical overlay scrollbar is placed on the left. Custom presenters receive `UiPopupLayout.ScrollOffset` in physical coordinates and subtract it from the content origin when painting.
