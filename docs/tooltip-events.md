# Visible Tooltip nodes and events

Last synced: 2026-11-19

A visible, accessible `UiTooltip` now publishes a `UiAccessibilityRole.Tooltip` child beneath its actual primary target. Its name is the frame's tooltip text; its ID is the target relationship's logical `SourceId`. Hidden descriptions continue through target HelpText without a surface node. `Inaccessible` suppresses the surface node and its events.

Windows exposes control type50022, a nonfocusable plain-text control-view element, with no content-view membership, Invoke or Value pattern. The [official ToolTip contract](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supporttooltipcontroltype) defines those view and naming rules. This extends [target accessibility](tooltip-accessibility.md); it does not add `Fluent.Tooltip` to the factory catalog.

`UiAccessibilityTree.AutomationEvent` reports `TooltipOpened` and `TooltipClosed`. Frame validation precedes notifications. Close observers run before removal; open observers run after publication. Neither runs under the publication lock. Observers may read or queue actions; recursive publication/disposal is rejected. Unchanged visible frames do not reopen a tooltip, and aborted frames produce no visibility transition. Reopening preserves logical ID and creates a new runtime identity.

The Windows bridge uses [UiaRaiseAutomationEvent](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcoreapi/nf-uiautomationcoreapi-uiaraiseautomationevent), with opened20000/closed20001. UIA retains the provider while event handlers finish. A close event therefore carries immutable source and ancestor providers captured before removal, including screen bounds, focus state and a fragment root retaining the native host COM interface. Asynchronous UIA caches can read that graph after tree and HWND disposal without calling the destroyed window. Event snapshots expose no control actions and are not inserted into the live provider cache. Ordinary removed providers immediately become unavailable; UIA's references determine the lifetime of the event graph.

During an ordinary frame, Windows stages Tooltip events in publication order. The window's existing UIA cleanup message disconnects removed live providers before raising those events. This allows the close to keep its original runtime identity without a disconnect cancelling its delivery. An open uses the live provider when its identity still matches and otherwise uses its captured properties. The Core notification marks shutdown closes with `DuringDisposal`. Windows sends those closes before tearing down the HWND.

The ABI reference is Microsoft win32metadata commit `15fc870a5e96df7c560877ff30136c0fb5a21e9b`, preserved under `artifacts/tooltip-events-2026-11-11`. The client uses source-generated COM for `IUIAutomationEventHandler` and requests cached Name, ControlType, focusability and AutomationId before subscribing.

`UiAccessibilityTree.TextPropertyChanged` publishes old and new text values after the changed element is available to readers. A still-visible tooltip sends `Name` for a text change without reopening. A target sends `HelpText` when its effective description changes, including when its tooltip is hidden. A tooltip label can change the target's effective `Name`. Explicit accessible names still take precedence. Unchanged projected values produce no notification. Windows sends the corresponding property ID and BSTR values through [UiaRaiseAutomationPropertyChangedEvent](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcoreapi/nf-uiautomationcoreapi-uiaraiseautomationpropertychangedevent).

The separate UIA client receives both new values with the matching source AutomationIds and reads the same text from the retained live providers. Managed tests check old values, publication order, hidden descriptions and label precedence. Evidence is in `artifacts/tooltip-uia-text-properties-2026-11-11`.

On Windows, `WM_CLOSE` requests shutdown through `ShouldClose`. The host stops frame production and disposes the backend. Tree disposal reports one managed `TooltipClosed` per still-visible surface while its target ancestry can be read. The backend disconnects live UIA providers before destroying the HWND and releases its provider association on `WM_DESTROY`. Consumers running their own backend loop must dispose it after stopping their producer.

A retained live provider becomes unavailable after window teardown. The separate external observer receives the final `TooltipClosed` with the original cached Name, ControlType and AutomationId and `IsOffscreen = true`. Product shutdown does not wait for a client marker. The original controls and their logs are in `artifacts/tooltip-shutdown-pump-2026-11-11`.

## Linux AT-SPI

The Linux Gallery publishes hidden descriptive text on the target's `Description` and sets `has-tooltip`. Label mode provides the target's name without repeating the text as a description. A visible ToolTip is a nonfocusable child with the `showing` state. AT-SPI notifies the target of child addition and removal. When a ToolTip closes, its retained native object becomes defunct and the target keeps its description. Reopening publishes a new native object. [AT-SPI roles](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/enum.Role.html) and [states](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/enum.StateType.html).

In the Gallery, open **Alerts and progress → Tooltip** and use **Toggle tooltip visibility**. The external probe runs the same control through AT-SPI, observes two complete lifecycles and checks the actual object tree. In the same Linux desktop session as the Gallery, run `dotnet <Duxel.Linux.App.Tests.dll> atspi-gallery-tooltip <gallery-pid> <new-result.json>`. The probe opens the page itself.

Fresh Linux x64 managed and NativeAOT Gallery builds from SDK 11.0.100 each passed all four checks on WSLg. Both used runtime 11.0.0 and both Gallery and external client processes exited normally with empty stderr. The build logs, executable hashes and two results are in `W:/Cache/Duxel/gallery-source-20261117/tooltip-atspi-2086`. The probe verifies the AT-SPI protocol and does not exercise a screen reader.

The keyboard probe uses `dotnet <Duxel.Linux.App.Tests.dll> x11-gallery-tooltip <gallery-pid> <new-result.json> <decimal-x11-window-id>`. It focuses the automatic Tooltip target through AT-SPI, then sends Escape, Tab and Shift+Tab directly to the owned X11 window. Escape closes the Tooltip and retains focus and help text. The Tooltip stays closed during a 750 ms observation. Tabbing away and returning opens a new ToolTip accessible object. The same hash-verified .NET 11.0.0 managed and NativeAOT Gallery binaries each passed all six checks on WSLg, and all four processes exited normally. See `W:/Cache/Duxel/gallery-source-20261117/tooltip-x11-2087`.
