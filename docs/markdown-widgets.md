Code blocks follow the same rule. Opening and closing fences and the language name appear only while editing that block. Moving to another block or switching to the preview displays only the code body, so a single line of code renders as one line. Incomplete fences follow the parsed syntax; literal backticks in the code body are preserved.

Rendering includes emphasis, combined bold/italic, strikethrough and angle autolinks. Task lists use Fluent checkbox visuals; edit their `[ ]`/`[x]` source to change state. Thematic breaks use the same Fluent theme palette. Subscript, superscript, inserted and marked extensions are not enabled, so `~text~`, `^text^`, `++text++` and `==text==` remain literal text.

Pipe tables render headers, borders, left/center/right column alignment and empty cells. Parsed source positions remain attached to each cell; editing a table reveals its complete source in the same buffer. Cells do not wrap internally. Wide tables scroll horizontally in the editing viewport while paragraph wrapping remains enabled. Source edits request one immediate follow-up frame, allowing a preview painted earlier in the frame to refresh in event-wait mode.

Document parsing and previews accept LF, CRLF and CR line endings. Editing normalizes line endings to LF through the shared multiline input policy.

```csharp
var markdown = new UiState<string>("# Title\n\nA **bold** paragraph.");
using var editor = Dux.MarkdownEditor("Document", markdown.Binding, new(Height: 480));
using var view = Dux.MarkdownView("Preview", markdown.Binding, new(Height: 480));
```

Options control width, height, source limit, wrapping, border and read-only editing. Width zero fills the available allocation. The default height is420 and the default limit is1,048,576 UTF-16 units. Static content can use `Dux.MarkdownView(markdown)`.

Set `view.Navigate = uri => ...` to provide application navigation. Set `new UiMarkdownOptions(BaseUri: new Uri("https://example.com/docs/"))` for relative destinations. Without a base, a custom callback receives the relative URI. The default `UiLinkNavigation.OpenExternal` accepts absolute HTTP, HTTPS and mailto destinations and reports launch errors through exceptions; application routes and other schemes require a custom callback.

Tab and Shift+Tab traverse viewer links after the document's text-selection stop; Enter follows the focused destination. A wrapped label is one stop with an outline around each displayed fragment. Focusing an offscreen link reveals it in the document viewport. Space does not follow links, and dragging still selects text. Physical screen-reader use still requires further qualification.

Focus changes also reveal the visible link fragment through enclosing `Dux.ScrollView` owners, from the inside outward, without requiring an accessibility tree. The next requested frame paints adjusted ancestor offsets. Unchanged focus preserves manual scrolling and does not affect sibling viewports. This contract covers owned ScrollView ancestors; legacy window scrolling has a separate implementation.

Parsing uses pinned Markdig1.4.0 with source spans. A source revision reparses once per document; caret movement within a block reuses the display projection. Source/display boundary mapping keeps the original Markdown authoritative. IME composition has an independent projection and cannot replace committed syntax. Styled line heights are shared by painting, selection, hit testing, caret scrolling and IME rectangles.

Images use `![alternative text](destination)` in both view and editor. Set `ResolveImage` to map a URI to an immutable `UiImageSource`; PNG and SVG can use the existing registered image decoder or an application's preloaded sources. `BaseUri` resolves relative destinations. No file or network request starts implicitly. Returning null, an absent resolver or an invalid URI displays an explicit unavailable-image alternative; unexpected resolver exceptions remain visible to the caller.

## Managed SVG and native image checkpoint — 2026-11-14

The SVG backend is now managed geometry/rasterization with Windows DirectWrite/WIC and Linux HarfBuzz/GdkPixbuf. Windows deploys no Skia/HarfBuzz/image-codec DLL. The Linux native HarfBuzz assets are target-specific. Existing resource/reload/LRU, zoom/rotation and font-snapshot contracts remain. See [SVG platform rendering](svg-platform-rendering.md) and `artifacts/svg-managed-2026-11-14/verification.json`; the earlier Skia checkpoints are historical.

`UiAccessibilityNode.ImageInfo` optionally publishes immutable `UiAccessibilityImageInfo` with the complete rendered rectangle before clipping, description and optional locale. Ordinary `Node.Bounds` remains clipped. Projected resolved Markdown images provide it; decorative images remain omitted, unavailable captions do not advertise a native image. Linux exposes `org.a11y.atspi.Image` only when this metadata exists: description, locale, size, position and extents in screen/window/parent coordinates. An unspecified locale is an empty protocol string. Size encloses rendered logical geometry in native integer pixels and can differ from the source bitmap dimensions. Source-range reveal and keyboard selection remain unchanged; generic Component.ScrollTo and physical-reader qualification remain open.
