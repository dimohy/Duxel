# 배경 독립 합성과 런타임 페인트 그룹

`UiBackdropImage`는 준비된 참조 이미지 두 개를 합성합니다. `UiPaintGroup`는 순수 그리기 콜백을 실제 GPU 대상에 캡처한 뒤 결과를 한 번 합성합니다. 두 API는 같은 식을 사용합니다. 투명 검정 배경의 B와 불투명 흰색 배경의 W에서 커버리지는 `C = 1 - W + B`, 최종 결과는 `B * opacity + destination * (1 - C * opacity)`입니다. RGB와 알파 커버리지는 독립적이므로 알파가0인 LCD 마스크의 RGB도 보존합니다.

`UiPaintGroup` 소유자는 프레임 콜백 바깥에서 유지합니다. `ui.PaintGroup(group, bounds, contentVersion, paint, opacity)` 또는 `UiControlContext`의 같은 메서드를 호출합니다. `paint`에는 컨트롤 그리기 컨텍스트가 전달됩니다. 이 콜백은 그리기만 수행하며 레이아웃·입력 처리·응용 프로그램의 부수 효과를 넣으면 안 됩니다. 내용 버전·논리 크기·DPI마다 한 번 실행됩니다. 최종 불투명도나 위치만 바꾸면 캡처를 재사용합니다. 테마·문자열·이미지 식별자가 바뀌면 내용 버전을 올립니다. 기존 의존 텍스처의 픽셀만 갱신하면 GPU 캡처가 자동 무효화되며, 관계없는 텍스처 갱신에는 재캡처하지 않습니다.

원본 좌표는 한 번 캡처하며 이후 배치는 저장된 원본 뷰포트를 사용합니다. 최종 결과에는 현재 부모의 클립을 적용합니다. 중첩 그룹은 자식부터 처리합니다. 의존성 순환·누락된 원본 텍스처·외부 그리기 콜백·가변 GPU 입자 프레임은 명시적으로 실패합니다. 원본 스냅샷은2D여야 하며 바깥쪽 배치는 기존 프레젠테이션 체계를 사용할 수 있습니다. 이후 캡처에서 참조할 수 있는 원본 이미지와 자식 그룹 소유자는 계속 유지해야 합니다.

`UiPaintGroupContent`는 정점·인덱스·분석적 도형·명령 상태를 복사합니다. `Acquire()`는 독립적으로 해제할 수 있는 `UiPaintGroupLease`를 반환합니다. 렌더 갱신은 임대를 대기 프레임에 넘기며, 클립 크기를 조정한 프레임 복사본은 별도 임대를 얻습니다. 렌더러도 자체 임대를 유지합니다. 생산자가 교체되거나 해제되어도 앞서 대기한 스냅샷은 바뀌지 않습니다. 그룹은 UI 스레드에서 해제합니다. GPU 텍스처는 장치 전체를 강제로 기다리지 않고 기존 프레임 펜스로 지연 해제합니다. 컨텍스트 종료는 소유자를 분리하고, 장치 종료는 아직 캡처하지 않은 정의도 해제합니다.

렌더러는 주 화면 패스 전에 일반 그리기를 두 번 실행하며, 색상 대상 쓰기와 셰이더 읽기 사이에 명시적 전환을 둡니다. 대상은 현재 파이프라인의 색상 형식과 샘플 구성을 사용하고, MSAA가 켜지면 중간 대상 하나를 두 패스에서 재사용합니다. 이전 GPU 제출에서 참조하는 텍스처 슬롯은 그동안 바뀌지 않습니다. 의존성 검사는 화면 이미지를 획득하기 전에 실행합니다. 장치 크기 한도·descriptor 슬롯·논리 대상 예산도 오프스크린 할당 전에 검사합니다. 그룹이 없는 프레임은 그룹용 명령 탐색을 건너뜁니다.

복사한 기하는64MiB, 최종 색상 대상 두 개의 합계는64MiB로 제한합니다. 살아 있는 모든 그룹의 논리 색상·MSAA 대상 합계는256MiB로 제한합니다. 네이티브 할당 정렬·스테이징·기하 캐시·해제 대기 자료는 이 예산에 포함되지 않으며 프로세스 메모리 측정값도 아닙니다. 계약을 전달하기 위한 명령·렌더 갱신 메타데이터도 늘어납니다. 최초 캡처에는 CPU 복사와 GPU 작업이 추가됩니다. 전체 프레임 속도 향상이나 메모리 감소를 뜻하지 않습니다.

`PaintGroupPasses`, `PaintGroupDrawCalls`, `PaintGroupCacheHits`로 비용을 나누어 봅니다. 전체 `DrawCalls`에는 캡처의 그리기도 포함됩니다. 지우기만 하는 캡처는 draw가0이어도 패스를 실행할 수 있습니다. 불변 캡처는 오프스크린 패스를 생략하며, 획득한 화면 이미지의 변경 영역 복구는 별개입니다. 입력과 이벤트 대기 예약 방식은 그대로입니다.

저장소 루트에서 `./run-gallery.ps1`를 실행하고 **렌더링** 탭을 엽니다. 앞의 세 블록은 준비된 참조를 불투명도0/0.5/1로 합성합니다. 오른쪽 블록은 겹친 빨강·초록 도형을 런타임에 캡처하고 불투명도0.8을 한 번 적용합니다. 애니메이션 타이머는 만들지 않습니다.

균일한0.875배 축소의 최종 해상도 글자는 아래 범위에서 검증했습니다. 임의 회전·원근 변환의 글자 품질·비활성 Avatar 통합·일반 대화형 위젯 하위 트리 캡처·강제 색상·고정 RC3 NativeAOT·원래 부하와 메모리 등의 전체 완료 기준은 남아 있습니다. 비활성 Avatar를 명령별 불투명도로 대체해서는 안 됩니다. 런타임 캡처 작업에서는 셰이더 바이너리를 바꾸지 않았습니다.

소유자 하나는 컨텍스트·프레임마다 내용 정의 하나를 가집니다. 같은 정의를 여러 위치·불투명도로 사용하는 것은 지원하지만, 같은 프레임 중간에 버전·크기·DPI를 바꾸면 앞선 그리기를 덮어쓰기 전에 거부합니다. 다른 정의에는 별도 소유자를 사용합니다. 그린 뒤 프레임을 닫기 전에 소유자를 해제해도 현재 스냅샷은 유효합니다. 출력 파괴 요청은 다음 프레임으로 넘기고 현재 스냅샷은 자체 임대를 유지합니다.

## 변형된 글자의 최종 해상도 캡처

`rasterScale`은 캡처 DPI에 곱해지며 캐시 키에도 포함됩니다. 최종 배치가0.875배라면 캡처도0.875배로 지정하여 글자 래스터화와 비트맵 크기를 최종 픽셀 수에 맞춥니다. 캡처 뒤에는 컨텍스트 DPI를 복구합니다. 중첩 캡처는 별도 모드를 지정하지 않으면 현재 캡처 DPI와 글자 모드를 이어받습니다.

기본값은 `UiPaintGroupTextMode.PhysicalLcd`입니다. 변형된 글자에는 `Projected`를 지정합니다. fragment 단계는 기존 투영 글자 커버리지 평균을 사용하고 vertex 단계는 평면 상태를 유지합니다. 전용 파이프라인 specialization이 기존 SPIR-V를 그대로 재사용하므로 일반 그리기와 컬러 이미지·도형 경로는 바꾸지 않습니다. 이 fragment specialization은 로컬 클립도 사용하므로 명령마다 클립 상수를 초기화합니다. 원본 색상 전체를 회색으로 바꾸는 모드가 아닙니다.

렌더링 탭에서 실제 한글·영문을0.875배 해상도로 캡처한 결과를 확인합니다. 비활성 Avatar도 이 경로를 사용하며 [검증 범위](fluent2-avatar.ko.md)를 참고하세요. 전체 모션·강제 색상 적합성은 남아 있습니다.
