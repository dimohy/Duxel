# 공통 위젯 변환 계약

상태 : `UiWidget.Margin`과 `UiWidget.Transform`을 공통 경로로 구현했습니다. 대표 버튼·체크박스·슬라이더·편집기와 중첩 클립·접근성 점 조회를 검증했으며, SVG의 Zoom/RotationDegrees도 같은 Transform을 사용합니다. 전체 위젯·복잡한 문자 조형·팝업·화면 읽기 적합성은 미완료입니다.

## 공통 여백 사용

```csharp
var button = Fluent.Button("실행", Run);
button.Margin = new UiEdgeInsets(12, 8, 20, 10);
```

순서는 왼쪽·위·오른쪽·아래입니다. 모든 UiWidget이 같은 속성을 상속하며 SVG 전용 Margin은 제거했습니다. 값은 유한한 0 이상이어야 합니다. 여백은 측정과 흐름에 포함되지만 클릭·호버·접근성의 콘텐츠 영역에는 포함되지 않습니다. 변경 시 부모의 보관된 측정을 무효화합니다. 기본 0 값은 추가 렌더 래퍼를 만들지 않습니다.

Implementation Observer의 `위젯 배치` 탭에서 네 방향을 1px씩 조절하고 버튼·체크박스·슬라이더·입력창을 조작할 수 있습니다. 회전·확대·시각 변환과 회전 중심도 같은 탭에서 조절합니다. `공통 여백 초기화`는 네 값을 0으로 돌립니다. 버튼·체크박스 클릭, 입력 편집·캐럿 이동, 키보드 포커스, 네 여백의 비클릭, 부모 제약·측정 무효화, Build 구성·빈 콘텐츠 수명은 15개 집중 검사로 확인했습니다. 모든 변환의 완료 기준과 구분합니다.

현재 Windows 관리 빌드는 다음 명령으로 실행합니다. `위젯 배치` 탭을 선택하세요.

## 공통 변환 사용

```csharp
button.Transform = new UiWidgetTransform(Scale: 1.5f, RotationDegrees: 90);
button.Transform = new UiWidgetTransform(RotationDegrees: 30,
    Origin: new UiVector2(0, 0), Mode: UiWidgetTransformMode.Visual);
```

기본 Layout 모드는 변환된 실제 경계를 측정하여 다음 위젯의 공간을 예약합니다. Visual 모드는 원래 크기와 배치 앵커를 유지하며 회전 중심에 따라 그리기 위치가 달라집니다. 자체 할당 경계로 잘라내지는 않지만 부모의 클립은 유지합니다. Layout의 경계 정규화는 회전 중심으로 생기는 평행 이동을 상쇄할 수 있습니다.

`UiWidgetTransform`은 불변 값입니다. 같은 값을 매 프레임 재할당해도 변경을 발생시키지 않습니다. 기본 Identity 경로는 추가 캡처를 만들지 않습니다. 공통 affine 좌표 모듈이 측정·그리기·역변환 입력·접근성·IME를 연결합니다. 원래 모서리와 부모의 정확한 클립을 구분하며, 부모 마스크에는 행렬이 포함됩니다. 창이나 할당 슬롯이 없는 자연 흐름은 무한 최대 제약으로 측정하고, 명시적인 0 크기 부모는 0으로 유지합니다. 스크롤 본문의 남은 화면 높이를 자식의 할당 높이로 오인하지 않습니다.

SVG 문서와 래스터 캐시는 SVG 모듈이 소유하며 확대 품질 요청에는 중첩 변환의 합성 배율을 사용합니다. 회전·여백 변경은 XML을 다시 파싱하지 않습니다. 호스트의 DPI와 논리 글자 크기는 변환 때문에 변경하지 않습니다. Windows 벡터 글리프의 복잡한 스크립트 조형과 화면 기준 팝업 포털은 후속 검증 범위입니다.
## 사용자 요구

- SVG 브라우저 비교의 실제 위젯에도 확대·회전·여백 조절이 적용되어야 합니다.
- 회전·확대된 콘텐츠는 실제 경계 크기로 측정·배치되어 다음 항목과 겹치거나 자체 영역에 잘리지 않아야 합니다.
- 여백은 Margin이며, 그리기 좌표만 바꾸는 Translate와 구분합니다.
- 콘텐츠 모서리는 변환 전에 둥글게 처리하고 콘텐츠와 함께 회전·확대합니다. 부모의 클리핑은 별도입니다.
- 회전 중심은 왼쪽 위·중앙·오른쪽 아래 등 상대 위치로 지정할 수 있어야 합니다.
- 이 계약은 SVG 전용 기능으로 남기지 않고 UiWidget 공통 계층에 적용합니다. 버튼도 실제로 회전하고 조작할 수 있어야 합니다.

## 책임 경계

공통 계층은 여백, 아핀 변환, 순수 측정, 배치, 그리기 좌표, 역변환 입력, 접근성 좌표를 소유합니다. SVG는 문서·래스터 해상도·텍스처 수명만 특화합니다. 기존 SVG 전용 측정·배치 처리는 공통 경로 검증 후 통합하며 중복 구현을 완료로 남기지 않습니다.

기본은 변환 후 경계를 배치에 반영하는 레이아웃 변환입니다. 배치 원점을 유지한 채 지정한 중심으로 움직이는 시각 변환을 별도로 지원합니다. 자동 배치가 변환된 경계를 원점으로 정규화하면 회전 중심에 따른 위치 효과가 상쇄될 수 있으므로, 두 의미를 한 속성에 섞거나 원점 선택을 조용히 무시하지 않습니다. [공식 변환 설명](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/transforms-overview)을 참고합니다.

전체 위젯 검증 분모는 현재 미확정입니다. 이 표의 설계나 일부 버튼 테스트를 전체 구현 완료로 세지 않습니다. 기존 UiLayer3D·할당 자식 렌더링·입력 슬롯·순수 측정·접근성 게시 경로를 먼저 재사용하고, 필요한 공통 좌표 계약만 승격합니다. 실제 소비와 회귀 검증 없이 공개 속성을 추가해 무동작 상태로 두지 않습니다.

아핀 클립의 변경 스냅샷은 모양과 뒤따르는 변환 행렬을 함께 비교합니다. 행렬만 바뀌어도 새로 드러나거나 가려진 픽셀을 갱신하며, 획득 이미지가 모두 안정되면 draw가 다시 0이 됩니다. 실제 MSAA1/4 검사는 직사각형·둥근 모서리·원형 클립과 부모/자식 역회전 변경을 포함합니다. 투영된 위젯 장면은 기존의 보수적인 전체 갱신을 유지하며, 임의 3D 장면의 부분 갱신을 보장하지 않습니다.

공통 변환 팝업: **위젯 배치**에서 회전·확대·여백을 조절한 뒤 **변환 팝업**, **변환 메뉴**, **변환 도구 설명**을 사용하세요. 트리거는 변환되지만 팝업은 화면 좌표로 바로 서서 열립니다. 부모의 회전·클립·포인터·접근성·IME 좌표를 공통 범위에서 분리하고, 닫으면 이전 위젯 좌표를 복원합니다. 지연 Tooltip도 화면 앵커를 보관하며 마우스가 창 밖에 있어도 호출자 표시 상태를 유지합니다. 선언형 Popover·메뉴·Tooltip과 기존 BeginPopup·BeginTooltip·모달·Combo·메뉴 경로를 검증했습니다. 임의 3D 카메라의 모든 조합과 화면 읽기 적합성은 남아 있습니다.

위젯 배치 → 기존 팝업 API에서 공통 회전·확대를 적용한 채 열기·실행·닫기를 확인합니다. 기존 Combo의 세 오버로드는 공통 화면 앵커 계산을 사용합니다. 팝업 너비는 원래 본문 너비와 변환된 트리거 너비 중 큰 값이며, 부모의 회전 클립을 벗어나 화면 안에 배치합니다. 화면 팝업은 부모의 벡터 텍스트 강제를 상속하지 않습니다.

화면 팝업은 진입 시점의 부모 카메라 레이어까지 텍스트 모드에서 분리합니다. 팝업 안에서 새로 연 카메라 레이어는 그대로 적용됩니다. 보관 레이어는 실제 벡터/화면 텍스트 모드를 함께 기억하므로 StaticCache와 동일 ContentVersion에서도 모드가 바뀌면 다시 구성하고, 이후에는 재사용합니다. MSAA1/4에서 부모 이동·회전, 중첩 2D 레이어, 변환 위젯, 모드 전환·복원 픽셀을 비교했습니다. 원래 고정 RC3 NativeAOT·전체 3D 입력·화면 읽기 검증과 구분합니다.
