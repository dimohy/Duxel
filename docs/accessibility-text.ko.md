# 공통 접근성 텍스트 상태

`UiAccessibilityNode.TextInfo`는 확정된 텍스트와 커서·선택을 나타냅니다. 기본 한 줄·여러 줄 입력, SearchBox·Combobox 편집기·SpinButton의 공통 커널이 실제 편집에 사용하는 상태를 게시합니다. SpinButton의 숫자 범위와 입력 중인 텍스트는 별개입니다. 지우기·옵션 선택·단계 변경으로 확정한 텍스트와 메타정보는 같은 프레임에서 갱신합니다. IME 조합 중인 문자열은 확정된 텍스트에 넣지 않습니다.

사용자 동작·표현에서는 `UiInputEditResult.AccessibilityText`·`UiMultilineEditResult.AccessibilityText`를 읽을 수 있습니다. 선택적인 데이터이며 접근성 트리가 없으면 만들지 않습니다. 기본 커널은 `CanSetSelection`을 표시하며 별도로 만든 텍스트 상태는 기본적으로 관찰만 허용합니다.

`UiAccessibilityTextContent`는 변경할 수 없습니다. `CharacterCount`·`GetText`·`GetUnicodeScalar`와 문자 오프셋은 UTF-16 단위나 글자 묶음이 아닌 Unicode 스칼라를 사용합니다. `GetUtf16Offset`·`GetCharacterOffset`은 정확한 삽입 경계를 변환하고 서로게이트 쌍 중간의 위치는 거부합니다. 잘못된 UTF-16과 역순 범위도 명시적으로 실패합니다. 예를 들어 `가😀`는 스칼라2개·UTF-16 단위3개이며 결합 문자는 편집기에서 한 묶음이어도 스칼라가 여러 개일 수 있습니다.

`UiAccessibilityTextInfo.CaretUtf16`·`AnchorUtf16`은 선택 방향을 유지하며 문자 오프셋도 별도로 제공합니다. 이전 스냅샷은 이후 편집이나 트리 해제 뒤에도 읽을 수 있습니다. 변경 없는 프레임은 상태 객체를, 커서만 움직이면 내용·문자 맵을 재사용합니다. BMP 텍스트에는 오프셋 배열이 필요하지 않습니다. 기존 게시 항목을 캐시로 사용하며 전역 사전이나 편집기 캐시 필드를 추가하지 않았습니다. 캐시·수명 계약이며 처리 속도 개선을 측정했다는 뜻은 아닙니다.

렌더링 중 입력을 그린 뒤 같은 ID 범위에서 `ui.GetAccessibilityTextInfo(id)`를 호출하세요. 이번 프레임에 만든 상태만 읽으며, 상태가 없거나 아직 그리지 않았거나 접근성이 연결되지 않았다면 null입니다. 이전 프레임으로 대신하지 않습니다. Linux 샘플 맨 아래에서 실제 스칼라 수·커서·선택을 확인할 수 있으며 표시 자체는 갱신을 예약하지 않습니다.

다른 스레드에서 동작을 요청할 때는 게시된 트리 스냅샷과 런타임 ID를 사용합니다.

```csharp
var element = tree.CaptureSnapshot().Elements.Single(e => e.Node.Id == id);
var current = element.Node.TextInfo ?? throw new InvalidOperationException();
var end = current.Content.GetUtf16Offset(2);
var desired = new UiAccessibilityTextInfo(current.Content, end, 0);
var admission = tree.RequestTextSelection(id, element.RuntimeId, desired, wait: false);
```

`wait: false`는 완료가 아닌 접수 결과입니다. 기본 동기 호출은 렌더 스레드 밖에서 실행하며 편집기의 처리 결과를 반환합니다. `CanSetSelection`과 정확히 같은 게시 내용 객체가 필요하고 오래되거나 별도로 만든 내용은 거부합니다. 실제 반영 전에도 텍스트·사용 가능 상태를 다시 검사하므로 접수 후 모델이 바뀌거나 비활성화되면 오래된 위치를 적용하지 않습니다. 읽기 전용 선택은 허용하며 텍스트와 키보드 포커스는 바꾸지 않습니다. 글자 묶음 내부나 표시할 수 없는 스타일 경계의 요청은 다른 곳으로 조용히 옮기지 않고 InvalidArgument를 반환합니다.

현재 관리형 .NET11 컨트롤189건에서 오프셋·잘못된 텍스트·스냅샷 수명·재사용·실제 커서/선택 이동·오래된 요청/비활성 거부·읽기 전용/여러 줄·범위를 적용한 조회·지우기/옵션/단계 변경의 일치를 확인했습니다. Linux 검사59건은 앱/세션38건과 경계 모듈21건이며 실행 경로별 네이티브101건은 실제 제품 렌더러에서 실행합니다. 근거는 `artifacts/linux-accessibility-2026-11-14/text-boundaries-verification.json`입니다.

## Linux 네이티브 Text

TextInfo를 게시하는 노드에만 여덟 번째 인터페이스인 [AT-SPI Text](https://github.com/GNOME/at-spi2-core/blob/main/xml/Text.xml)를 부분 제공합니다. CharacterCount/CaretOffset, GetText, GetCharacterAtOffset, GetNSelections/GetSelection, SetCaretOffset/AddSelection/SetSelection/RemoveSelection을 지원합니다. 네이티브 위치는 Unicode 스칼라 단위입니다. GetText의 끝은 범위에 포함하지 않으며 -1은 문서 끝을 뜻합니다. 잘못된 조회에는 프로토콜 오류를, 잘못된 변경에는 false를 반환합니다. 연속된 선택 하나를 지원하므로 AddSelection은 두 번째 선택을 거부하고 SetSelection은 기존 선택을 바꾸며 RemoveSelection은 현재 커서에서 선택을 접습니다. 반대 방향 선택의 기준점·커서는 내부에 유지하고 조회한 범위는 시작·끝 순서로 반환합니다. SelectableText는 자식 Selection과 구분합니다.

변경은 기존 렌더 스레드 요청과 검사 경로를 거칩니다. 게시한 위치가 바뀌면 TextCaretMoved·TextSelectionChanged를 보냅니다. TextChanged는 삭제 후 삽입 순서로 스칼라 시작 위치·길이와 정확한 UTF8 문자열을 전달합니다. 변하지 않은 스냅샷에는 텍스트 이벤트를 보내지 않으며 교체 시 공통된 앞뒤 문자 범위는 유지합니다. 독립 libatspi 클라이언트에서 캐시를 지우지 않고 실제 한글·이모지 조회, 선택 방향·거부, 포커스 유지, 커서·선택 이벤트와 실제 Backspace/되돌리기의 삭제·삽입 문자열을 확인했습니다.

## 게시한 그리기 좌표

`UiAccessibilityNode.TextLayout`은 TextInfo.Content와 정확히 같은 내용 객체에 연결된 변경 불가능 `UiAccessibilityTextLayout`을 선택적으로 게시합니다. GetCharacterExtents/GetRangeExtents는 클라이언트 좌표를 사용하고 GetOffsetAtPoint는 그리기 클립을 검사하며 GetLineRangeAt은 실제 표시 줄의 스칼라 원문 범위를 반환합니다. 문자 상자는 글리프 잉크가 아닌 글자 묶음의 논리 상자입니다. 결합 문자는 같은 상자를 공유하고 상자 안의 점은 첫 스칼라 위치를 반환합니다. 빈 범위는 너비0인 삽입 위치를 반환하며 범위 상자는 해당 줄들을 둘러쌉니다. 스크롤 시 내용 객체를 유지하며 상자를 옮깁니다. 텍스트·측정 환경·원점·클립·표시 줄 버전이 같으면 좌표 객체도 재사용합니다. 과거 좌표는 재배치와 트리 해제 이후에도 유지됩니다.

한 줄 입력은 실제 편집 영역·내용 원점·줄 높이·스크롤·편집기가 사용하는 앞부분 너비를 따릅니다. 일반 줄바꿈 입력은 실제 표시 줄 맵을 재사용하며 자동 줄바꿈과 명시적 줄바꿈의 원문 범위를 모두 포함합니다. SearchBox 지우기·Combobox 옵션 확정·SpinButton 단계 변경 뒤의 최종 텍스트에 맞춰 좌표를 게시합니다. 뒤늦은 숫자 포커스 확정에서는 이전 초안을 그린 좌표를 제거합니다. 실제 한 줄/여러 줄 입력을 클릭하면 같은 접근성 키보드 포커스를 얻습니다. 네이티브 검사에서는 보고한 문자 상자를 실제 X11 이벤트로 클릭하고 편집기 커서가 맞는지 확인합니다.

AT-SPI는 화면/창/부모 좌표의 GetCharacterExtents/GetRangeExtents/GetOffsetAtPoint와 문자/실제 줄 단위 GetStringAtOffset을 추가로 지원합니다. 픽셀 변환 시 소수 x 좌표 때문에 너비0인 삽입 위치를 너비1로 늘리지 않습니다. 클립 밖의 점은 -1, 잘못된 범위는 프로토콜 오류를 반환합니다. 아직 IME 조합 중이거나 스타일/Markdown 줄 맵 또는 줄바꿈 없는 기존 여러 줄 경로이면 좌표를 게시하지 않으며 조회에는 가짜 좌표 대신 NotSupported를 반환합니다. 속성, 제한 범위·스크롤, 전체 스타일 편집, 보호 텍스트·물리 IME/화면 읽기 프로그램 검증이 남아 있습니다. 한 줄 좌표를 처음 만들 때는 기존 편집기의 앞부분 너비 측정을 사용하며 큰 문서의 생성 비용은 성능 검증을 마치지 않았습니다. 원래 플랫폼·전체 목표 완료로 보지 않습니다.

## 검사하는 범위 편집과 Linux EditableText

`UiAccessibilityTextInfo.CanEditText`는 ReadOnly 권한과 별도로 공통 범위 편집 기능을 표시합니다. 기존 네 인수 선택 상태 생성자는 유지하며 명시적인 다섯 인수 생성자에서 이 기능도 지정할 수 있습니다. 일반 한 줄·여러 줄 편집기는 이를 게시하고 스타일/Markdown 여러 줄 편집기는 아직 범위 편집을 표시하지 않습니다. `UiAccessibilityTextEdit`에는 정확히 같은 게시 Content, Replace/Copy/Cut/Paste 종류, 시작·끝 순서의 UTF16 원문 경계와 Replace에만 사용하는 교체 텍스트가 있습니다. Paste는 삽입 범위를 사용합니다. Insert와 Delete는 각각 같은 시작·끝 또는 빈 교체 문자열을 가진 Replace입니다.

렌더 스레드 밖에서 현재 스냅샷·런타임 식별자를 읽고 요청합니다.

```csharp
var element = tree.CaptureSnapshot().Elements.Single(e => e.Node.Id == id);
var content = element.Node.TextInfo!.Content;
var edit = new UiAccessibilityTextEdit(content, UiAccessibilityTextEditKind.Replace, 0, 0, "정");
var result = tree.RequestTextEdit(id, element.RuntimeId, edit);
```

렌더 커널은 클립보드 접근·변경 전에 현재 텍스트·활성/표시 상태·권한·글자 묶음 경계를 다시 검사합니다. 오래되거나 별도로 만든 Content, 잘못된 제어 문자/UTF16·경계·길이 초과는 명시적으로 실패하며 입력을 잘라 넣지 않습니다. 여러 줄의 CR/CRLF는 기존 LF 정규화 계약을 사용하고 탭이나 한 줄의 줄바꿈 제어 문자는 거부합니다. 기존 버퍼·이력을 통해 실행 취소 한 단계와 삽입 끝 커서를 만들며 포커스를 빼앗지 않습니다. 변경한 텍스트가 마지막 게시 값과 일치해야 동기 호출을 성공으로 완료하고 뒤늦게 바인딩이 거부하면 Failed를 반환합니다. `wait: false`는 여전히 접수 결과만 반환합니다.

읽기 전용 Copy는 선택·커서·텍스트를 유지하고 다른 읽기 전용 편집은 클립보드를 읽기 전에 거부합니다. 별도 네이티브 클립보드 대신 앱에 설정한 IUiClipboard를 사용합니다. 알려진 클립보드 IO 오류·시간 초과는 Failed/Timeout을 반환하며 잘라낼 원문을 지우거나 일부 텍스트를 넣지 않습니다. 효과를 적용하기 전과 클립보드 호출 후에 취소 상태를 확인합니다. 이미 실행 중인 동기 클립보드 호출은 취소하거나 되돌릴 수 없으며 클립보드·편집기·외부 바인딩 전체를 아우르는 트랜잭션은 아닙니다.

아홉 번째 부분 인터페이스인 [EditableText](https://github.com/GNOME/at-spi2-core/blob/main/xml/EditableText.xml)는 정의된 내용 메서드 여섯 가지 SetTextContents·InsertText·DeleteText·CopyText·CutText·PasteText를 구현합니다. 위치·범위는 스칼라 단위이며 InsertText의 길이는 UTF8 바이트 단위입니다. 온전한 앞부분을 삽입하고 길이가 원문보다 크면 전체를 사용하며 음수나 스칼라 중간을 자르는 바이트 수에는 false를 반환합니다. CopyText에는 반환 bool이 없으므로 거부 시 D-Bus 오류를 반환합니다. 기능 표시는 읽기 전용·비활성 권한을 무시하지 않습니다.

공통 검사는 오래된 내용·접수 후 변경·읽기 전용 복사·길이 초과·글자 묶음 경계·잘못된 클립보드 텍스트·IO/시간 초과·줄바꿈 정규화·바인딩 거부·실제 Ctrl+Z/Y를 확인합니다. 독립 libatspi 검사에서는 실제 앱의 여섯 메서드·UTF8 앞부분·금지 문자·길이 제한·이력·포커스를 확인하고 이름을 지정한 별도 클립보드 selection만 공유합니다. 전체 스타일·조합 편집, 물리 화면 읽기 프로그램/IME와 나머지 Text API 검증은 남아 있습니다.

## Unicode 단어·문장·문단 조회

GetStringAtOffset은 이제 스칼라 문자·단어·문장·실제 표시 줄·문단의 다섯 단위를 지원합니다. 단어·문장 범위는 요청한 스칼라 위치 이하의 시작점부터 다음 시작점까지이며 사이의 구두점·공백을 유지합니다. 단어 사이의 구분자나 이모지는 앞 단어 시작점의 범위에 포함합니다. 문서 끝에서는 앞 단어·문장 범위를 반환하고 문자 조회는 기존의 빈 끝 범위를 유지합니다. 문단 구분자에는 CRLF·Unicode 문단 구분자가 포함되며 U+2028은 줄 구분자로 남습니다. 마지막 구분자 뒤의 빈 문단을 유지하고 빈 텍스트의 모든 단위 조회는 빈 범위를 반환합니다.

네이티브 AT-SPI 시작 시 Pango1.0 ABI 라이브러리 libpango-1.0.so.0이 필요하며 이번 검증 버전은1.52.1입니다. 이 라이브러리의 Unicode/언어 분할과 문단 탐색을 사용합니다. 완전한 문단의 문맥을 처리하고 UTF8 바이트 결과가 스칼라 경계를 지키는지 검사한 뒤 스칼라 위치 표를 유지합니다. 현재 UI 문화권을 언어 태그로 사용하며 고정 문화권에는 언어 미지정을 뜻하는 `und`를 지정합니다. 영어 규칙이나 구두점만 보는 방식으로 대체하지 않습니다.

Linux는 이 정보가 있을 때만 `org.a11y.atspi.Image`를 제공합니다. 설명·언어·크기와 화면·창·부모 기준 위치·영역을 읽을 수 있으며, 언어가 없으면 빈 프로토콜 문자열을 반환합니다. 크기는 실제 렌더링 영역을 감싸는 정수 픽셀이므로 원본 비트맵 크기와 다를 수 있습니다. 원문 범위로 드러내기와 키보드 선택은 유지합니다. 일반 Component.ScrollTo와 실제 화면 읽기 검증은 남아 있습니다.
