The low-level `PlatformTextParagraphObject` contract reserves one U+FFFC source character with width, height and distance from its top to the baseline. Requests validate ordered unique source positions and finite geometry and copy the object array. Existing constructors remain available; an additional constructor accepts objects. Windows uses actual [IDWriteInlineObject](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nn-dwrite-idwriteinlineobject) metrics and returns source positions, native top-left allocations and direction through `PlatformTextParagraphLayout.Objects`. No substitute glyph is painted and no COM object escapes in the snapshot. Finite baselines may lie outside the object, including negative values and values exceeding its height. Owned widgets consume native allocations while preserving centered alignment. Linux Pango shape code is connected but runtime qualification is pending. Markdown images and task markers consume native object allocations; quotes and rules share paragraph layout. Table cells also consume native paragraphs through immutable source slices.

`IPlatformTextParagraphBackend` shapes a complete paragraph with explicit font/style intervals, wrapping width and base direction. `PlatformTextParagraphRequest` copies typography and validates complete UTF16 coverage before native execution. Intervals cannot split surrogate pairs; positive infinity explicitly selects no wrapping and zero remains a valid width.

`PlatformTextParagraphLayout` holds source-based lines, two-dimensional carets, line geometry and immutable glyph runs. Runs preserve their style index, exact font resource, original order, bidi level, offsets and fractional native origin. Raster/vector painting consumes those glyphs without reshaping substrings. No COM handles escape into the managed snapshot.

Line `Length` excludes the hard newline preserved by `NewlineLength`. `Advance` includes trailing source whitespace; `WidthWithoutTrailingWhitespace` measures formatted wrapped content without deleting source positions or changing carets. Core preserves the designed line rhythm while applying the same native geometry to painting and interaction.

Windows uses one explicit-font DirectWrite TextLayout; Linux uses one private explicit-font Pango layout with size/font intervals, wrapping and base direction. Literal `UiInlineText` shares native lines, measurement, caret/selection geometry and cached raster/vector runs on both platforms. Existing font-atlas allocation, dependencies and invalidation manage GPU resources. Paint-color changes do not reshape the paragraph.
