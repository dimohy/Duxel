# 관리 할당 검증

버튼 동일 값 대입 검사는 같은 독립 루프를 최소 0.25초 예열한 다음 최종 측정합니다. 기준은 그대로입니다. 동일한 label/size 대입 10,000회에서 할당은 0바이트이고 추가 프레임 요청이 없어야 합니다. `NoInlining`은 테스트의 측정 경계에만 적용합니다. 제품 setter와 런타임 설정은 바꾸지 않았습니다.

저장소 예열 정책을 적용한 것입니다. 기존 큰 검사 메서드는 콜드 실행과 루프 전환을 할당 측정 구간에 섞었습니다. 변경 후 빌드는 3회 중 2회 12,336바이트로 실패했고 기준 빌드는 3회 통과했습니다. 같은 프레임 설정의 독립 재현에서도 콜드 실행 3회 중 2회 6,192바이트가 나왔습니다. 대입별 측정은 타이밍이 달라져 0바이트였고 디스어셈블리에서 instrumented Tier0·Tier1 OSR 코드를 확인했습니다. 측정 민감성을 보여주지만 정확한 할당 원인을 증명하지는 않습니다.

독립 루프를 예열한 재현은 기본 JIT의 독립 실행 3회 모두 0바이트였습니다. 교정한 전체 수명 검사도 기본 JIT의 독립 실행 3회에서 각각 101검사·대입 할당 0바이트·초기 무효화 요청 2회를 통과했습니다. 최종 실행에는 tiered compilation이나 PGO 비활성화가 필요하지 않았습니다. 다중 행 회귀도 17검사를 통과했습니다.

근거: `artifacts/jit-allocation-2026-11-11/verification.json`. 이전 실패와 런타임 디스어셈블리를 보존합니다. 정상 상태 관리 할당 검사 근거이며 콜드 시작 무할당·기존 런타임 할당 스택의 규명·현재 NativeAOT·전앱 성능 검증을 대신하지 않습니다. [런타임 Dynamic PGO 설계](https://github.com/dotnet/runtime/blob/main/docs/design/features/DynamicPgo.md)는 계측과 프로파일링을 설명하지만 관측한 바이트를 해당 기작에 귀속하는 것은 아직 추론입니다.

Progress/Slider/Toggle에도 같은 독립 루프 예열 규칙을 적용했습니다. 교정 전 기본 JIT 독립 실행 3회는 각각 12,336바이트·추가 요청 0회였습니다. 교정 후 3회는 수명101검사를 모두 통과했고 해당 setter의 할당 0바이트·추가 요청 0회였습니다. 제품 setter·런타임 설정·엄격한 판정은 유지하며 기존 할당 스택 귀속은 미확정입니다. 근거: `artifacts/text-commands-2026-11-11/verification.json`.
