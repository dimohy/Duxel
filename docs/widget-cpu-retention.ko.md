## 공통 레이아웃과 기하 재사용 · 2026-11-19

Windows .NET 11 관리형 빌드에서 Wrap과 Grid에 자식을 각각 1만 개 넣고 예열한 뒤, 같은 제약으로 1,000회 측정했습니다. 두 컨테이너가 기존 배치를 재사용해 자식 측정 호출과 측정 구간의 메모리 할당이 모두 0이었습니다. Checkbox·Slider·RadioGroup을 각각 1,000개 넣은 별도 검사에서도 예열 뒤 자식 재측정은 0회였습니다.

자식 크기와 상태가 바뀔 때는 기존 측정을 무효화했습니다. 순서가 있는 입력 검사 597건을 통과했으며, 프레임 슬롯 1개와 3개에서 입력을 모두 처리한 뒤 한 번 그린 결과가 매번 전체를 그린 기준과 일치했습니다. 기하 재사용과 캐시 수명은 아틀라스 텍스트 검사에서도 확인했습니다. 이 측정은 준비된 레이아웃과 검사 장면에 해당합니다. 전체 앱의 프레임 시간과 메모리는 별도 검증 범위입니다. 근거는 `L:/Cache/Duxel/cpu-reuse-2134/verification.json`에 있습니다.

## 캐시 상한과 프레임 수명 · 2026-11-19

Windows .NET 11에서 텍스트 캐시에 서로 다른 요청 900개를 넣어도 항목 256개와 기하 256 KiB 상한을 지켰습니다. 캐시를 비우고 그리기 버퍼를 재사용한 뒤에도 보관한 프레임의 기하 좌표는 그대로였습니다. DirectWrite 검사에서는 화면에 남아 있는 레이어의 텍스처를 유지했고, 레이어를 제거하면 캐시가 평상시 상한으로 돌아왔습니다.

Vulkan 프레임 슬롯 1개와 3개에서 SVG·이미지·둥근 이미지와 벡터 캐시의 수명을 확인했습니다. 컨테이너의 배치 무효화와 위젯 해제도 다시 검증했습니다. 이 결과는 캐시와 프레임 소유권의 범위를 다룹니다. 고부하에서 앱 전체의 메모리 증가는 별도 검증이 남아 있습니다. 근거는 `L:/Cache/Duxel/cache-lifetime-2133/verification.json`에 있습니다.

## 공통 위젯 저장소,2026-11-06

생성된 컨테이너와 상속한 사용자 위젯은 같은 UiBuildContext를 사용한다. 상태 의존성 사전과 Build 복구·제거 목록은 실제 사용할 때 생성하며, 해제 시 내부 저장소 참조를 끊는다. 직접 그리는 위젯은 BuildContext가 들어갈 참조 슬롯에 프레임 콜백을 보관하고, 구성·소유권이 필요해지면 해당 문맥으로 콜백을 이전한다. 별도 래퍼 객체 없이 기본 위젯 크기를 줄인다. 생성기의 정적 레이아웃·표현 타입 선택은 유지한다.

## 이번 공통 구현

`UiDrawListBuilder.TextRuns.cs`는 반복 요청의 atlas 텍스트 기하를 소유 배열로 보관한다. 최초 요청은 작은 메타데이터만 기록하고 두 번째 동일 요청에 기하를 보관하며, 세 번째부터 원래 glyph 레이아웃·kerning·snap·clip 계산을 건너뛴다. 기존 builder scratch에 복사하고 현재 명령의 사용자 데이터를 적용하므로 큐에 들어간 프레임은 캐시 교체와 독립적이다. 원래 예상 글자 수 기준 flush 경계와 명령 병합도 유지한다.

한 builder당 최대256개 항목, 최대256KiB 기하, 항목당 최대256 UTF-16 code units다. 문자열·키·관리 객체는 이 기하 바이트와 별도이며 항목 수·글자 수로 상한을 둔다. 120프레임 이상 사용하지 않은 항목은60프레임 주기 검사로 해제하며 `_ClearFreeMemory`도 소유권을 해제한다. 제한을 넘는 텍스트와 관찰 콜백이 있는 요청은 원래 생성기를 매번 실행한다.

측정 캐시는 실제 atlas 객체에 종속된 `ConditionalWeakTable`로 분리했다. 객체 해시 충돌로 다른 폰트의 결과를 재사용하지 않고, 캐시가 사용이 끝난 큰 atlas를 영구 보존하지 않는다. 폰트별512개·문자열256자 상한을 유지하고 캐시 접근을 동기화한다. `MissingGlyphObserver`가 있는 측정은 매번 실행한다. null 행높이와 명시적 -1도 다른 키다.

Tooltip은 소유한 대상에 위임하고 Field·Tooltip·사용자 래퍼가 protected CanRetainOwnedMeasurement를 공유합니다. 기본 조합은 false를 유지하며 Build나 본문을 자동으로 추론하지 않습니다. 새 캐시나 위젯 필드는 추가하지 않습니다. 실제 편집·되돌리기와 Tooltip 예약·표시·Escape는 계속 처리합니다. Field/Tooltip은 렌더링에서도 크기 소비 경로를 호출하며, 아래의 검증된 소유 자식 크기 단계가 알려진 불변 결과를 재사용합니다. 원래 전체 CPU·수명·동작·부하 검증과 기존 즉시 모드 소비 경로는 이번 범위만으로 완료하지 않습니다.

## 검증된 소유 자식 크기 — 2026-11-12

자연 크기 Field 위젯과 Tooltip이 자식의 명시적 제약으로 기존 UiRetainedLayout을 공유합니다. 살아 있는 자식이 측정 재사용에 동의하고 텍스트 환경도 허용할 때만 소유자별 단일 크기 결과 캐시를 선택적으로 생성합니다. 기본 UiWidget 저장소는 늘리지 않습니다. 최초 크기 확인은 자식 검증·측정을 실행합니다. 이후 리소스·텍스트 키와 제약이 맞아야 재사용하며, 앞서 검증한 자연 크기와 같은 렌더링용 고정 할당도 재사용할 수 있습니다. 조회 전마다 소유권·폐기 상태를 확인합니다. 알 수 없는 자식·글리프 관찰·기존 즉시 모드 AutoField에는 이 캐시를 적용하지 않습니다.

자식·소유자 무효화는 참조를 해제하고 기존 리비전을 증가시킵니다. 무효화·실패한 시도는 등록할 수 없으며, 크기 소비 경로는 같은 프레임의 오래된 준비 기하도 빌리지 않습니다. 기존 컨테이너의 준비 배치 동작은 별도로 유지합니다. 실제 렌더링·입력 값·필드 메타데이터와 비활성 범위·편집/되돌리기·팝업 예약/그리기/동작은 계속 처리합니다. Dispose는 단일 결과 캐시를 해제합니다. 추가 소유 캐시의 저장량은 제한되지만 전체 앱 Private·작업 집합·장시간 증가 및 고정 RC3 NativeAOT 성능은 별도 미완료 항목입니다.
