# 원형 영역을 투명하게 잘라내기

`UiDrawListBuilder.CircleCutout(center, radius)` 또는 `UiControlContext.CircleCutout(center, radius)`로 그리는 내용에서 원 하나를 뺍니다. 기존 사각형 클립도 함께 적용합니다. 빈 곳에는 배경색을 덧칠하지 않아 뒤의 실제 픽셀을 보존합니다. 중심은 유한한 좌표,반경은 유한한 양수여야 합니다.

```csharp
var draw = ui.GetWindowDrawList();
var clip = new UiRect(0, 0, 320, 240);
using (draw.CircleCutout(new(100, 80), 24))
{
    draw.AddRectFilledRounded(new(24, 24, 160, 112), new(30, 150, 210),
        ui.WhiteTextureId, 12, clip);
}
```

좌표는 기하와 같은 로컬 논리 좌표입니다. 명령의 이동과3D 투영을 적용하면 원도 함께 이동합니다. 채움·테두리·원·둥근 이미지·그라디언트·폰트 삼각형·SVG 텍스처가 공통 analytic coverage를 사용합니다. 재질의 불투명도와 깊이/샘플 커버리지는 구분합니다. XML·비트맵 합성·다각형 띠를 만들지 않습니다.

스코프는 애니메이션 타이머나 주기 프레임을 요청하지 않습니다. 모델을 바꾸는 소유자가 프레임을 요청해야 합니다.2D에서는 실제 획득 이미지마다 변경 내용을 반영한 뒤 그대로 요청한 프레임의 draw·스트리밍 업로드를 생략합니다. 명시적3D/깊이 장면은 기존의 보수적인 전체 장면 갱신 정책을 유지합니다. 변하지 않는 유지 기하는 재사용하지만 함께 있는 동적 배경의 업로드나 draw까지0이라고 주장하지 않습니다.

마스크는 기존32바이트 primitive 저장소를 사용합니다.128바이트 push constant와64바이트 compiled descriptor 크기는 그대로입니다. append·분할·채널 병합·유지 재생에서 인덱스와 대기 프레임의 원본을 보존합니다. 유지 소스의 버전이 같아도 바깥 마스크가 바뀌면 새 콘텐츠 지문을 제공합니다. 변경 영역 비교는 도형 레코드 범위 밖의 마스크 데이터도 확인합니다. 바깥 스코프에서 유지 참조를 자르면 현재는 프레임 소유 기하·명령 사본을 만듭니다. 전체 CPU나 할당0을 뜻하지 않습니다.

직접 중첩한 스코프와 스코프 안의 외부 그리기 콜백은 명시적으로 실패합니다. 채널·참조 재생은 이미 같은 원이 적용된 상태를 보존할 수 있지만 다른 원을 중첩해서 빼지는 못합니다. 마스크를 재생할 때는 전체 draw-list Append를 사용하세요. 정점·인덱스·명령만 받는 overload에는 필요한 보조 레코드를 전달할 수 없습니다.

일반/마스크 셰이더는 `imgui_vertex.glsl`/`imgui_fragment.glsl`을 공유하고 컴파일할 진입점을 선택합니다. 일반 진입점에는 마스크 입출력이나 fragment 분기가 없습니다. 보호한 기준 SPIR-V와 소스 확장 메타데이터2개를 제외한 명령이 같습니다. 마스크 셰이더 모듈과 최대9개 모드의 pipeline은 처음 필요할 때 만들며 기존 그래픽 자원과 함께 해제합니다. 새 장치 기능·barrier·네이티브 import·shaderInt64 요구는 없습니다. 실제 진입점은 imgui.vert,imgui.frag,imgui_cutout.vert,imgui_cutout.frag,particles.comp이며 기존 일치 검사 도구의 EntryShaders 인수에5개를 전달합니다.

저장소 루트에서 `./run-gallery.ps1` 실행→**렌더링**→**원형 잘라내기**를 누르세요. 무늬가 있는 뒤쪽 면과3D 투영의 투명한 구멍을 비교합니다. 애니메이션은 직접 켜기 전까지 꺼져 있고 탭을 바꿔도 선택을 유지합니다.

근거는 `artifacts/circle-cutout-2026-11-12/verification.json`입니다. SDK11.0.100/runtime11.0.0 관리 실행으로 검증합니다. 최초 통합 셰이더 후보의 비용 증가도 실패 근거로 보존했습니다. 최종 마스크 미사용 진단은 같은256개 둥근 사각형,64준비/256측정 프레임,독립 프로세스3회 교대 측정입니다. 실행별 중앙값의 중앙값은29.888→29.712us(-0.59%)이며 변동 범위가 겹쳐 속도 개선을 주장하지 않습니다. 측정 픽셀 해시와 기존141장 이미지가 일치합니다. 원래 고정 RC3 NativeAOT/전체 부하·Private/작업 집합·다른 GPU·장시간 증가 검증은 남아 있습니다. Avatar 상태 배지의 위치·이름 결합·잘라내기 연결은 다음 소비 경로 작업입니다.

그리기만 잘라냅니다. 레이아웃·입력 판정·포커스·접근성 영역은 바꾸지 않습니다. 지연된 인라인 자식 그리기도 부모의 마스크를 적용합니다.

검증 스냅샷: CPU51/51계약·8136회 검사(CircleCutout20·관찰189),마스크는 설정마다88회씩5가지 설정에서 통과했습니다. 실제 Khronos instance/device validation layer 로드를 확인했고 캡처 로그에 VUID/오류가 없었습니다. 프레임 자원2/3개·공유 camera/basis 설정·일반 compiled·양쪽 스케줄러를 포함합니다. 추가 GPU 검사는 primitive74·둥근 이미지40·SVG74·Avatar220·Presence552·관찰55회입니다. 설정별 반복을 포함한 횟수이며1455개의 독립 기능 요구사항을 뜻하지 않습니다. 샘플의 본문 실행 카운터는 실제 구성 뒤에 그려 같은 이벤트 프레임의 확정값을 표시하며 추가 프레임을 요청하지 않습니다.
