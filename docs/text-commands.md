# Shared text keyboard commands

Single-line and multiline inputs use the existing Ctrl+Left/Right word boundaries for Ctrl+Backspace/Delete, including held-key repetition. Without a selection, backward deletion skips preceding whitespace and removes the preceding word or punctuation run; forward deletion skips following whitespace and removes the following run. Resulting endpoints snap outward to complete .NET `StringInfo` text elements. Existing selections take priority, Shift does not expand deletion, readonly inputs refuse mutation, and undo/redo retains the edit. These boundaries use the existing BMP letter/digit/combining-mark heuristic; locale-aware UAX29 segmentation and full native behavior remain open.

Plain Left/Right in multiline inputs collapse an existing selection to its logical leading/trailing endpoint, including reverse and cross-line selections. Held keys use the same rule. Shift continues to extend the active endpoint; Ctrl continues word navigation. Collapsing clears the old visual-row/vertical affinity so later movement starts from the collapsed caret. This covers the shared standard, wrapped and Fluent nonwrapping paths, without establishing visual bidi navigation.
