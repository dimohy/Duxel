# 내부 창 배치와 이동

Last synced: 2026-11-05

사용자는 수정한 Slider 창을 직접 확인하고 "잘림·여백이 나아졌고 이동도 자연스러움"이라고 답했다. 이 화면/이동 결함은 해결 확인으로 반영한다. 아래 계측의 한계와 전체 엔진 성능·메모리 목표는 별도로 유지한다.

갤러리 제목이 앱 제목 표시줄에 가리고 하단 고정 여백이 컸다. 선언형 Window가 Position/Size를 매 프레임 덮어써 드래그를 놓으면 초기 위치로 복귀하는 결함도 재현했다. 첫 프레임 출력 성공은 배치·상호작용 검증이 아니었다.

UiWindowOptions.Placement 기본값 Initial은 위치·크기를 최초 생성 때만 적용한다. 이후 사용자 이동·크기를 유지하며, 계속 제어하려면 UiWindowPlacementCondition.Always를 지정한다. 기존 SetNextWindowPos/Size의 매번 적용 계약은 유지한다. PositionSpace=UiWindowPositionSpace.WorkArea는 작업 영역 원점에 Position을 더한다. 갤러리는48px 앱 제목 표시줄 아래24px 여백을 둔다. 기본 Screen 좌표는 유지하며 드래그 중 제목 Y가 작업 영역 위로 가지 않게 한다.

AutoHeight는 실제 콘텐츠 하단으로 저장 높이를 맞추고 변경 시 다음 프레임을 요청한다. 최소 높이·작업 영역 하단·필요한 스크롤을 보존한다. 첫 배치에서 콘텐츠를 수집하고 다음 프레임에 반영하여 콜백을 두 번 실행하지 않는다. 자동 높이는 기존 높이 보간을 생략하며 중첩 창은 부모 정책을 복원한다.

NET10전체1,004·관리/고정RC3 Native108·이전428이미지 동치. 수정 전 위치 복귀 검사가 실패했고 수정 후 포인터 추종·해제 위치·제목 가림 방지·자동 높이·GPU 전체 픽셀을 확인했다. 공통 GPU 창 이미지를 직접 검토했으며 사용자 데스크톱 검증으로 확대하지 않는다. 근거는 artifacts/gallery-window-fix-2026-11-05다.

이동 검사는 아직 draw6회·기하 업로드가 남는다.320×240 소비 앱1,376B, 리사이즈 후404×281 전체 검사1,584B이며 다른 크기의 값을 성능 비교로 사용하지 않는다. 보고된 체감 지연은 실제 갤러리 프로필로 확인 중이다. FPS·Private 개선이나 지연 해결은 미확정이다.
