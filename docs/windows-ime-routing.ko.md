# Windows IME 입력 대상

Windows 반복 횟수는 원시 입력과 순서 있는 IME 소비 전에 보존합니다. UTF-16 첫 단위의 소유권은 반복 횟수도 유지하며 결과 중복 비교는 한 단위와 전체 반복 문자열을 모두 다룹니다. 저수준 즉시 처리기 검사는 이전 323개에 원시 입력·IME 반복 검사 세 개를 더해 326개가 통과했습니다. [반복 메타정보·경계 검사·한계](input-event-batches.ko.md#네이티브-반복-횟수).

Windows App과 Observer는 네이티브 메시지를 순서대로 수집합니다. 지정된 IMM 문자열을 HWND 소유 스레드에서 한 번 읽고, 불변 전달 객체를 통해 UI 스레드의 각 논리 입력 직전에 적용합니다. 전달 객체는 원래 IME 처리기를 요구합니다. 네이티브 수집 세대와 논리 UI 세대를 구분하므로 이미 끝났거나 교체된 네이티브 조합에 오래된 확정·위치 요청을 적용하지 않습니다. 같은 호스트 묶음 안에 클릭이 있어도 UTF-16 첫 단위의 논리 위치에서 정한 대상을 유지합니다. 제거·숨김 수명과 수집 시각을 포함한 네이티브 검사 363개와 실제 App·작업 스레드·Vulkan 검사 37개가 통과했습니다. [계약·실행 명령](input-event-batches.ko.md#windows-네이티브-순서-수집).

## 제거한 입력과 숨긴 입력

`IUiImeHandler.ReleaseInput(inputId)`는 사용자 정의 처리기도 구현해야 하는 수명 계약입니다. Input·Textarea·Markdown은 공통 텍스트 소유자를 해제할 때 이를 호출하고 변환 래퍼도 원래 처리기로 전달합니다. 구현은 해당 입력의 대기 문자와 보관한 소유권을 폐기하되 다른 입력의 큐를 지우면 안 됩니다. 살아 있는 위젯을 숨기는 것은 해제가 아니므로 다시 표시할 때 늦은 확정을 소비할 수 있습니다. 이 API로 갱신하는 사용자 정의 처리기에는 이 메서드 구현이 필요합니다. 즉시 모드의 입력 id를 직접 관리하는 호스트는 입력을 영구 제거할 때 명시적으로 호출해야 합니다.

Windows는 활성·조합 대상, 대기 문자 소유자와 커서 위치에서 제거한 입력을 해제합니다. UTF-16 상위 단위가 대기 중이면 대상만 비워 두고 하위 단위까지 해석하므로 새 포커스로 문자가 넘어가지 않습니다. 폐기한 id 목록을 계속 보관하지 않으며 같은 id를 새로 사용하면 새 입력을 받습니다. 실제 네이티브 조합이 남아 있으면 HWND 소유 스레드에서 `CPS_CANCEL`을 요청합니다. 먼저 예약된 확정도 대상이 없어졌다면 취소로 처리합니다. 이미 끝났거나 교체된 세대는 무시하고 네이티브 실패는 계속 드러냅니다. [네이티브 취소·확정 계약](https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immnotifyime).

제어된 순서 검사는 110개에서 218개로 늘었습니다. 수정 전에는 폐기 뒤 소유권·대기 문자가 남아 218개 중 24개가 실패했고 수정 후 모두 통과했습니다. 실제 편집기 세 종류·두 탐색 순서에서 대기 문자·분리 UTF-16·숨김 복귀·취소를 확인했습니다. 이전 수명 검사에서는 기존 313개에 직접 수명 검사 10개를 더해 저수준 IME 323개가 통과했습니다. 문자 두 경로·id 재사용·다른 입력의 대기 문자 보존·새 포커스 유무에 따른 취소를 포함합니다. 실제 키보드/TSF 서비스 전체 수용을 뜻하지는 않습니다. [근거](../artifacts/goal-audit-2026-11-16/ime-input-lifetime-verification.json).

`SetCompositionOwner`는 현재 활성 입력을 선택합니다. 네이티브 조합은 `WM_IME_STARTCOMPOSITION`에서 입력 id를 기억하고 `WM_IME_ENDCOMPOSITION`까지 그 대상을 유지합니다. 포커스가 바뀌거나 활성 입력이 없어져도 진행 중인 조합의 대상을 바꾸지 않습니다. 조합 문자열은 원래 입력이 활성일 때만 노출합니다. 대상 없이 시작한 조합이 나중에 활성화한 입력에 기록되는 것도 막습니다.

결과 문자열과 네이티브 문자 결과는 모두 기억한 대상으로 전달합니다. 새 조합 없이 반복된 결과 알림은 한 번만 소비하며, 다음 조합 구간의 결과는 같은 문자열이어도 별도 입력으로 받습니다. 조합 밖의 일반 문자는 현재 활성 입력을 따릅니다. 결과 없이 종료했다고 확정 문자를 만들어내지 않습니다. 비활성 한 줄 위젯이 늦은 확정을 받으면 최종 커서를 저장해 포커스를 되돌렸을 때 확정 문자 뒤의 위치를 복원합니다.

`WM_IME_COMPOSITION`은 지정된 문자열만 조회합니다. `GCS_RESULTSTR`와 `GCS_COMPSTR`가 함께 오면 이전 구간의 결과를 확정하고 다음 조합 문자열을 유지합니다. 결과만 오면 이전 조합을 지우고, 속성·절 정보만 바뀌면 표시 문자열을 유지합니다. GCS 플래그가 없으면 취소로 처리합니다. 상태를 한 번의 잠금 안에서 반영한 뒤 화면 갱신을 요청합니다. 이는 [Microsoft의 복합 플래그·취소 계약](https://learn.microsoft.com/en-us/windows/win32/intl/wm-ime-composition)에 따른 처리입니다.

이전 포커스 검사에서는 기존 249개, 포커스·위치·오류 처리 28개, 실제 Input·Textarea·Markdown 소비 36개로 총 313개가 통과했습니다. 포커스 연결 수정 전에는 270개 중 10개가 실패했고, 위젯 통합 검사에서는 추가로 커서 복원 8개 실패를 재현했습니다. 비활성 Textarea·Markdown이 확정을 받았을 때 최종 커서를 저장하도록 공통 여러 줄 커널을 수정했습니다. 실제 키보드 서비스나 픽셀 비교 완료를 뜻하지 않습니다.

## 논리 포커스와 후보 위치

조합 중 다른 입력으로 이동하면 HWND 소유 스레드에 확정 요청을 예약합니다. 조합 대상이 있으면 `NI_COMPOSITIONSTR/CPS_COMPLETE`, 대상 없이 시작한 조합이면 `CPS_CANCEL`을 사용합니다. 같은 조합의 요청은 합치고, 처리 전에 원래 입력으로 돌아왔거나 새 조합이 시작됐다면 오래된 요청을 폐기합니다. 확정 본문을 임의로 만들거나 조합 종료를 가정하지 않고 실제 결과·종료 메시지를 기다립니다. [ImmNotifyIME 계약](https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immnotifyime).

위치 요청에는 입력 대상·포커스 버전·조합 세대를 기록합니다. 다음 입력의 위치는 이전 조합이 끝날 때까지 보류하며, 종료 뒤에도 여전히 유효한 최신 위치만 적용합니다. 모든 위치 적용은 소유 스레드에서 처리합니다. 여러 예약 위치는 마지막 값으로 합치고, 적용 단계에서 미적용으로 반환된 요청은 성공 캐시에 넣지 않습니다.

IMM은 확정 요청 중 결과·종료 메시지를 동기적으로 보낼 수 있으므로 상태 잠금을 잡은 채 호출하지 않습니다. 거부나 컨텍스트 부재는 이미 예약된 종료 메시지 뒤에 다시 확인합니다. 종료·새 조합으로 무효가 된 요청은 현재 입력의 오류로 만들지 않습니다. 여전히 유효한 요청의 실패는 다음 관리형 호출에서 드러내며, 포커스 정리는 허용하고 네이티브 재시도를 반복하지 않습니다.

검증은 실제 HWND 큐·소유 스레드·상태 전이를 사용하지만 IMM의 완료 응답과 좌표 적용은 검증 훅으로 제어합니다. 실제 키보드 서비스의 응답과 후보 창 픽셀 위치는 별도 수용 검증입니다. [포커스 연결 근거](../artifacts/goal-audit-2026-11-16/ime-focus-verification.json).

## UTF-16 문자 메시지

`WM_CHAR`와 `WM_IME_CHAR`는 채널별로 상위 서로게이트 한 개만 보관합니다. 하위 서로게이트가 도착해야 완전한 Unicode 스칼라를 전달하며, 상위 코드 단위를 받은 입력 대상을 유지합니다. 그 사이 논리 포커스를 옮기거나 프레임을 소비해도 새 입력으로 문자가 넘어가지 않습니다. 입력 대상 없이 시작한 쌍은 나중에 포커스한 입력에 붙이지 않습니다.

일반 입력 이벤트와 IME는 같은 작은 디코더를 사용합니다. 프레임 소비는 대기 중인 코드 단위를 지우지 않으며, 네이티브 조합 시작·종료·취소, 창 포커스 해제와 객체 폐기 시에는 두 경로를 함께 초기화합니다. IME 훅이 조합 메시지를 소비해도 내부 연결을 통해 일반 입력 경로의 대기 상태를 제거합니다. 일반 공개 생성자는 유지합니다.

고립된 하위 서로게이트는 입력하지 않습니다. 새로운 정상 문자나 상위 코드 단위가 오면 이전 미완성 쌍을 폐기하고 새 입력을 처리합니다. 대체 문자를 삽입하지 않습니다. [Microsoft 문서](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-char)의 UTF-16 코드 단위 계약과 [Unicode 창의 WM_IME_CHAR 처리](https://learn.microsoft.com/en-us/windows/win32/intl/wm-ime-char)를 기준으로 합니다. [최신 문자 경계 근거](../artifacts/goal-audit-2026-11-16/ime-scalar-verification.json).

로컬 소스 기반 그래픽 검증 실행 파일에서 다음 명령을 실행합니다.

사용자 샘플은 저장소 루트에서 `./run-gallery.ps1`로 실행합니다. **입력·IME**의 이름과 메모 사이에서 한글 조합 중 포커스를 옮겨 확정·커서 복귀를 확인하세요. 이 경로는 실제 IME 서비스의 동작을 확인하는 방법이며, 자동 메시지 검사와는 범위가 다릅니다.

```powershell
./Duxel.Graphics.Tests.exe <새-결과-경로> ime-owner-only
```

검사는 소유한 숨김 HWND에 시작·갱신·결과·종료 메시지를 보내 실제 창 훅을 통과시킵니다. IMM 문자열 추출 데이터만 검증 전용 partial 훅으로 주입하며 일반 빌드에는 포함하지 않습니다. 소유 스레드·작업 스레드의 포커스 변경, 문자·결과 문자열 알림, 중복 결과, 취소, 대상 없는 조합, 렌더 순서가 다른 실제 두 입력 위젯을 확인합니다. 사용자 포커스·클립보드·키보드 설정은 바꾸지 않습니다.

이는 메시지 전달과 위젯 소비 검사이며 실제 키보드·TSF 서비스 세션 전체 검증은 아닙니다. 복합 플래그·취소·속성 변경, UTF-16 분리 도착과 실제 입력 위젯의 연속 확정을 검사합니다. 같은 묶음 안의 문자·포인터 순서와 소유한 위젯의 제거는 활성화된 Windows 순서 전달 경로에서 별도로 확인했으며 기존 집계 방식의 실패 대조도 보존합니다. 실제 서비스의 포커스 확정·후보 창 위치와 CS_INSERTCHAR/CS_NOMOVECARET 표시는 남아 있습니다. [기존 입력 대상 근거](../artifacts/fluent-messagebar-2026-11-15/ime-owner-verification.json), [복합 메시지 근거](../artifacts/goal-audit-2026-11-16/ime-flags-verification.json).
