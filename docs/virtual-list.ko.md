# 키가 있는 가상 목록

스크롤바 손잡이를 끌 때는 누른 순간의 정확한 콘텐츠 오프셋을 기준으로 삼습니다. 10억 행의 끝에서도 손잡이를 누르거나 제자리에 두고 있으면 소수 오프셋이 그대로 유지됩니다. 손잡이를 옮겼다가 처음 누른 위치로 되돌려도 같은 오프셋을 복구합니다.

Windows에서는 `./run-gallery.ps1`, WSL에서는 `./run-gallery-linux.ps1`로 실행합니다. **가상 목록**에서 **방향 : 세로**를 누르면 가로 목록으로 바뀝니다. 하단 손잡이, 가로 휠, **끝** 버튼으로 이동할 수 있습니다. 예제 아래의 소스에는 선택한 방향과 크기 설정이 반영됩니다.

Windows와 Linux Vulkan 실행기의 `virtual-list-pixels`는 두 방향의 고정·가변 크기 항목을 기준 화면과 비교합니다. 10억 항목의 끝에 가까운 소수 오프셋, 좁은 부모 클립, 기존 열 레이아웃, 래스터·벡터 레이어를 검사합니다.

두 환경에서 `virtual-list-host-pixels`를 실행하면 같은 목록 끝 장면의 RGBA 데이터를 비교할 수 있습니다. 방향·테마·MSAA·래스터/벡터별로 배경, 도형, 글자까지 그린 화면을 각각 저장합니다. Windows 관리 실행과 WSLg NativeAOT의 배경 16쌍은 모두 일치했습니다. MSAA 4× 래스터 4쌍에서는 WSLg의 목록 시작 경계 바깥 한 줄에 픽셀이 남았습니다. 나머지 도형 12쌍의 차이는 RGB 채널당 최대 1이었습니다. 네이티브 글자에도 차이가 있었고, 경계 바깥 픽셀이 어느 렌더링 단계에서 생겼는지는 아직 확인하지 못했습니다.

화면별 `.scissor.tsv`에 각 그리기 명령의 논리 클립, GPU에 전달한 Vulkan scissor, 렌더링 영역을 기록합니다. 경계 밖 픽셀이 보인 네 장면에서 두 환경의 scissor는 일치했고 해당 픽셀을 범위 밖으로 지정했습니다. WSLg에서 부분 갱신을 꺼도 48장 모두 동일했습니다.

`clip-host-pixels`는 목록과 글자를 빼고 테두리가 있는 사각형 또는 삼각형 두 개만으로 같은 현상을 재현합니다. Mesa lavapipe 25.2.8에서는 MSAA 4× 장면 32개 모두에서 경계 밖 픽셀이 보였습니다. Windows와 Mesa 26.0.8에서는 최소 장면 64개와 확인한 가상 목록 장면이 시작 경계를 지켰습니다. 새 Mesa 검증은 같은 Linux NativeAOT 실행 파일을 격리된 컨테이너에서 실행했습니다. 관찰 결과는 [Mesa의 scissor 수정](https://docs.mesa3d.org/relnotes/25.3.0.html)과 일치합니다.

Linux에서는 갤러리와 같은 D-Bus 사용자 세션에서 `dotnet Duxel.Linux.App.Tests.dll atspi-gallery-virtual-list <갤러리-PID> <새-result.json>`을 실행할 수 있습니다. 별도 AT-SPI 클라이언트가 키 0의 값을 편집하고 10억 번째 행으로 이동한 뒤 양 끝의 키를 바꿉니다. 접근성 트리에 노출되는 행 수가 제한 범위에 있고, 새로 만들어진 키 0의 편집기에 기존 값이 남는지 확인합니다.

같은 인자로 `atspi-gallery-virtual-horizontal`을 실행하면 가로 예제를 검사합니다. 외부 AT-SPI 클라이언트가 방향을 바꾸고 `Component.ScrollTo`로 화면 밖에 있는 편집기를 표시합니다. 이때 같은 접근성 객체를 유지하는지, 10억 번째 항목에 가도 필요한 항목만 만들고 키에 저장한 값을 복구하는지 확인합니다.

`atspi-gallery-virtual-rtl`은 오른쪽부터 배치한 목록에서 같은 동작과 편집기의 실제 X 좌표를 검사합니다. 갤러리의 가로 모드에서 **가로 순서 : 왼쪽부터**를 누르면 오른쪽부터 배치합니다. `virtual-list-rtl-pixels`는 이 배치를 기준 화면과 비교합니다.

`Dux.VirtualList(source, itemCount, options)`는 한 방향으로 스크롤하는 `UiVirtualList<TSource>`를 만듭니다. 기본값은 세로입니다. `Axis = UiScrollAxis.Horizontal`을 지정하면 스크롤바를 아래에 표시합니다. 가로 배치 순서는 `FlowDirection`으로 지정하며 기본값은 상위 Fluent Provider의 방향을 따릅니다. 전체 길이와 오프셋은 `double`로 보관하고, 화면에 보이는 항목과 그 주변의 오버스캔 항목만 생성해 뷰포트 근처에 배치합니다.

```csharp
using var list = Dux.VirtualList(
    source, 1_000_000_000,
    new(ItemExtent : 32, Width : 300, Height : 280, Overscan : 1));
list.Offset = 32_000_000_000d - 280.25;
```

`source`는 `IUiVirtualListSource`를 구현한 클래스입니다. `GetKey(index)`는 안정적 정체성, `Create(index)`는 일반 키 소유권으로 넘길 새 위젯, `Bind(widget, index)`는 기존 호환 위젯의 바인딩을 제공합니다. 새로 고침·재정렬에서는 겹치는 키를 재사용합니다. 논리 항목의 키는 고유해야 하며, 구현은 전체 데이터를 훑는 대신 생성 범위의 중복을 검사합니다. 템플릿을 바꿀 때는 호환 바인딩이나 다른 키가 필요합니다. 모델 변경 중 무효가 될 수 있는 인덱스 조회보다 안정된 모델 참조를 바인딩에 사용합니다.

소스와 데이터는 호출자 소유이며 생성 위젯은 목록이 소유합니다. 모델이나 키 변경 후 `Refresh()`로 현재 범위를 다시 바인딩하고, `ItemCount`로 명시적 기하 메타데이터를 제공합니다. 순수 측정에서는 소스나 높이 인덱스를 호출하지 않고 컨트롤을 생성하지 않습니다. 행은 할당된 영역 안에서 렌더하며 기존 Fluent 컨트롤과 레이아웃 컨테이너를 사용할 수 있습니다.

## 항목 크기

`ItemExtent`는 세로 모드의 높이 또는 가로 모드의 너비를 정합니다. 항목마다 크기가 다르면 `UiVirtualListOptions.ExtentIndex`에 모델을 기반으로 한 `IUiVirtualListExtentIndex`를 설정합니다. `GetBoundary(index)`는 해당 항목 직전까지의 누적 길이를 반환합니다. 인덱스 `0`은 0, `ItemCount`는 전체 길이입니다. 경계는 유한하고 엄격히 증가해야 하며 항목 크기는 `float`로 표현 가능한 양수여야 합니다. 한 프레임 동안 경계와 키를 유지합니다. 목록은 이진 탐색으로 경계를 찾고 필요한 항목 영역만 조회합니다.

같은 모델에서 높이나 순서를 변경한 뒤 `Refresh()`를 호출합니다. 목록은 `FindIndexByKey(key, itemCount)`를 사용해 이동한 기준 행을 찾습니다. 키가 없으면 `-1`을 반환하고, 모델 인덱스로 조회 범위를 제한합니다. 가능하면 첫 가시 행의 키와 행 내부 오프셋을 보존하며, 오프셋은 새 행 높이 이내로 제한합니다. 키가 사라지면 기존 절대 오프셋을 사용합니다. 명시적으로 지정한 스크롤 오프셋이 우선합니다.

높이가 바뀔 때 뷰포트가 완전히 가려져 있으면, 다시 보이는 프레임의 클립을 기준으로 위치를 복원합니다. 상위 클립이 움직여도 가시 영역 가장자리에 대한 기준 행의 위치를 유지합니다. 생성 범위에 남아 있는 행 위젯은 키와 편집기 상태를 유지합니다.

## 수명과 입력

범위가 그대로면 새 키 열거·바인딩·생성 없이 기존 행을 렌더합니다. 겹치는 키는 위젯 정체성·편집기 포커스·undo를 유지합니다. 오버스캔 범위를 벗어나면 `UiBuildContext`로 행을 해제하고, 포커스 소유권·편집 버퍼·undo도 정리합니다. 다시 돌아온 키에는 새 위젯을 만들므로 지속할 텍스트·선택·업무 상태는 모델에 둡니다. 다른 키 사이의 자동 풀링이나 재부모화는 하지 않습니다.

새 행을 채택한 뒤 쓰지 않는 기존 행을 해제하므로 전환 중에는 두 창을 임시로 소유할 수 있습니다. 내부 컬렉션은 데이터 개수가 아닌 설정한 창/예산의 제한된 최고 용량을 유지합니다. 생성/바인딩 실패에는 기존 Build 중단 정리를 사용합니다. 명시적 `MaxRealizedItems` 예산(기본 4096)을 키/위젯 요청 전에 검사합니다. 오버스캔 기본값은 한 행입니다. 예산을 넘으면 일부 행을 몰래 빼지 않고 실패합니다.

선택한 방향의 휠 입력을 사용하고, 소비하지 않은 입력은 바깥 영역으로 전달합니다. 공통 스크롤바가 두 방향의 손잡이 드래그와 페이지 이동을 double 정밀도로 처리합니다. 방향이나 컨텍스트가 바뀌거나 목록이 해제되면 스크롤바 소유권도 정리합니다. 항목 콜백이 명시적으로 바꾼 오프셋은 유지하며, 크기 변경은 다음 준비 프레임에 적용합니다. 뷰포트가 완전히 가려지거나 크기가 0이면 항목을 생성하지 않습니다.

## 정밀도와 범위

뷰포트 두 축은 부모나 `Width`/`Height`로 유한해야 합니다. `Offset`은 유한·음이 아닌 값이며 렌더 시 현재 범위로 제한합니다. 범위는 정수 변환 전에 제한합니다. double로도 뷰포트를 구별할 수 없는 높이는 거부합니다. 개별 행의 컨트롤은 여전히 일반 float 기하를 사용하며, 거대한 단일 행 내부까지 가상화하는 것은 아닙니다.

항목 크기 자동 측정과 서로 다른 키 간 자동 풀링은 남아 있습니다. 가로와 세로가 모두 긴 콘텐츠는 아래 가상 그리드를 사용합니다. 일반 전체 콘텐츠 `UiScrollView`는 표현할 수 없는 거대 월드 좌표를 거부합니다. 컨테이너는 3/6입니다.

## 두 축의 가상 그리드

```csharp
using var grid = Dux.VirtualGrid(source, 1_000_000_000, 1_000_000_000,
    new(RowHeight : 44, ColumnWidth : 200, Width : 960, Height : 320));
grid.Offset = new(double.MaxValue, double.MaxValue);
```

`IUiVirtualGridSource`로 셀마다 고유한 키를 지정하고 위젯을 만듭니다. 그리드는 화면 주변의 행과 열이 만나는 셀만 만들며, 소스를 호출하기 전에 `MaxRealizedCells`를 확인합니다. `RowExtents`와 `ColumnExtents`로 행 높이와 열 너비를 따로 지정할 수 있습니다. `SetDimensions`는 행과 열 수를 바꾸고, `Refresh`는 모델 변경을 화면의 셀에 반영합니다.

접근성 트리에는 전체 행·열 수와 두 축의 스크롤 범위가 공개됩니다. Windows UIA의 `Grid.GetItem`과 Linux AT-SPI의 `Table.GetAccessibleAt`은 0부터 세는 행·열 좌표를 받습니다. 먼 셀을 조회하면 화면 위치를 유지한 채 접근성 객체 하나만 만듭니다. UIA의 `VirtualizedItem.Realize`나 AT-SPI의 `Component.ScrollTo(Nearest)`를 호출하면 해당 셀이 화면에 나타나고, 같은 접근성 객체에 편집기 등의 내용이 연결됩니다. 다음 조회가 임시 객체를 교체할 수 있습니다. 키나 이름을 바꿨으면 `Refresh`를 호출하세요. 셀의 키가 좌표와 일치하지 않으면 임시 객체를 해제합니다. 큰 그리드에서는 행과 열을 따로 지정하세요. AT-SPI의 단일 인덱스는 32비트 정수입니다.

갤러리의 **가상 그리드**에서 첫 셀을 편집하고 **마지막 행·열**로 갔다가 **첫 행·첫 열**로 돌아오세요. 예제 아래에서 C# 코드를 볼 수 있습니다.

Windows와 Linux Vulkan 검증기의 `virtual-grid-pixels`는 가상 그리드의 셀과 스크롤바를 별도로 그린 기준 화면과 비교합니다. 두 축의 소수 오프셋, 고정·가변 크기, 오른쪽 시작 순서, 상위 클립, 스크롤바 하나가 공간을 차지해 다른 스크롤바가 필요한 경우를 검사합니다.

프레임 슬롯 3개로 `virtual-grid-host-pixels`를 실행하면 빈 화면과 스크롤이 없는 그리드, 고정 크기 그리드의 끝, 클립이 적용된 가변 크기 그리드의 끝을 원시 RGBA로 저장합니다. 두 벡터 그리드의 끝에서는 셀 테두리, 원, 스크롤바를 따로 그립니다. 전체 기준 화면 검사도 같은 환경에서 실행합니다.

## Windows 접근성

`AccessibleName`으로 가상 목록의 Pane 이름을 지정합니다. Scroll 패턴은 선택한 방향의 전체 길이를 사용하고 백분율과 단계 이동에서 `double` 정밀도를 유지합니다. `UiAccessibilityScrollInfo`의 `HorizontalOffset`과 `HorizontalContentWidth` 또는 `VerticalOffset`과 `VerticalContentHeight`로 정확한 값을 읽습니다. Scroll 요청은 새 범위의 항목을 생성하고 게시하기 전에 적용합니다.

오른쪽부터 배치하면 `UiVirtualList.Offset`과 접근성 스크롤 백분율은 오른쪽에서부터 셉니다. `UiAccessibilityScrollInfo.HorizontalOffset`은 왼쪽 기준의 물리 위치입니다. ScrollItem이나 특정 지점으로 이동하는 요청은 양쪽 방향 모두 창의 같은 좌표계를 사용합니다.

오버스캔을 포함해 생성된 범위의 컨트롤이 Pane 아래에 표시됩니다. 클립 밖 오버스캔 컨트롤은 공급자가 살아 있는 동안 `ScrollIntoView`를 사용할 수 있습니다. 행이 생성 범위를 벗어나면 해당 공급자는 사용할 수 없게 되고, Pane은 새 범위를 게시한 뒤 자식 목록 변경을 알립니다. 제거됐던 키로 돌아오면 새 공급자가 생성됩니다. 지속할 편집 값은 모델에 둡니다.

`IUiVirtualListAutomationSource`를 구현하면 `ItemContainer`와 각 행의 `ListItem`을 제공합니다. `GetAccessibleItemName`은 모델 이름을, `GetKey`는 `AutomationId`를 제공합니다. `FindAccessibleItem`은 시작 인덱스와 전체 항목 수를 받습니다. 모델 인덱스나 맵을 사용해 조회 범위를 제한합니다. 이름과 AutomationId 검색, 지정한 행 다음부터 조건 없이 열거하는 요청을 지원합니다. 검색 콜백은 렌더 스레드에서 실행되므로 빠르게 반환해야 합니다. 키나 접근성 이름을 바꾸면 `Refresh()`를 호출합니다.

생성 범위 밖 검색 결과는 뷰포트를 움직이거나 위젯을 만들지 않고 같은 계층에 임시 요소 하나를 게시합니다. 다음 검색에서 이 요소를 교체할 수 있습니다. `Refresh()`에서 보관된 키가 이동하면 AutomationId로 새 인덱스를 찾아 공급자를 유지합니다. 삭제된 키의 공급자는 해제합니다. `VirtualizedItem.Realize`는 키를 다시 확인하고, 소유 스크롤 조상이 행을 가린 경우 그 조상도 이동합니다. 같은 공급자에 실제 자식 컨트롤을 연결한 뒤 반환합니다. 고정 클립으로 행을 표시할 수 없으면 요청이 실패할 수 있습니다. 이미 생성된 행을 검색하면 해당 공급자를 반환합니다. [Microsoft 가상 항목](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-workingwithvirtualizeditems)

## 검증과 샘플

`layout_virtual_list_fba.cs`의 `Variable heights` 컨트롤은 높이 36과 64인 행을 번갈아 표시합니다. 별도 Windows UI Automation 클라이언트로 높이를 바꾼 뒤 가시 키와 소수 위치가 보존되는 것을 확인했습니다. 부모가 목록을 완전히 가렸다가 다른 위치에서 표시하는 경우도 확인했습니다. `VirtualizedItem.Realize`는 마지막으로 이동한 행을 정확한 스크롤 한계에서 표시했습니다.

`artifacts/virtual-list-uia-2026-11-11/verification.json`에는 별도 Windows UIA 클라이언트로 실행 중인 샘플을 검증한 결과가 있습니다. 오버스캔 편집기를 다시 표시하고 10억 번째 행으로 이동한 뒤, 이전 공급자가 해제됐는지 확인했습니다. 처음으로 돌아왔을 때는 새 공급자에서 모델의 편집 값이 복원됐습니다.

샘플의 바깥 Pane을 스크롤하면 목록을 화면 밖으로 옮길 수 있습니다. `Reorder keys`는 멀리 떨어진 두 키를 맞바꿉니다. 별도 UIA 클라이언트는 재정렬 전의 임시 요소를 유지한 채 `Realize`로 두 Pane을 이동해 마지막 행의 키를 확인합니다. 근거는 `artifacts/nested-virtual-realize-2026-11-11/verification.json`에 있습니다.

근거: `artifacts/virtual-list-2026-11-10/verification.json`. 고정 .NET11 RC3 빌드는 경고·오류 0개입니다. CPU43검사가 순수 측정/부모 탐색, 10억 행 끝부분·소수 정밀도, 제한 소유권, 갱신/재정렬, 중복/생성 실패, 예산/subnormal, 중첩 휠, 손잡이/페이지, 컨텍스트 이동과 실제 편집기 입력/undo/퇴출을 확인합니다. 별도 회귀는 ScrollView47·좌표2317·컨테이너229·수명101이 통과하며, 중복 범위를 고유 요구사항처럼 합산하지 않습니다.

좌표 실행에는 명시적으로 재배치한 행 좌표와 공통 스크롤바를 기준으로 한 실제 취득 이미지 192비교와 생성 수/오프셋 192검사가 새로 포함됩니다. 래스터/벡터·MSAA1/4·Light/Dark·일반/기존 열 라우팅·좁은 클립, 프레임 슬롯 3이며 좌표 readback은 1697회입니다. 이를 속도·전체 모델 메모리·전체 앱 할당 개선으로 해석하지 않습니다.

`samples/fba/layout_virtual_list_fba.cs`는 논리 10억 항목, 실제 편집 행, 희소 모델 텍스트/표식과 Top/Middle/End/개수 조작을 보여 줍니다. `DUXEL_SAMPLE_EXERCISE=1`은 시작 검증용 자동 전환을 예약합니다. 저장된 정상/캐시 비활성 실행은 기존 PS5 실행기 한계 때문에 본문이 같은 로컬 프로젝트 사본을 사용합니다. 지원 셸에서는 `./run-fba.ps1 samples/fba/layout_virtual_list_fba.cs -NoCache`를 우선합니다. 현재 로컬 소스가 필요하며 이전 배포 패키지는 지원 근거가 아닙니다. 관리 Windows 실행으로 NativeAOT·수동 OS 입력·공식 외형 승인을 주장하지 않습니다.
