# Fluent Tree — 위젯 연결 단계

갤러리의 **콘텐츠와 목록 → Tree**에서 두 예제를 실행할 수 있습니다. **행 안의 버튼** 예제에서 보고서 행으로 이동한 뒤 F2를 누르면 **열기** 버튼에 포커스가 놓입니다. Enter를 누르면 보고서를 연 횟수가 늘고, Escape를 누르면 포커스가 보고서 행으로 돌아옵니다.

Linux 외부 검사기는 `x11-gallery-tree-actions <갤러리 PID> <결과 JSON 경로> <X11 창 ID>`를 받습니다. 기존 계층·선택 검사를 실행한 뒤 갤러리 창에 F2, Enter, Escape를 보내고 AT-SPI의 포커스 상태와 보고서를 연 횟수를 확인합니다. 버튼과 행에 포커스가 놓인 화면도 각각 저장합니다.

WSLg에서 .NET 11.0.0 관리형과 NativeAOT 갤러리가 각각 12개 검사를 통과하고 정상 종료했습니다. 두 런타임의 화면 네 쌍은 프레임 수치가 있는 위쪽을 제외하면 일치했습니다. 같은 런타임에서 반복 캡처한 네 쌍은 창 전체가 일치했습니다. 물리 키보드와 스크린리더의 음성 출력은 이 검사 범위에 포함하지 않았습니다. 근거는 `W:/Cache/Duxel/gallery-source-20261117/tree-actions-2117/verification.json`에 있습니다.

[공식 안내](https://fluent2.microsoft.design/components/web/react/core/tree/usage)는 펼침 전용·탐색·다중 선택을 구분합니다. 부모를 선택하면 하위 항목도 선택하고, 일부만 선택되면 부모에 혼합 상태를 표시합니다. [WAI-ARIA 키보드 안내](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)는 초점과 선택을 구분하고 계층 안팎·보이는 항목 순서·처음/끝으로 이동하는 규칙을 설명합니다.

## 내부 모델의 역할

- UiTreeHierarchy는 키·부모 키·이름을 받습니다. 자식보다 부모를 나중에 넣어도 됩니다. 입력 배열을 복사하고 중복 키, 없는 부모, 자기 자신을 부모로 지정한 항목, 제어 문자와 분리된 순환 관계를 거부합니다. 재귀 호출 없이 순서·부모/자식·깊이·형제 위치/개수·하위 범위·말단 개수를 한 번 계산해 보관합니다.
- UiTreeModel은 호출자가 소유한 펼친 항목 목록을 읽습니다. 배열 내부 변경도 감지합니다. 부모를 접어도 자식의 펼침 상태를 보존하고, 보이지 않게 된 초점은 가장 가까운 보이는 부모로 돌립니다. 상태가 바뀔 때만 표시 목록을 다시 만듭니다. setter가 변경을 거부하면 실제 상태를 유지하며 계속 재시도하지 않습니다.
- UiTreeSelection의 내부 다중 선택 값은 말단 항목의 키입니다. 부모 상태는 하위 선택 개수로 계산합니다. 부모를 바꾸면 하위 말단 값을 한 번 쓰고, 접힌 항목의 선택도 보존합니다. 혼합 상태, 잘못된 값 거부, 제어된 쓰기와 같은 상태 재사용을 확인했습니다. 최종 공개 바인딩 API는 아직 확정하지 않았습니다.

## 계층 선택 조회

`UiAccessibilityTree.CaptureSelection`은 읽기 잠금 한 번 안에서 컨테이너와 소속 항목, 선택 항목을 복사합니다. `ResolveSelectionContainer`는 중첩 행의 `SelectionContainerId`를 확인하되 실제 조상만 허용하고 중간에 있는 독립 선택 컨테이너를 건너뛰지 않습니다. 오래된 RuntimeId는 거부합니다. 보관한 `UiAccessibilitySnapshot`에서도 같은 조회를 수행할 수 있으며 ID 색인은 최초 사용 시 한 번 만듭니다.

Tree 조회는 실제 계층을 유지한 채 전위 순서로 소속 항목을 수집합니다. 독립적인 하위 ListBox의 선택은 섞지 않습니다. 전체 수집은 항목마다 조상을 다시 검색하지 않고 반복 순회합니다. 일반 목록의 직접 자식 인덱스와 ComboBox의 실제 팝업 ListBox 소유권은 유지합니다.

Windows UIA의 GetSelection·GetSelectionContainer·AddToSelection과 Linux AT-SPI의 선택 조회·일괄 변경·알림이 이 정보를 사용합니다. 선택 항목을 제거하면 실제 Tree 루트에 무효화 이벤트를 보내고, 필수 선택이면 마지막 선택 해제를 막습니다. 공통 조회13건·실제 Tree 입력29건·Windows COM ABI7건과 기존 선택 컨트롤742건을 확인했습니다. [검증 기록](../artifacts/fluent-tree-selection-2026-11-18/result.json).

## 접힌 선택 항목과 지연 노출

이제 부모를 접어도 단일 선택된 하위 항목을 가상 TreeItem으로 조회할 수 있습니다. 선택된 항목의 숨은 조상 경로와 ItemContainer로 요청한 경로만 게시하며, 관계없는 숨은 행은 만들지 않습니다. Windows에서는 가상 항목을 raw view에만 두고 control/content view에서는 제외합니다. 펼친 뒤에도 RuntimeId와 선택 값이 유지되며 초점을 빼앗지 않습니다.

ItemContainer의 키·이름·순차 검색과 VirtualizedItem.Realize를 기존 요청 경로에 연결했습니다. `UiAccessibilityVirtualItem.ContainerId`는 실제 조상 컨테이너를 가리킵니다. 기존 세 인자 생성자와 deconstruction은 유지합니다. Realize는 조상들의 펼침 값을 한 번 쓰고 실제 행 배치가 준비된 뒤 끝납니다. 제어된 바인딩이 변경을 거부하면 실패를 반환하고 보이는 상태를 꾸며내지 않습니다. 잎 항목은 네이티브 ExpandCollapse의 LeafNode 상태를 제공합니다.

ScrollIntoView는 필요한 조상을 펼친 뒤 실제 상위 ScrollView를 통해 이동합니다. 펼친 첫 프레임에서 부모가 보관한 배치를 재사용해 새 행의 영역이 아직 0이면, 공통 스크롤 경로가 다음 배치 세대까지 요청을 보존합니다. 기존 배치 재사용 규칙을 없애거나 시간 지연으로 우회하지 않습니다. 같은 조건에서 실패를 확인한 뒤 수정 후 성공과 실제 오프셋을 확인했습니다.

집중 검증73건에는 숨은 선택·가상 항목·Windows COM 호출24건, Tree 입력29건, 네이티브 선택7건, 공통 선택 조회13건이 포함됩니다. 기존 가상 목록75건도 통과했습니다. 1만 단계 조상을 한 번의 바인딩 쓰기로 펼치는 모델 동작을 확인했으며 속도나 FPS 개선율은 측정하지 않았습니다. [현재 검증 기록](../artifacts/fluent-tree-virtual-selection-2026-11-18/result.json).

실제 Linux AT-SPI 실행과 외부 화면 읽기 프로그램, Tree의 공개 표현/API·행 동작·이름 검색 입력·갤러리 등록은 여전히 남아 있습니다. 이 단계의 조회·펼침 검증만으로 Tree 전체를 완료 처리하지 않습니다.

TreeChildrenChanged는 가상 항목이 실제 행으로 바뀌거나 자식 구성이 바뀔 때 실제 부모별로 한 번 통지합니다. Windows는 기존 구조 변경 이벤트 전송 경로를 공유하고, 변경 없는 프레임에서는 알림을 반복하지 않습니다. Tree를 다른 부모 아래로 옮기면 새 식별 범위로 가상 항목 ID를 다시 만들고 이전 제공자는 사용 불가로 처리합니다.


## 공개 표현과 이름 검색

`UiTree<TPresentation>`과 `UiTreeItem`을 공개했습니다. 같은 입력·선택·접근성 엔진에 `IUiTreePresentation`의 행 측정·행 배경/펼침 표시·선택 표시·초점 표시를 연결합니다. 측정을 재사용할 수 있다는 약속은 표현 형식이 명시합니다. 잘못된 행 측정값은 공통 배치 경계에서 거부합니다.

생성자는 펼침 전용, `UiBinding<string?>` 단일 선택, `UiBinding<string[]>` 말단 항목 다중 선택으로 나뉩니다. 서로 다른 선택 권한 두 개를 선택적으로 넘기는 공개 API는 만들지 않았습니다. 단일 선택 바인딩에 null을 넘기면 거부합니다. `UiTreeOptions`는 Medium/Small 행 크기, Subtle/SubtleAlpha/Transparent 표현, 방향·너비·탐색 동작을 제공합니다. 옵션이 바뀌면 행과 부모의 측정 결과를 무효화하되 항목 ID·펼침·선택은 유지합니다. 행 콘텐츠는 호출자가 소유한 위젯의 글꼴과 구성을 유지합니다.

키보드로 이름을 입력하면 보이는 행만 검색합니다. 같은 글자를 반복하면 일치하는 다음 행으로 이동하고, 한글과 여러 글자·공백을 포함한 이름도 검색할 수 있습니다. 초점만 옮기고 선택과 펼침은 바꾸지 않습니다. 검색 중 공백은 선택 토글로 처리하지 않습니다. 방향키 이동과 초점 이탈은 검색을 초기화하며, 1초가 지나면 다음 입력부터 새 검색을 시작합니다. 검색 만료만을 위한 프레임은 요청하지 않습니다. 기존 선택 컨트롤과 입력 버퍼만 공유하고 각 위젯의 탐색·선택 규칙은 분리했습니다.

## 기본 문자열 라벨

`new UiTreeItem(value, parentValue, label)`은 표현이 소유하는 문자열 라벨을 만듭니다. Fluent 기본 표현은 Medium에서 Body1, Small에서 Caption1을 사용합니다. 네 번째 인수로 위젯을 넘긴 행은 명시한 글꼴과 구성을 유지합니다. 사용자 표현은 `IUiTreePresentation.CreateLabel`을 구현하거나 명시적 콘텐츠를 사용합니다. 라벨 생성은 배치 전에 수행하며 원문과 소유권을 검증합니다.

`UiTreeOptions.TextOverflow`의 기본값은 Wrap입니다. 줄바꿈한 높이는 실제 행 배치에 반영됩니다. Ellipsis는 기존 문단 엔진으로 너비를 측정하고 결합 문자·이모지 ZWJ를 자르지 않는 접두부에 말줄임표를 붙입니다. 표시할 너비가 없으면 글자를 그리지 않습니다. 잘린 행만 기존 hover/focus Tooltip으로 전체 이름을 제공하며 Escape로 닫습니다. 접근성 이름은 항상 원문입니다. 방향·크기·너비 변경은 재측정하고 변경 없는 프레임은 조판을 재사용합니다.

라벨 검사16건, 두 테마·두 크기·RTL의 GPU4건과 이미지4장을 확인했습니다. 공개 API19건·기존 행 입력29건도 통과했습니다. 실행 샘플은 일반 문자열과 명시적 두 줄 콘텐츠, 줄바꿈/말줄임 전환을 함께 제공합니다. 이 검증은 Tree 전체·실제 Linux·외부 보조공학 수용 완료를 뜻하지 않습니다. [근거](../artifacts/fluent-tree-labels-2026-11-18/result.json).


## 행 안의 버튼과 입력 컨트롤

`UiTreeOptions.RowActions`를 켜면 행 안에 버튼이나 입력 컨트롤을 배치할 수 있습니다. F2를 누르면 첫 컨트롤에 초점이 갑니다. 방향키를 직접 사용하는 입력 컨트롤에서는 해당 키의 원래 기능이 유지됩니다. 그 외에는 좌우 방향키로 컨트롤 사이를 이동합니다. Escape를 누르면 행으로 돌아갑니다. Tree 전체가 Tab 순서에서 한 자리를 차지하며, 초점이 있는 가지가 접히면 보이는 상위 행으로 이동합니다. 버튼을 클릭해도 행 동작을 함께 실행하지 않습니다. 실행 샘플의 Duxel.App 행에서 열기 버튼을 확인할 수 있습니다. 접근성은 TreeGrid 아래에 계층형 행을 표시합니다. 펼쳐진 행마다 콘텐츠 셀 하나를 게시하고 버튼은 해당 셀의 자식으로 표시합니다. Windows UI Automation은 Grid와 GridItem 패턴을 제공합니다. Linux에서는 AT-SPI의 트리 표, 표 행, 표 셀 역할을 사용합니다. Linux 브리지는 Table과 TableCell에서 행·열 수, 셀과 범위 조회, 기존 행 선택을 제공합니다. 표 인덱스는 행 우선 좌표를 사용하며 접근성 트리의 자식 계층은 그대로 유지합니다. 실제 Linux에서 D-Bus 응답과 화면 읽기 프로그램 동작을 확인하는 작업이 남아 있습니다. 버튼에 초점이 있을 때 위아래 방향키를 누르면 인접 행의 같은 순번 버튼으로 이동합니다. 해당 버튼이 없으면 행 자체에 초점이 갑니다. Home과 End는 행의 첫 버튼과 마지막 버튼으로 이동합니다.

## 화살표와 여러 줄 행

펼침 화살표는 공통 160ms 전환을 사용합니다. `ReducedMotion = true`는 Tree 화살표를 즉시 바꿉니다. `AlignSelectorToTop = true`는 여러 줄 행의 체크 표시 또는 단일 선택 표시를 위쪽에 배치하며, 클릭 영역도 이에 맞춰 이동합니다. 갤러리의 각 예제 아래에는 현재 설정이 반영된 코드가 있습니다.

## Linux에서 접근성 확인

갤러리와 같은 Linux D-Bus 사용자 세션에서 `dotnet Duxel.Linux.App.Tests.dll atspi-gallery-tree <gallery-pid> <새-result.json>`을 실행하세요. 별도 libatspi 클라이언트가 폴더의 혼합 상태, 접기·펼치기, 폴더와 하위 항목의 체크 전환을 확인합니다. 두 번째 예제에서는 AT-SPI Table로 보고서 셀을 찾아 열기 버튼을 실행합니다. WSLg의 .NET 11 x64 NativeAOT 갤러리에서 7건을 모두 통과했습니다.

Linux 데스크톱의 같은 사용자 세션에서 갤러리와 Orca 또는 Accerciser를 실행하세요. GNOME에서 Orca는 `Super+Alt+S`로 켤 수 있습니다. **Tree → 행 안의 버튼**으로 이동해 보고서 행에 초점을 두고 F2로 열기 버튼에 들어가세요. Orca로 이름과 상태를 듣거나 Accerciser로 행·셀·버튼 관계를 검사할 수 있습니다. 자동 검증은 이 구조와 동작을 읽어서 실제 선택과 버튼 결과를 확인하는 데 활용할 수 있습니다. 현재 갤러리의 실제 Orca 동작은 미검증입니다.
