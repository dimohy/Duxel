# 다중 행 자동 줄바꿈

컴파일 다중 행 표현에서 `UiMultilineInputLayout.Wrap = true`로 설정하면 바인딩 모델에 줄바꿈 문자를 추가하지 않고 감쌉니다. 기존 기본값은 `false`로 유지합니다. `layout_multiline_wrap_fba.cs`는 생성 사용자 표현과 할당·콘텐츠가 바뀌는 실제 편집기 예제입니다.

감싸기를 켠 편집기는 시각적 행·원문 UTF16 경계·글자 진행 폭을 지연 소유합니다. [읽기 전용/Fluent 비감싸기 기하](multiline-hard-lines.ko.md)도 같은 기반으로 명시적 행을 소유합니다. 들어가는 공백 위치에서 줄을 나누며 긴 단어는 .NET `StringInfo`의 텍스트 요소 경계에서 나눕니다. 빈 명시적 행과 마지막 줄바꿈도 보존합니다. 영역보다 큰 요소 하나는 쪼개지 않고 클립합니다. 세로 overflow는 실제 스크롤바 공간을 예약해 다시 나누며 감싸기 모드는 가로 스크롤바를 만들지 않습니다.

그리기·포인터 위치·커서·선택·Home/End·상하·Page·누른 키 반복이 같은 행을 사용합니다. 인접 시각 행이 원문 인덱스를 공유하면 End와 포인터는 이전 행 끝의 위치 의미를 보존합니다. 연속 상하 이동은 짧은 행을 지나도 원하는 X를 유지합니다. 좌우·삭제·선택 정렬은 텍스트 요소 경계를 사용합니다. undo와 바인딩 알림에는 실제 편집만 들어갑니다. 브라우저의 모든 단어 분리·합자·양방향·입력기 동작 일치를 입증한 것은 아닙니다.

텍스트·할당·스크롤바 공간·줄 높이·텍스트 리소스 키가 바뀌면 행을 갱신합니다. 글리프 관찰로 측정 유지가 꺼지면 프레임 간 행 재사용도 끄고 같은 렌더 내 준비된 행은 일관되게 사용합니다. 컨텍스트 이동·해제 시 문자열과 기하를 정리합니다. Wrap 변경은 모드를 갱신하고 읽기 전용/Fluent 비감싸기는 명시적 행을 유지하며 기본 비감싸기 편집 경로는 선택 행 데이터를 놓습니다. 소유 매핑이 바뀐 뒤 오래된 결과를 그리려 하면 명시적으로 거부합니다. IME 미확정 표시는 별도 행·밑줄·커서 스크롤을 쓰지만 대기 핸들러 검사가 실제 Windows IME 동작 검증을 뜻하지는 않습니다.

## 검증 — 2026-11-11

고정 .NET 11 RC3에서 기존 다중 행 37개를 포함해 CPU 66검사를 통과했습니다. GPU는 이전 192개와 래스터/벡터·Light/Dark·MSAA 1/4·획득 이미지 재사용 4회의 감싸기 128개를 합친 320검사를 통과했습니다. 독립 기준은 원문 행 문자열과 사각형을 직접 사용해 기본·클립·스크롤·선택 화면을 구성합니다. readback은 433회이며 원래 이미지 파일 41개는 그대로 일치합니다. 관련 좌표·컨테이너·스크롤·가상 목록·수명 회귀도 별도로 통과했습니다.

초기 CPU 실패는 합성 키를 누른 채 둔 검사 환경과 실제 할당 재배치 후 커서 가시성 누락에서 나왔습니다. 키 해제를 보내고 의도한 반복은 별도로 검사하며 레이아웃 변경 시 커서 가시성을 갱신합니다. 초기 로그를 보존합니다. GPU 검사 호출부 컴파일 오류도 교정했으며 최종 빌드는 경고·오류 0입니다.

행 구조는 원문 텍스트 요소 수에 의해 제한되며 축소 후 남는 행 용량을 줄입니다. 다시 나누는 접두부 측정에는 현재 할당이 발생합니다. 할당·CPU 시간·Private 메모리·전앱 성능 개선을 주장하지 않습니다. 기존 도구 제약으로 현재 NativeAOT·런타임 비교는 미검증입니다. [Fluent Textarea 통합](fluent2-textarea.ko.md)에 표현·읽기 전용/placeholder/검증·관리 접근성 동작을 연결했으며 공식 외형/동작 전체 일치·복합 스크립트·실제 OS 입력은 미완료입니다.
