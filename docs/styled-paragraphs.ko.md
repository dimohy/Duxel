# 스타일 문단 스냅샷

엔티티 검증은 Windows 원문·커서 검사36개와 독립 DirectWrite 기준의 정확한 GPU 비교8쌍을 포함합니다. 관련 전체 GPU664쌍과 실제 옵저버44개 시나리오도 통과했습니다. [검증 근거](../artifacts/fluent-messagebar-2026-11-15/markdown-entity-verification.json).

HTML 엔티티의 렌더링된 문자는 원문 전체를 하나의 커서 단위로 사용합니다. `&amp;`, `&eacute;`, 여러 문자로 확장되는 `&fjlig;`, 보조 평면 숫자 엔티티를 구분해 검사합니다. 마우스·방향키·선택은 숨겨진 원문 중간에 멈추지 않으며, 활성 편집 블록에서는 원문을 그대로 편집합니다. 네이티브 줄바꿈이 확장 문자열을 나누지 않으면 전체 문단 조판을 유지합니다. 엔티티가 들어간 아주 좁은 행은 기존 원자 단위 줄바꿈 계약을 유지합니다. 옵저버의 **Markdown → 문단 조판 예제**에서 확인할 수 있습니다. 보조 평면 검사에는 해당 글리프가 있는 Segoe UI Symbol을 명시적으로 지정하며 기본 글꼴을 바꾸지 않습니다. 새 Linux 네이티브 실행과 전체 유니코드 편집 적합성 검증은 별도입니다.

표가 섞인 문서도 표 앞뒤의 텍스트를 네이티브 문단 조각으로 구성합니다. 각 조각은 파싱을 반복하거나 이미지를 별도로 소유하지 않고 부모의 활성 표시 블록·원문과 표시 위치·네이티브 행 정보를 보존합니다. 그림·마우스와 커서 경계·선택·이미지 접근성 영역이 같은 좌표 변환을 사용합니다. 표 경계의 마지막 빈 행은 한 번만 제외하며, 배치가 같으면 스냅샷을 유지하고 조각을 교체하면 이전 참조를 해제합니다. Windows에서 집중 검사 14개와 문단·표·접미 문단의 독립 GPU 비교 48쌍을 추가했습니다. 기준은 앞 빈 줄을 포함한 네이티브 글리프 원점과 실제 뷰어의 내용 클리핑을 유지해 MSAA4까지 비교합니다. 네이티브 문단 조건에 해당하지 않는 기존 확장 문자 사례는 이전 배치를 유지하며, 전체 편집·유니코드 적합성과 새 Linux 실행 검증은 남아 있습니다. [검증 근거](../artifacts/fluent-messagebar-2026-11-15/markdown-mixed-native-verification.json)를 참고하세요.

렌더링된 표 셀은 문서를 다시 파싱하거나 이미지 자원을 별도로 소유하지 않고, 변경되지 않는 원문 조각과 공통 네이티브 문단을 사용합니다. 열의 자연 너비·정렬·여백·가로 넘침은 유지하며 셀 안에 자동 줄바꿈을 추가하지 않습니다. 그림·원문 커서·양방향 마우스 경계·선택 조각·이미지 접근성 영역이 같은 셀 배치를 사용합니다. 방향키는 숨겨진 파이프 문법 대신 셀 경계를 건너며, 배치 조건이 같으면 셀 스냅샷을 재사용합니다. 표 원문을 펼치면 셀 배치를 해제하고, 모든 표가 펼쳐진 문서는 네이티브 문단으로 원문을 표시합니다. 표가 섞인 문서의 바깥 블록도 네이티브 문단 조각으로 구성합니다. Windows에서 집중 검사 13개와 좌·가운데·우 정렬, 너비180/240, 양쪽 테마, MSAA1/4의 정확한 픽셀 비교 48쌍을 추가했습니다. [검증 근거](../artifacts/fluent-messagebar-2026-11-15/markdown-table-native-verification.json)를 참고하세요.

작업 표시는 네이티브 인라인 객체로 공간을 차지하고 기존 Fluent 체크 상자 모양으로 그립니다. 이미지와 작업 항목은 캐시한 원문 단위 정보를 공유하므로 마우스·원문 순서 이동·화면 방향 이동이 숨겨진 문법 안에서 멈추지 않습니다. 작업 목록을 편집하면 파싱 결과를 유지한 채 객체와 원문 단위 정보를 해제하고 원문을 표시합니다. 인용문도 같은 네이티브 텍스트 조판을 사용하며 구분선은 별도 장식으로 그립니다. Windows에서 원문·배치 검사 11개와 GPU 비교 80쌍(작업 항목48·인용문16·구분선16)을 추가했습니다. 인용문의 독립 기준은 Segoe UI에 없는 막대 문자(│)와 뒤 공백에 지정된 보조 글꼴인 맑은 고딕을 사용합니다. 표가 포함된 문서는 기존 문서 조합 경로를 유지하며 새 Linux 네이티브 실행 검증은 남아 있습니다. [검증 근거](../artifacts/fluent-messagebar-2026-11-15/markdown-structure-verification.json)를 참고하세요.

네이티브 행 정보를 사용하는 여러 줄 입력과 Markdown 편집기의 일반 좌우 방향키는 화면의 글자 경계를 따라 이동합니다. 양방향 문장의 앞·뒤 경계와 같은 원문 위치를 공유하는 줄바꿈 행을 보존합니다. 길게 누르기도 같은 경로를 사용하며 Shift 선택은 원문 기준점을 유지합니다. 같은 행의 선택을 해제하면 해당 방향의 화면 경계로 이동하고, 이미지는 하나의 단위로 건넙니다. Delete·Backspace·Ctrl+단어 이동은 원문 순서를 따릅니다. 한 줄 입력과 네이티브 행 정보가 없는 구조적 행은 기존 이동 경로를 유지하므로 전체 편집기 적합성 완료를 뜻하지 않습니다. Windows의 독립 마우스 경계와 실제 키·반복 입력을 따로 검증했으며 새 Linux 실제 실행은 미검증입니다. [커서 좌표 계약](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nf-dwrite-idwritetextlayout-hittesttextposition)을 참고하세요.

일반 Markdown 문단의 이미지는 네이티브 인라인 객체로 공간을 차지합니다. 그림·접근성 영역·마우스 경계가 같은 배치를 사용하며 RTL 문맥과 줄바꿈에서도 숨겨진 이미지 문법 전체를 하나의 원문 단위로 다룹니다. 편집 중인 블록은 이미지를 예약하는 대신 원문을 표시합니다. 배치가 같으면 문단 스냅샷과 기존 이미지·SVG 자원을 재사용합니다. Windows에서 원문·영역 검사 7개와 독립 시스템 TextLayout·객체 구현을 기준으로 한 GPU 픽셀 비교 48쌍을 추가했습니다. 표는 별도 셀 배치를 유지하며 작업 항목·인용문·구분선은 네이티브 문단을 공유합니다. 새 Linux 네이티브 실행은 미검증입니다. [검증 근거](../artifacts/fluent-messagebar-2026-11-15/markdown-native-images-verification.json)를 참고하세요.

저수준 객체 계약 `PlatformTextParagraphObject`는 U+FFFC 한 글자에 너비·높이·상단에서 기준선까지의 거리를 지정합니다. 요청은 정렬된 고유 원문 위치와 유한 크기를 검증하고 배열을 복사합니다. 기존 생성자는 유지하며 객체 목록을 받는 별도 생성자를 추가했습니다. Windows는 [IDWriteInlineObject](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nn-dwrite-idwriteinlineobject)의 실제 크기를 조판에 사용하고, `PlatformTextParagraphLayout.Objects`로 원문 위치·왼쪽 상단 영역·방향을 반환합니다. 대체 글리프를 그리지 않으며 COM 객체는 스냅샷에 남지 않습니다. 기준선은 객체 밖에도 있을 수 있어 음수와 높이를 넘는 유한 값도 허용합니다. 실제 소유 위젯은 이 배치를 사용하며 가운데 정렬을 유지합니다. Linux Pango shape 코드도 연결했으나 실제 실행 검증은 대기 중입니다. Markdown 이미지와 작업 표시는 네이티브 객체 배치에 연결했고 인용문·구분선도 문단 배치를 공유합니다. 표 셀도 원문 조각을 통해 네이티브 문단을 사용합니다. 이 저수준 API 추가를 전체 위젯 지원 완료로 해석하지 않습니다.

var request = new PlatformTextParagraphRequest("A \uFFFC B",

    [new(2, 40, 24, 24)], width: 240);
var layout = paragraphBackend.CreateParagraph(request, vectorMetrics: false);
// layout.Objects contains native allocations for externally painted children.

`IPlatformTextParagraphBackend`는 원문 전체를 명시적 폰트·스타일 구간, 줄바꿈 너비와 기준 방향에 따라 조판합니다. `PlatformTextParagraphRequest`는 스타일 배열을 복사하고 네이티브 실행 전에 UTF16 원문 전체가 빠짐없이 지정되었는지 검사합니다. 구간은 서로게이트 쌍을 나눌 수 없습니다. 양의 무한 너비는 줄바꿈 없음을 명시하며 너비 0도 유효합니다.

`PlatformTextParagraphLayout`에는 원문 기준 행, 2차원 커서, 행 위치와 불변 글리프 런이 들어 있습니다. 각 런은 스타일 번호, 정확한 폰트 리소스, 원래 순서, 양방향 수준, 오프셋과 소수점 네이티브 원점을 보존합니다. 래스터·벡터 그림은 원문 일부를 다시 조판하지 않고 이 글리프를 사용합니다. 관리형 스냅샷에는 COM 핸들이 남지 않습니다.

행의 `Length`는 `NewlineLength`로 보존하는 명시적 줄바꿈을 제외합니다. `Advance`에는 끝 공백도 포함됩니다. `WidthWithoutTrailingWhitespace`는 원문 위치나 커서를 바꾸지 않고 줄바꿈된 실제 배치 너비를 측정합니다. Core는 디자인의 행 간격을 유지하며 그림과 상호작용에 같은 네이티브 위치를 적용합니다.

Windows는 명시적 폰트의 DirectWrite TextLayout을 사용합니다. Linux는 전용 폰트 맵의 Pango 문단에 크기·폰트 구간, 줄바꿈과 기준 방향을 적용합니다. 두 플랫폼의 일반 문자열용 `UiInlineText`가 같은 결과의 행, 측정값, 커서·선택 위치와 캐시된 래스터·벡터 런을 사용합니다. GPU 리소스는 기존 폰트 아틀라스 할당·의존성·무효화 경로에서 관리합니다. 그림 색상만 바꾸면 문단을 다시 조판하지 않습니다.

`./run-gallery.ps1`로 실행하고 **타이포그래피** 탭에서 **혼합 굵기 문단**까지 스크롤하세요. 한글·라틴, 히브리어·아랍어와 한글·히브리어 폰트 경계를 지나는 명시적 방향 문맥을 확인할 수 있습니다. 편집용 입력 상자가 아닌 표시용 위젯입니다.
