# 변경 영역 렌더링

2026-11-06 실제 앱 후속 비교는 [최적화 평가](optimization-evaluation.ko.md)의 명령 구간 누적 후보를 우선한다. 정확성 검사는 통과했으나 실행별 시간·메모리 범위가 겹쳐 개선 미확정이다. 아래11/04 수치는 당시 단계의 역사적 근거이며 현재 후보와 합산하지 않는다.

최신 공통 경로 평가는 [최적화 평가와 개선](optimization-evaluation.ko.md)을 따른다. 변경 판정은 streamed 기하 업로드·용량 확장보다 먼저 실행하며, 변경이 비어 있으면 업로드와 draw 계획을 생략한다. 정적 캐시 수명·입력·레이아웃·texture 무효화·프레임 제출은 유지한다. 일반 primitive 명령은 현재 항목을 ref로 처리한다. 이번 평가의 FPS·메모리 판정은 아래 이전 단계의 비교와 별도로 보존하며 합산하지 않는다.

> Last synced: 2026-11-06

최신 메모리 판정은 아래 **추가 12초 메모리 비교**를 따른다. Private는 정지2.17%·이동3.02% 감소했고 실행 범위가 겹치지 않았다. 앞선3초 판정도 별도로 보존한다.

공통 Vulkan 렌더러는 화면 좌표의 정적·동적 목록과 메뉴·팝업·툴팁을 대상으로 이전 이미지를 보존한다. 획득한 스왑체인 이미지별 명령 이력을 비교하여 이전·새 경계의 합집합만 지우고, 해당 영역과 겹치는 모든 명령을 기존 순서대로 다시 그린다. 반투명 요소의 이동·삭제도 배경부터 복구하며 벡터를 비트맵으로 바꾸지 않는다. 변경이 없으면 draw를 발행하지 않는다. 입력·레이아웃·화면 구성 콜백과 프레임 제출은 계속 실행한다.

동적 기하는 명령별 실제 정점·인덱스·primitive 바이트를 비교한다. GPU 상주 기하는 기존 `StaticGeometryKey`와 내용 revision 계약을 사용한다. 이력은 원본의 풀 버퍼를 보관하지 않는다. 스냅샷의 마지막 이미지 독자가 끝난 뒤 저장공간을 재사용한다. 해시만으로 동적 바이트의 동일성을 판단하지 않는다.

MSAA는 별도 화면 복사본을 추가하지 않고 기존 multisample attachment를 저장한다. 공유 MSAA 표면과 획득한 resolve 이미지의 이력을 함께 비교하고, 두 변경 영역의 합집합을 복구한 후 부분 resolve한다. `renderArea`와 scissor를 함께 제한하며 초기 이미지, 화면 크기·좌표계·배경색·텍스처 변경은 전체 화면을 무효화한다. [Vulkan의 attachment 연산은 render area 안에서 수행된다](https://docs.vulkan.org/refpages/latest/refpages/source/VkRenderingAttachmentInfo.html).

일반 투영·깊이 3D 장면, 사용자 draw 콜백 및 GPU 시뮬레이션 명령은 전체 화면 의존성을 갖는다. 해당 프레임은 전체 갱신하고 오래된 이미지 이력도 무효화한다. 3D 카메라 장면의 기하·GPU 버퍼 재사용은 기존 공통 경로를 계속 사용한다. 임의 3D 장면의 부분 재그리기를 보장하는 기능은 아니다. 넓게 흩어진 변화는 합집합이 커지므로 절감 효과가 작아질 수 있다.

장수명 표시 스냅샷은 실제 길이의 소유 배열을 사용하여 수많은 표면마다 풀 버킷의 여유 공간을 유지하지 않는다. 공통 유지 기하 배처도 알려진 스트림 크기를 미리 확보하고 장수명 소유 배열을 사용한다. 일반 프레임 빌더와 변경 중인 표면은 기존 풀·용량 유지 정책을 보존한다.

업로드 staging은 마지막 사용 이후 공통 캐시 유예 기간인 180프레임을 지나고 업로드 fence가 완료되었으며 기록 중인 배치가 없을 때 반환한다. 이후 업로드는 필요한 크기로 다시 생성한다. 초기 대량 업로드의 고수위 버퍼를 정지 화면의 상주 기하와 함께 영구 보관하지 않는다. 이는 강제 GC나 GPU 사용 중인 버퍼의 조기 해제가 아니다.

기본 활성화다. 진단 시 프로세스를 시작하기 전에 `DUXEL_VK_DAMAGE=0`을 설정하면 전체 갱신 경로를 비교할 수 있다. 샘플의 도형 수·창 크기·MSAA·벡터 품질을 줄이는 설정이 아니다.

재현은 기존 측정기를 사용한다. `SESSION_HANDOFF.md`의 후속 인계와 `artifacts/retained-damage-2026-11-04/`의 비교 계획·실행 파일 해시·원본 프레임·메모리·stdout/stderr가 이번 결과의 기준이다. .NET10 소스 검증과 고정 .NET11 RC3 NativeAOT Speed 측정은 별도 결과다.

아래 성능 수치는 Windows의 RTX 5070 Ti Laptop GPU에서 측정했습니다. 현재는 Linux X11에서도 갤러리를 실행할 수 있습니다. Linux x64 NativeAOT 갤러리는 Ubuntu/WSLg에서 Vulkan 화면 표시 검사 100개를 통과했습니다. ARM64와 라즈베리파이 실기기 성능은 아직 측정하지 않았습니다. [Linux 갤러리 실행 방법과 검증 범위](../samples/Duxel.Gallery.Linux/README.ko.md)
