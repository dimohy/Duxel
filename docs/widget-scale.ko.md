# 버튼 1만 개의 공통 입력 ID 재사용

Last synced: 2026-11-05

## 최신 후속: 일시 객체의 할당 회귀 해결

2026-11-05에 ID 캐시 저장소를 처음 범위가 있는 렌더를 수행할 때 생성하도록 바꿨다. UiWidget의 기존 정체성 참조가 생성 시에는 문자열 토큰 또는 null이고, 범위 렌더 후에는 소유 캐시를 가리킨다. 이는 실행 중 테마 선택이 아니라 입력 정체성의 수명 상태다. 소스 생성기의 구체 동작·표현 연결은 유지한다. 소유되지 않은 Parent 팩터리에는 캐시 객체를 만들지 않는다.

.NET10에서 팩터리1,024개 할당은122,880→98,304B로20% 줄어 ID 캐시 도입 전의 수준을 회복했다. 이전 delegate131,072B보다25% 적다. 이25% 기준을 집중 회귀에 연결했다. 전체802검사·생성기64검사·net8/9/10 경고0·오류0을 확인했고 직전 버전과 기존 이미지323개가 같다.

같은 CPU 측정기를 사용하여 원본(original), 필드3개 방식(inline), 지연 저장(lazy)을 각각3회 독립 실행했다. 순서는 original/inline/lazy, lazy/inline/original, original/lazy/inline이며 원본과 최종의 순서는 AB/BA/AB다. SDK·런타임·RID·Speed·부하·클립·글자 fixture·준비/측정 시간은 아래와 같다. 최종 할당은 모든 조건664B/반복을 유지한다.

| 조건 | 원본→최종 CPU median ms | 감소율 | inline→lazy 종료 Private MiB |
|---|---:|---:|---:|
| idle | 3.5012 → 3.0672 | 12.40% | 15.27 → 15.75 |
| scroll | 3.5261 → 3.0569 | 13.31% | 23.50 → 24.18 |
| partial | 3.5191 → 3.0761 | 12.59% | 31.70 → 32.63 |
| full | 3.5223 → 3.0760 | 12.67% | 39.89 → 41.07 |

원본 대비 median은 각3회 범위가 겹치지 않았고, 직전 inline 대비 CPU 차이는 모두 범위가 겹쳐 성능 변화 미확정이다. 원본 대비 idle/scroll p95·p99는 개선 범위가 겹치지 않았으나 partial/full p95·p99는 겹친다. 일부 지표의 중앙값 악화도 comparison.json에 보존했다.

**상주 비용의 교환은 남는다.** 위젯 본체의24B 증가를 제거했지만, 실제 유지 범위 렌더 때48B 캐시 객체를 한 번 만든다. 즉 이 위젯의 본체+캐시는 직전 inline 방식보다24B 많다. 이번 진단에서 inline 대비 종료 Private는 조건별 약0.47~1.18MiB, 작업 집합도 약3.42~4.42% 증가했고 범위가 겹치지 않았다. 일시 객체의 회귀 해결을 전체 메모리 감소라고 보고하지 않는다. 최종 종료 Private는 모든 조건에서 캐시 도입 전 원본보다 낮지만, 이전 조건의 미수거 객체를 포함하는 짧은 관측이며 장기/최대/앱 전체 검증은 계속 남는다.

현재 결과: artifacts/widget-identity-storage-2026-11-05/comparison.json, verification.json, runs.jsonl, full-net10 및 image-comparison.json. 아래는 필드3개 초기 후보의 역사적 기록이다.

이번 개선은 유지된 기본·사용자 위젯의 입력 ID 생성 비용이다. 소스 생성기는 같은 구체 구현 클래스를 직접 연결하고, 런타임의 유지 위젯은 그 인스턴스별 ID를 재사용한다. 버튼 1만 개를 위한 클래스 1만 개를 생성하지 않는다. 전체 Fluent 룩앤필·DirectText·GPU 업로드/draw·앱 FPS 또는 Pi 성능의 완료 증거는 아니다.

## 원인과 구현

기존 공통 ID 캐시는 4,096개·1,048,576자 상한이다. 유지 버튼 1만 개를 순회하면 뒤쪽 ID가 캐시에 들어가지 못해 프레임마다 문자열을 생성했다. 전체 캐시 상한을 키우는 대신 UiWidget이 현재 부모 범위·해석된 범위·기본 입력 ID를 보유하도록 바꿨다. 기본 위젯과 사용자 상속 모두 같은 경로다. 부모 범위 변경 시 교체하고 Dispose 시 해제한다. 임의의 추가 PushID 범위는 기존 공통 ID 해석을 유지한다.

위젯별 캐시는 입력 참조를 포함해 최대 4,096자다. 초과하는 긴 범위는 위젯 소유 캐시에 넣지 않으면서 정확한 ID를 계산한다. 전역 캐시 상한도 유지한다. 입력과 콜백은 매 프레임 실행하며 paint·레이아웃·벡터 품질·샘플 부하를 줄이지 않았다.

## 고정 RC3 NativeAOT CPU 비교

기존 Performance.Bench와 BenchFrameRecorder에 --widgets 모드를 연결했다. JSON 기록은 타입 지정 DTO와 소스 생성 JsonSerializerContext를 사용한다. 최초 Native 게시에서 기존 반사 기반 기록의 IL2026/IL3050 경고를 발견해 해당 기록 경로를 수정했으며 경고 산출물은 측정에 사용하지 않았다.

SDK 11.0.100-rc.3.26522.148, 런타임 11.0.0-rc.3.26522.148, win-x64, NativeAOT Speed다. Core는 양쪽 모두 net10.0이며 원본 Core+생성기 소스를 별도 보존했다. 같은 atlas 글자 fixture, 1600×1000 clip, 버튼 10,000개, 준비0.5초·측정1초다. 10열×1,000행을 전부 호출하므로 화면 밖 위젯도 CPU 처리한다. partial은100개 라벨, full은10,000개 라벨을 미리 만든 같은 길이 문자열로 교체한다. scroll은 위치를 바꾼다. 각3독립 프로세스를 AB/BA/AB로 실행했고 강제 GC를 사용하지 않았다.

|---|---:|---:|---:|---:|
| idle | 3.4985 → 3.0398 | 13.11% | 378528 → 664 | 36.26 → 15.67 |
| scroll | 3.5061 → 3.0379 | 13.36% | 425752 → 664 | 36.90 → 23.89 |
| partial | 3.5407 → 3.0963 | 12.55% | 425752 → 664 | 35.64 → 32.09 |
| full | 3.5600 → 3.0569 | 14.13% | 425752 → 664 | 46.39 → 40.29 |

median과 할당·종료 Private·작업 집합은 각3회 범위가 겹치지 않았다. idle/scroll p95도 개선 범위가 겹치지 않았지만 partial/full p95는 겹쳐 개선 확정으로 세지 않는다. partial p99도 미확정이다. 원본·모든 지표·변동 범위는 artifacts/widget-scale-2026-11-05/comparison-final.json 및 final-*.csv에 보존했다. CPU draw-data 명령 수는 양쪽562이며 이는 GPU draw calls가 아니다.

Private는 각 조건 끝의 관측값이다. 네 조건이 한 프로세스에서 순서대로 실행되어 이전 조건의 미수거 객체도 포함할 수 있다. 장기 증가·최대값·캐시 수명 종료 후 상주량 안정화 또는 실제 앱 전체 메모리 감소로 확대하지 않는다.

## 검증·비용·남은 일

.NET10 전체801검사·생성기64검사, net8/9/10 솔루션 경고0·오류0이다. 10,000개 동일 라벨의 서로 다른 ID, 전부의 문자열 참조 재사용, 부모 이동·긴 범위 상한, 마지막 버튼의 라벨 변경 중 단일 콜백을 확인했다. 최종 상한 적용 전후 기존 출력 이미지323개가 같다. 공식 Fluent 참조 화면과의 비교는 아니다. 기존 RC3 전체 GPU 입자 실패는 미해결로 남기고 불필요하게 재실행하지 않았다.

관리 .NET10에서 새 캐시 필드3개는 위젯당24B를 추가한다. 일시적인 팩터리 객체1,024개 생성은 이전98,304B에서122,880B로25% 증가했다. 이전 delegate 팩터리131,072B보다는6.25% 적지만 현재 전환의 실제 비용으로 기록한다. 유지 위젯의 프레임별 생성 비용과 구분하며 이 회귀 해결도 남아 있다. Native 진단 EXE는3,351,552→3,352,576B(+1,024B)다.

다음은 일시 팩터리 객체 비용, DirectText·레이아웃·paint 재사용, 실제 앱 NativeAOT의 GPU/메모리·장기 부하 검증이다. 전체 목표와 모든 미완료 축을 유지한다. 기존 실행 파일과 삭제 거부 대상은 보존했다.
