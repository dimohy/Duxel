# Single-line pointer selection and scrolling

[Shared text drag ownership](text-drag-ownership.md): single-line and multiline now share explicit press ownership and a timestamp; focus-only held input cannot select. CPU444/multiline2560 pass, including context/scrollbar lifetime and pointer GPU checks. Full OS capture/word-drag/partial-occlusion/native fidelity remains open.

A press inside the visible editing area owns a single-line drag independently of keyboard focus. While held, selection continues outside both horizontal and vertical field bounds. The pointer is clamped horizontally to the content edges for source-element hit testing. Horizontal overflow pans the source at a distance-dependent speed, using elapsed time bounded to 1/240–1/30 second; 30/60 Hz behavior is checked. The original selection anchor stays fixed while direction reverses. A changed scroll offset requests another frame only while more movement remains, so a stationary pointer continues scrolling and an endpoint stops scheduling.

UiState holds one internal drag owner, frame and timestamp; it adds no per-widget dictionary or public API. New presses, release/up, active-control transfer, an omitted owner at frame end, disposal and context transfer clear ownership. A press/release delivered together cannot retain it. Fully clipped, disabled, layout-blocked or higher-popup-blocked editors release capture. Press hit testing retains the actual parent clip and editing-slot bounds. A partly clipped control keeps its allocated content geometry; this change does not redefine its layout or establish complete partial-occlusion, word-drag or native OS capture behavior.

Readonly text remains selectable and scrollable without changing the binding. External source shrink clamps selection and scroll. Incoming IME handling and the existing source-element/word rules remain shared with keyboard editing. Full shaped/bidi pointer geometry and real OS IME are still open.

Fixed .NET 11 RC3 validation reproduced 19 initial failures and two additional coalesced press/release failures. The combined editing suite passes 336 checks, including 35 drag checks in standard and Fluent behaviors. Input-kernel passes 400 checks, including 96 actual-pointer GPU comparisons: left/right outside selection and horizontal pan, raster/vector, Light/Dark, MSAA1/4 and four acquired-image reuses. Literal selection/caret/offset references do not call the capture logic. All 357 previous input images and 3,457 multiline images match. Details: `artifacts/input-drag-2026-11-11/verification.json`.

`fluent_input_elements_fba.cs` now includes a long-text button and drag instructions. Its automatic run exercises value/readonly transitions, while injected pointer behavior is covered separately by CPU/GPU fixtures. Actual OS mouse capture across windows, official visual fidelity, current Native/runtime comparison and integrated performance remain unverified; the original whole-goal scope and resize hold are preserved.
