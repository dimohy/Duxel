# Nonwrapping multiline source geometry

[Multiline source elements](multiline-elements.md): plain editing now keeps combining/supplementary elements intact; all modes align between same-frame edits and queued IME. CPU393/multiline2464 pass; prior input693/multiline3457 images match. Readonly multiline controls and Fluent navigable Textarea use owned source-indexed line data when `Wrap = false`. CRLF is one text element and one hard break; standalone CR and LF are hard breaks too. Empty and trailing lines retain their original UTF-16 ranges. The readonly value and copied text preserve the original delimiters. Standard unwrapped editable behavior keeps its existing editing path.

The same line data drives painting, pointer hits, caret placement, selection, Home/End, vertical movement, preferred X, text-element movement/deletion and repeat. Triple click selects the logical hard line. Nonwrapping mode does not create soft rows. Changing Wrap invalidates the mode key; ownership releases source, preview and placeholder data on context transfer/disposal or when the standard editable path stops using it. Measurement remains metadata-only.

Both scrollbars use the actual assigned root and content insets. Horizontal overflow can reduce usable height enough to require a vertical bar; vertical overflow can similarly require a horizontal bar. A monotonic two-axis calculation reserves both gutters and gives the editor its effective content viewport. Source shrink clamps offsets and releases disappearing captured bars. At the horizontal endpoint, the caret stroke stays inside the content edge; parent clipping continues to apply.

IME preview uses separate hard-line display data, normalized as editable multiline input, with both overflow axes and caret scrolling. Ending preview releases its display rows. The preview does not enter the model. These queued-handler checks do not prove actual OS IME candidate/pointer behavior.
