# 구현 수용 기준 점검

2026-11-16에 원래 위젯 재사용·위젯 트리·컨테이너·Observer 원장 네 개의 50개 항목을 다시 읽었다. 항목별 원문과 기존 완료 상태는 [점검 기록](../artifacts/goal-audit-2026-11-16/acceptance-review.json)에 보존한다. 개별 회귀 검사 통과를 전체 제품 완료로 바꾸지 않는다.

2026-11-19에 현재 원장 네 개에서 같은 항목 ID 50개를 확인했습니다. 완료는 33개입니다. 위젯 재사용은 20개 중 11개, 위젯 트리와 테마는 14개 중 6개, 컨테이너는 6개 중 6개, 갤러리는 10개 중 10개입니다. 이 합계는 네 원장의 범위입니다.

## 이번에 발견한 결함

Observer에서 **Popover → 프로필 편집 열기 → 프로필 편집 닫기**를 실제 컨트롤의 합성 포인터 입력으로 실행하면 접근성 관계를 연결하다 충돌했다. 닫힌 표면의 접근성 노드는 같은 프레임에 제거됐지만, 별도 Label과 입력 위젯 사이의 대기 중 관계는 남아 있었다.

공통 오버레이 종료 경로가 노드와 대기 중 Label 관계를 함께 제거한다. 다른 표면의 관계는 유지하고, 다시 열린 표면은 현재 노드로 새 관계를 만든다. 관계의 유효성 검사는 그대로 유지한다. Observer 회귀에는 닫은 뒤 다시 열었을 때 실제 Label과 입력의 연결을 확인하는 조건을 추가했다.

확장 입력 검사에서는 별도 테스트 자원 문제도 확인했다. 보조 평면 문자 `U+1F600`을 정상 입력하는 검사가 해당 글리프 없는 글꼴 쌍을 선택했다. 이 사례만 Segoe UI Emoji를 명시적으로 선택하며, 글꼴이 없으면 실행 전에 실패한다. 문자를 바꾸거나 제품의 미지원 글리프 오류를 숨기지 않는다.

최종 소스에서는 Observer 316개, Label 63개, 복합 계약 500개, 문자 편집 4,114개, Tooltip GPU 792개, Popover GPU 452개 검사가 통과했다. 각 범위는 중복될 수 있다. 일반 Observer의 44개 페이지는 화면 제출 확인을 통과했으며 픽셀 비교나 실제 키보드 검증은 아니다. Windows와 Linux 호스트 빌드는 경고·오류가 없었다. 실제 Linux 실행은 수행하지 않았다.

Windows와 WSLg Linux의 관리형 화면 재사용 검사에서 각 운영체제 내부의 픽셀 검사는 통과했습니다. 같은 이름의 장면을 비교한 결과 574쌍 중 214쌍이 일치했고 작은 영역 갱신 160쌍은 모두 일치했습니다. 운영체제 간 나머지 픽셀 차이와 갤러리 전체 비교는 추가 검증이 필요합니다. [Vulkan 픽셀 검증 범위](../tests/Duxel.Vulkan.Linux.Tests/README.ko.md)

프로젝션 레이어의 소수 좌표 테두리는 개별 클립을 적용하기 전에 가장자리 커버리지를 계산합니다. 독립적인 1× MSAA 검사에서 테두리의 색과 클립 바깥의 빈 픽셀을 확인합니다. .NET 11.0.0 Windows 관리형과 WSLg x64 NativeAOT에서 통과했고, WSLg에서 이전 셰이더의 결함을 재현했습니다. 운영체제 간 다른 픽셀 차이는 추가 확인이 필요합니다.

WSLg의 Cairo 1.18.0에서 Linux 문단의 글리프 묶음별 마스크 합성은 독립적인 네이티브 기준과 36개 사례 모두 일치했습니다. Pango로 같은 표면에 직접 그린 결과와 비교하면 알파값이 다른 사례 7개가 남아 있습니다. Duxel과 Vulkan을 호출하지 않고 Cairo 표면에 글리프 묶음 하나만 그려도 차이를 재현했습니다.

기존 여섯 축의 합계 스냅샷에는 개별 항목의 소속이 기록되지 않았다. 이번 50개 원문 항목을 그 합계에 임의로 배분하지 않았다. 기존 수치는 과거 원장의 수치이며, 현재 전체 기능의 검증률로 해석하지 않는다. 최종 회귀 결과와 실행 파일·소스 해시는 같은 폴더의 `verification.json`에 기록한다.

외부 Windows UI Automation 클라이언트로 일반 .NET 11 갤러리에서 검색어와 여러 줄 텍스트를 입력했습니다. 다른 메뉴에 다녀와도 SearchBox와 Textarea의 값과 화면에 표시된 C# 초기값이 유지됐습니다. SearchBox의 지우기 버튼을 실행하면 검색어와 코드의 초기값이 함께 비었고, 메뉴를 오간 뒤에도 빈 값이 유지됐습니다. 갤러리는 정상 종료했습니다. 실제 키보드·한글 IME·스크린리더 검증은 남아 있습니다.

## 공통 입력 단계의 추가 근거

현재 공통 Input/Presentation 단계에서는 이벤트마다 배치와 동작을 처리하고 최종 표시만 생성합니다. 실제 버튼 콜백이 바꾼 여백·레이아웃/시각 회전·배율·부모 회전·스크롤과 세 편집기의 이동 후 클릭·편집을 두 순회 순서로 검증했습니다. 새84개를 포함한345개가 통과했습니다. 제품 소스20개의 해시는 직전 공통 단계 검증과 동일합니다. [추가 검증](../artifacts/goal-audit-2026-11-16/interactive-phase-verification.json).

당시 기록에는 `cpu-behavior`의 일부 근거가 담겨 있습니다. 과거 원장의 50개 기준은 완료 24개, 미완료 26개로 보존합니다. 현재 원장에서는 Windows .NET 11 기본 위젯 동작 검증을 완료했습니다. 관리형 검사 4,646건을 통과했고, 이전 NativeAOT와 공통 GPU 이미지 4,038쌍이 모두 일치했습니다. 새 Switch 방향 이미지 8장은 현재 빌드에서 별도로 검사했습니다. 네이티브 창과 리사이즈 검사는 보류 중입니다. 현재 NativeAOT, 메모리 상한, 플랫폼별 검증은 각각 별도 기준으로 남아 있습니다.
