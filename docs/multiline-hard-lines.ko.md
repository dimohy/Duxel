# 감싸지 않는 다중 행의 원문 기하

[다중 행 원문 요소](multiline-elements.ko.md): 기본 편집의 결합·보충 문자 분할과 모든 모드의 동일 프레임/대기 IME 정렬을 수정했습니다. CPU393·다중행2464 통과, 이전 입력693장·다중행3457장 일치. [Native 상태](native-toolchain-status.ko.md)는 이전 P: 도구체인을 현재 사용할 수 없고 현 위치가 미확인임을 구분합니다.

읽기 전용 다중 행과 Fluent 탐색 Textarea는 `Wrap = false`에서도 소유한 원문 인덱스 행 데이터를 사용합니다. CRLF는 텍스트 요소 하나이자 명시적 줄바꿈 하나이며 단독 CR·LF도 줄바꿈입니다. 빈 행·마지막 빈 행도 원래 UTF-16 범위를 유지합니다. 읽기 전용 값과 복사한 텍스트는 원래 구분자를 보존합니다. 기본 동작의 감싸지 않는 편집 가능 경로는 기존 구현을 유지합니다.

같은 행 데이터가 그리기·포인터 위치·커서·선택·Home/End·상하 이동·선호 X·텍스트 요소 이동/삭제·반복을 처리합니다. 세 번 클릭하면 논리적 원문 행을 선택합니다. 비감싸기 모드에서는 소프트 행을 만들지 않습니다. Wrap 변경은 모드 키를 무효화하며 컨텍스트 이동·해제 또는 기본 편집 경로에서 행 데이터가 불필요해지면 원문·미확정 표시·placeholder 데이터를 놓습니다. 측정은 메타데이터만 사용합니다.

두 스크롤바는 실제 할당 루트와 콘텐츠 여백을 사용합니다. 가로 overflow가 유효 높이를 줄여 세로 바를 요구할 수 있고, 세로 overflow도 가로 바를 요구할 수 있습니다. 단조롭게 두 축을 계산해 양쪽 공간을 예약하고 실제 콘텐츠 뷰포트를 편집기에 전달합니다. 원문 축소는 오프셋을 보정하고 사라진 캡처 바를 해제합니다. 가로 끝의 커서 선은 콘텐츠 경계 안에 표시하며 부모 클리핑도 유지합니다.

IME 미확정 표시는 편집 가능 다중 행처럼 정규화한 별도 명시적 행 데이터를 사용하며 양축 overflow와 커서 스크롤을 반영합니다. 종료하면 표시 행을 놓습니다. 미확정 문자는 모델에 넣지 않습니다. 대기 핸들러 검사로 실제 OS IME 후보창·포인터 동작을 입증하지는 않습니다.

고정 .NET 11 RC3에서 CPU204·접근성40·수명101·다중 행 GPU2208·컨테이너237·좌표2317 통과입니다. 새 GPU 160검사는 기본·클립·선택·스크롤·오른쪽 끝 커서를 래스터/벡터·Light/Dark·MSAA1/4·획득 이미지 재사용 4회로 비교합니다. 이전 이미지 3,025장은 모두 일치하고 전체 readback은 3,265회입니다. 기준은 명시적 표시 행 문자열·원문 선택 사각형·커서 기하와 공통 스크롤바를 사용합니다. 내부 조합 검증이며 공식 브라우저 외형 일치 근거는 아닙니다.

초기 CPU는 16실패였습니다. 이미 End인 위치의 실패를 처음에는 검사 설정 문제로 오분류했으나 원래 검사를 복원해 키보드 의도 처리 결함을 확인했습니다. 이제 원문 인덱스가 바뀌지 않아도 이동 요청·누른 키 반복이 커서를 다시 보이게 합니다. 원래 끝 위치와 실제 이동을 모두 검사합니다. 원문 기하·이동·overflow 실패와 별도 GPU 오른쪽 끝 커서 실패를 수정했습니다. 로그는 `artifacts/multiline-hard-lines-2026-11-11`에 보존합니다.

`fluent_textarea_fba.cs`에 Wrap 전환과 CRLF/CR을 보존하는 읽기 전용 비감싸기 예제를 넣었습니다. 전체 Unicode 셰이핑·bidi·합자·브라우저 동작, 외부 Windows UIA와 실제 OS IME는 미완료입니다. 접두부 측정/재계산 할당·보유 메모리도 통합 성능 검증에 남습니다. 현재 Native·런타임 비교는 미검증이며 리사이즈는 사용자 보류를 유지합니다.
