# Tooltip 충돌·화살표 검증

Last synced: 2026-11-11

현재 [자동 크기/넘침](tooltip-auto-size.ko.md)은 상태를 유지한 재측정과 본문/전체 콘텐츠 영역을 제공한다.

현재 [측정 기반 배치](tooltip-measured-layout.ko.md)는 후보별 컴파일 오프셋과 실제 대상 폭 콘텐츠 재측정을 추가한다.

현재 [오프셋/덮기 검증](tooltip-offset-cover.ko.md)은 기존768참조를 유지하면서 부호 있는 오프셋·논리 패딩·덮기/이동 제한을 추가한다.

공유 계산기를 [고정 Fluent 잠금 파일](https://github.com/microsoft/fluentui/blob/8830c10bfb2f4c1bdd540287b09713b9679cd1ad/yarn.lock)이 선택한 Floating UI core1.6.8의 offset/flip/shift/arrow 계산에 맞췄다. [공개 core 모듈](https://unpkg.com/@floating-ui/core@1.6.8/dist/floating-ui.core.esm.js)과 utils0.2.8을 해시·MIT 고지와 함께 보관한다. 제품 구현은 컴파일된 C#이며 JavaScript는 독립 검사 기준 생성에만 사용한다.

향한 변 우선 best-fit, RTL 중앙 정렬의 기준 변, 불변 후보 순서, 분리된 선택/이동 경계, 화살표 폭, 1단위 패딩 여유, 작은 대상 정렬에서 한 번 재배치한 뒤 경계 이동을 재적용하는 규칙과 남은 `ArrowCenterOffset`을 반영했다. 기존 삼각형 폭은 기본적으로 높이의 두 배다. 향후 Fluent 표면은 CSS 화살표의 회전 전 정사각형 폭을 전달할 수 있으며 이번 단계에서 둥근 모양·그림자 합성까지 구현한 것은 아니다.

`reference-cases.mjs`는 원본 core의 utils import만 보관한 버전으로 바꿔 실행한다. 명시적인 플랫폼이 단위 배율의 대상/본문/경계 사각형과 화살표/클라이언트 크기를 제공한다. LTR/RTL·12방향·큰 본문·작은 대상·기본/사용자 후보(중복 포함)·분리 경계·고정·다양한 화살표 크기/패딩으로 결정적인 768사례를 생성한다. C#이 위치·본문·화살표 기준점·남은 차이를 허용오차0.001로 비교한다. 사각형 플랫폼 검사이며 DOM 조상/변환 전체를 검증하지 않는다.

첫 비교에서 RTL 중앙 후보 우선순위 차이5건을 발견했다. 부호를 유지한 정렬 변 조건을 수정한 뒤 참조 사례가 모두 통과했다. 최종 CPU 검사는1326개다. Tooltip GPU416개는 기존 실제 소유자 배치/옵션 검사 외에 밝은/어두운 테마·MSAA1/4별 참조 충돌 장면8개를 포함한다. 기존 측면 위/아래 정렬 기준은 화살표 재배치에 맞춰1단위 이동하며 변경 없는 이미지는 별도로 비교한다. 실행 샘플은 불변 사용자 후보 순서를 사용한다. 근거는 `artifacts/tooltip-collision-2026-11-11`이다.

해당하는 조상/배율 탐색·공식 둥근 화살표/합성 그림자·제어된 표시·전체 속성/창 종료 알림·Fluent 팩터리·현재 NativeAOT/런타임 비교와 원래 프로젝트 전체 목표는 남아 있다. Fluent 전체 준수나 성능 개선을 주장하지 않는다.
