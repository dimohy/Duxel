# 성능 최적화 기록 정책

> 마지막 동기화: 2026-07-10

> 사용자 검증 정책 변경(2026-11-18): 새 기능·회귀·성능 검증은 .NET 11 정식 SDK 11.0.100과 런타임 11.0.0을 사용한다. 성능 비교는 동일한 버전과 설정으로 NativeAOT를 실행한다. .NET 9·10은 최종 배포 컴파일에서 확인하고 공개 TFM은 유지한다. 기존 RC3 결과는 당시 검증 기록이다.

이 문서는 Duxel에서 성능/메모리 최적화를 수행할 때 **반드시 남겨야 하는 기록 기준**을 정의합니다.

## 1) 기록 원칙

- 최적화 1건마다 반드시 로그 1건을 남긴다.
- 로그는 "가설 → 변경 → 검증" 순서로 기록한다.
- 수치 검증은 가능한 한 동일 샘플/동일 옵션으로 A/B 비교한다.
- 결과가 음수(성능 하락)여도 숨기지 않고 그대로 기록한다.
- 저장소 벤치는 `global.json`의 .NET 11 정식 SDK를 기준으로 실행한다. 비교 양쪽의 정확한 SDK와 런타임 버전을 로그에 남긴다.

## 2) 필수 로그 항목

각 항목을 누락 없이 기록한다.

- 날짜/세션 식별자
- 변경 영역 (파일/모듈)
- 최적화 유형 (GC, 풀링/재사용, 비동기화, 핫패스 리팩토링 등)
- 변경 요약 (1~3줄)
- 검증 명령어
- Before / After 수치
- 개선율(%)
- 리스크/후속 과제
- SDK 버전, 워밍업 조건, 독립 실행 횟수
- 평균 FPS와 raw frame 기준 median/p95/p99 frame time, 1% low FPS

## 3) 로그 저장 위치

- 정책 문서: `docs/optimization-policy.ko.md`
- 세션 로그: `docs/optimization-session-YYYY-MM-DD.md`

## 4) 검증 기준

- 최소 1회 `dotnet build Duxel.slnx -c Release`
- 최소 1회 런타임 벤치 실행
  - 벡터: `./scripts/run-vector-clip-ab.ps1 ...`
  - 레이어 혼합: `./scripts/run-layer-widget-clip-ab.ps1 ...`
- 각 후보는 phase 측정 전에 최소 `0.25`초 또는 `96`프레임을 워밍업하고, 같은 조건으로 최소 3회 독립 실행한다.
- 비교값은 독립 실행 3회 이상의 중앙값을 사용한다. 평균 FPS만으로 결론 내리지 않고 raw frame sample에서 계산한 median/p95/p99 frame time과 가장 느린 1% frame의 조화 평균인 1% low FPS를 함께 기록한다.
- 순서 영향을 받을 수 있는 A/B phase는 실행마다 순서를 교대하거나 별도 프로세스로 분리하고, 결과 artifact에 실제 phase 순서를 기록한다. 자동 판정은 3회 이상 반복 중앙값과 noise 구간을 함께 사용한다.
- 벤치 결과는 phase별 표, 각 지표의 Before/After, 개선율(%)을 함께 기록한다.
- A-B-A-B 재검증에서 개선 방향이 뒤집히거나 실행 간 변동 구간이 겹쳐 결론이 달라지면 해당 정량 결과를 `INVALID`로 표시한다. 이때 성능 개선율을 주장하지 않는다. 소비처가 없다는 것이 코드 경로로 증명된 dead work 제거 같은 구조 변경은 정성 결과로 유지할 수 있지만, 정량 개선으로 합산하지 않는다.

## 6) 운영 규칙

- 새 최적화 PR/커밋에는 해당 세션 로그 링크를 포함한다.
- 동일 영역 재최적화 시 기존 로그를 덮지 않고 새 행을 추가한다.
- 측정이 어려운 구조 리팩토링은 정성 결과를 쓰되, 가능한 가장 근접한 지표를 함께 첨부한다.

### 2026-11-13 Popover 소유 메뉴의 이벤트 대기
가설: 소유 메뉴 포털을 외부 영역으로 판단해 500ms 뒤 부모까지 닫고, 포커스 제한 상태에서는 열린 메뉴의 트리거 포커스를 프레임 끝에 지웁니다. 변경: 실제 활성 메뉴의 트리거 소유권·직전/현재 게시 경계·상위 팝업 가림을 함께 검사하고, 메뉴의 정상 트리거 포커스를 해당 팝업 계층에 유지합니다. Before: 호버 포털 및 제한 모드 Escape 회귀 각각 실패. After: CPU65개 계약/9834회, GPU3회/825개, 네이티브3회/67개 통과; 고정 포인터 재생은297쌍 완전 일치. 예약 프레임 없음은 해당 비편집 회귀로 확인했으며 앱 전체 유휴 전력·정량 속도 개선을 주장하지 않습니다. 리스크: 직전 프레임 경계는 기존 팝업 입력 계약과 같으며 이동·숨김 수명 회귀를 유지합니다. 공식 진입 모션과 전체 적합성은 별도 미완료입니다. 근거 artifacts/popover-motion-2026-11-13/verification.json.

### 2026-11-13 Popover의 유한 진입 모션과 의존성 캐시

가설: 기존 paint-group을 재사용하면 겹치는 콘텐츠도 올바른 그룹 투명도로 처리하면서 텍스트·본문 래스터를 유지할 수 있습니다. 변경: 공식400ms·곡선·10px 방향 모션, 표시 좌표에서 한 번 처리하는 입력/IME/UIA, Projected 텍스트, 정확한 장면 비교와 참조 텍스처 버전, 정상 지연 해제를 연결했습니다. 전체 캐시 키에 무관한 텍스처 갱신을 넣지 않습니다.

Before: 진입 모션 없음. After:50ms에서 불투명도0.5·남은 이동5px, 정착 본문/화살표 래스터 업로드 유지, 같은 시점/장면의 그룹 갱신0회, 무관한 텍스처 변경0회, 참조 텍스처 변경1회 갱신을 CPU로 확인했습니다. GPU는 불투명한 빨강·초록 자식의 겹침을 파란 배경 위에 그룹0.5로 합성하고 실제 클릭을1회 처리합니다. 시간/속도 개선율은 미측정입니다. 움직임 자체는 변경이므로 장면 합성을 다시 수행할 수 있으며 모든 진입 프레임이 단일 사각형 재생이라고 주장하지 않습니다.

검증: 최종 관리형 CPU65개 계약/9901회, GPU5회/1751개, 실제 Windows 접근성2회/22개, 렌더링 탭 숨김/표시 각각614프레임 정상 종료. 프레임 슬롯2/3의341쌍이 완전히 같고 이전 정적297개 이미지도 그대로 유지합니다. 리스크:2D 그룹의 기존 예산·미지원 소스 제한, 정상 입력창의 커서 예약, 정착 후 다음 프레임에서 처리하는 지연 텍스처 해제는 유지합니다. 앱 전체 유휴 전력·실기기 처리량·NativeAOT 근거로 확대하지 않습니다. 근거 artifacts/popover-enter-2026-11-13/verification.json.

### 2026-11-13 SearchBox 지우기와 포커스 수명
원인: 지우기 버튼의 캡처 중 편집기 탐색 등록을 건너뛰어 유지 프레임 끝에 포커스를 해제했습니다. 변경: 공통 편집기 탐색을 유지하며 보조 버튼 캡처만 보호하고, 수락된 지우기의 편집 이력을 보존합니다. Before: 유지 프레임 회귀 실패. After: SearchBox113개·GPU288개·실제 Windows120ms 누름/놓기·한글 재입력11개 통과. 전체 CPU65개 계약9957회도 통과했습니다. 처리 속도·전력 개선율은 미측정이며 성능 개선을 주장하지 않습니다. 기존 바인딩 거부·정규화·읽기 전용과 다른 입력기의 기본 동작은 유지합니다. 근거 artifacts/searchbox-clear-2026-11-13/verification.json.
