## Interaction and architecture

- Wheel zooms around the pointer; middle drag pans; Ctrl+middle vertical drag zooms; left drag moves an entity.
- Right click opens a context menu with selection and framing commands.
- Camera tour and entity animation default to On. The tour accelerates and brakes smoothly between 85% of fit zoom and at most 120%, with gentle horizontal and vertical movement while close. The selected entity accelerates and decelerates in the foreground depth layer.
- Tour cycles alternate between tracking the moving entity and visiting another pseudo-random entity. Selection is reproducible for benchmarking; measurement JSON records actual visits in `tourVisits`.
- Selecting an entity raises both its hit-test order and real Z depth. Its background and text share that layer.
- Local card clips and the board viewport constrain long text. The overview has an independent camera in the same renderer, without an offscreen composition image.
- The bottom-left overview shows the current viewport as a translucent area; the status panel displays FPS.
- Projected text is a vector mesh from DirectWrite outlines tessellated by Direct2D. Missing glyphs in the selected fonts fail explicitly. The default approximation tolerance is 0.001 source font pixels; screen-space approximation error scales with magnification. The demo uses 4x MSAA. This is not an infinitely scalable analytic glyph renderer.

Both modes use the same dynamic 3D layer API:

| UI label | Behavior |
| --- | --- |
| `Update: REBUILD ALL` | Regenerate and upload all geometry every frame |
| `Update: CHANGED ONLY` | Retain geometry with an unchanged `ContentVersion`; update matrices for camera changes and rebuild changed content |

The retained data is vector geometry, not a rasterized layer. Fully changing content uses the same API and still requires generation/upload of actual changes. A large speedup between these modes measures eliminated regeneration and transfers, not an intrinsic speedup from depth testing.

Changed-only mode still renders frames during animation. Offscreen 3D commands are rejected using their bounds and actual camera transform, while their GPU geometry remains resident for reuse without rebuilding or uploading when visible again. Visible shapes and text, the overview, relationship updates and frame submission still cost work.

Ordinary relationships retain their order in batches of 32 with endpoint-to-batch dependencies. The selected table's connectors exist only in a separate foreground layer. Moving selected table 1 in the default 1,200-table document rebuilds four foreground relationships and leaves background batches unchanged. Moving another table updates its dependent batches and any affected foreground connector. Selection changes invalidate the old and new selections' batches so no duplicate connectors remain. Camera-only movement rebuilds no relationships. Resizing and full-rebuild mode update every batch.

`Scene builds/frame` counts executed geometry bodies. `Frame upload` sums HUD, geometry, compiled index and layer state transfers. `Draw calls` includes the HUD; `Layer draws` counts combined 3D draws. HUD and matrix transfers can therefore remain with zero scene geometry upload. GPU timestamps lag by frame slots. Changed-only mode stops requesting frames when idle. Result JSON records the selected entity, relationship count, width and depths in `selection`.

Selected connectors use 5px strokes and a foreground depth immediately behind the selected table, keeping its text visible while passing in front of other tables. Changing selection restores the old connectors' ordinary width and depth. Table headers round only the upper two corners; both lower corners are square.
