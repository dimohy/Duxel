## 조작과 구조

- 휠: 커서 위치를 기준으로 확대·축소. 가운데 드래그: 화면 이동. Ctrl+가운데 세로 드래그: 확대·축소. 왼쪽 드래그: 엔티티 이동.
- 오른쪽 클릭은 선택·화면 맞춤 기능을 가진 컨텍스트 메뉴를 연다.
- 카메라 투어와 엔티티 애니메이션은 기본 On이다. 투어는 전체 맞춤 배율의 85%부터 최대 120%까지 가감속하며, 확대 상태에서도 상하좌우로 천천히 이동한다. 선택한 엔티티는 앞쪽 깊이에서 가속·감속하며 움직인다.
- 투어는 움직이는 엔티티 추적과 임의의 다른 엔티티 탐색을 한 주기씩 번갈아 수행한다. 탐색 대상은 재현 가능한 의사 난수로 고르며, 측정 JSON의 `tourVisits`에 실제 방문을 기록한다.
- 엔티티를 클릭하면 클릭 판정 순서와 실제 Z 깊이를 함께 앞쪽으로 올린다. 배경·텍스트가 같은 레이어의 깊이를 따른다.
- 선택된 엔티티의 연결선은 5px로 강조하고 다른 엔티티보다 앞, 선택된 엔티티 바로 뒤의 깊이에 표시한다. 선택을 바꾸면 이전 연결선은 일반 두께와 깊이로 돌아간다. 타이틀은 위쪽 두 모서리만 둥글고 아래쪽 두 모서리는 직각이다.
- 카드 내부의 로컬 clip과 보드 viewport를 함께 적용한다. 긴 필드 이름도 카드와 위젯 영역 밖으로 출력하지 않는다.
- 미니맵은 같은 렌더러의 독립 카메라·viewport를 사용한다. 별도 합성 이미지가 없다.
- 왼쪽 아래 미니맵에 현재 보이는 영역을 반투명으로 표시하고, 상태 패널에 FPS를 표시한다.
- 3D 텍스트는 DirectWrite 글리프 윤곽을 Direct2D로 삼각형 분할한 벡터 메시다. 선택한 폰트에 글자가 없으면 명시적으로 실패한다. 메시의 기본 곡선 근사 오차는 원본 폰트 픽셀 0.001이며 화면에서 확대되면 오차도 배율만큼 확대된다. MSAA 4를 사용한다. 무한 배율의 해석적 글리프 렌더링이라고 주장하지 않는다.

두 갱신 모드는 모두 동일한 동적 3D 레이어를 사용한다.

| 화면 표시 | 처리 |
| --- | --- |
| `Update: REBUILD ALL` | 매 프레임 모든 도형을 CPU에서 재생성하고 업로드 |
| `Update: CHANGED ONLY` | `ContentVersion`이 같은 벡터 데이터를 GPU에 유지. 카메라 변경은 행렬만 갱신. 실제 변경한 콘텐츠는 버전을 올려 갱신 |

재사용되는 것은 도형 데이터다. 레이어를 비트맵으로 굽는 방식이 아니다. 모든 내용이 바뀌는 경우에도 같은 레이어 API를 사용하지만 실제 변경 데이터의 생성·전송 비용은 발생한다. 두 모드의 큰 성능 차이는 불필요한 CPU 재생성과 업로드를 제거한 효과이며, 3D 깊이 검사 자체의 속도 향상률이 아니다.

`CHANGED ONLY`도 애니메이션 중에는 표시할 프레임을 그려야 한다. 화면 밖 3D 명령은 경계와 실제 카메라 행렬로 판정해 그리기 요청을 생략한다. GPU 도형 데이터는 유지하므로 다시 화면에 들어와도 재생성·재업로드하지 않는다. 화면에 보이는 도형·텍스트, 미니맵, 관계선 갱신과 프레임 제출 비용은 남는다.

일반 관계선은 순서를 유지한 32개 단위 레이어로 나누고 양쪽 테이블에서 묶음으로의 의존 관계를 구성한다. 선택된 테이블의 연결선은 별도 전경 레이어에만 둔다. 기본 1,200개 문서에서 선택된 1번 테이블이 움직이면 전경의 연결선 4개만 다시 생성하고 배경 관계선 묶음은 유지한다. 다른 엔티티를 움직이면 그 엔티티에 의존하는 묶음과 필요한 전경 선만 갱신한다. 선택 변경은 이전·새 선택의 묶음을 갱신해 중복 선을 남기지 않는다. 카메라만 움직일 때는 관계선도 재생성하지 않는다. 화면 크기 변경과 전체 재생성 모드는 모든 묶음을 갱신한다.

`Scene builds/frame`은 도형 생성 본문 실행 횟수다. `Frame upload`는 HUD, 지오메트리, 컴파일된 인덱스와 레이어 상태 전송을 합한 전체 프레임 값이다. `Draw calls`도 HUD를 포함하며 `Layer draws`는 결합된 3D 드로우 수다. 따라서 장면 지오메트리의 업로드가 없어도 HUD·행렬 전송이 남을 수 있다. GPU 시간은 이전 프레임 슬롯에서 회수한 값이다. `CHANGED ONLY` 모드에서 유휴 상태에는 추가 프레임을 요청하지 않는다. 결과 JSON의 `selection`은 선택한 엔티티·연결선 수·두께·깊이를 기록한다.

목표는 **1,000 FPS**다. 상태 패널은 `현재 FPS / 1000`을 표시하고 실행 JSON은 `fpsTarget: 1000`을 기록한다. 측정 요약의 `fpsTargets`와 `fps-target.md`는 시나리오별 독립 실행 평균 FPS의 중앙값·목표 대비 비율·반복 수·달성 여부를 기록한다. 순간 최고 FPS는 달성 근거로 사용하지 않는다. 3회 미만은 예비 결과이며, 3회 이상 모든 실행이 목표 이상인 경우에만 `MET_ACROSS_RUNS`다. 이는 FPS 조건의 통과이며 전체 기능·품질 검증 완료와는 별개다.

기본 ERD는 엔진의 `UiLayer3D.PlaneModel`로 카메라와 엔티티 위치·앞뒤 순서를 분리한다. 카메라 이동은 엔티티별 MVP를 다시 조립하거나 모델 버퍼를 갱신하지 않는다. 엔티티 이동은 보드·미니맵의 모델과 연결선만 변경하며 카메라와 도형 메시를 유지한다. `sharedCameraLayerDraws`는 결과 JSON의 실제 공통 카메라 드로우 수다. 아래 비교 명령의 `-CompareCompiledLayers`를 `-CompareSharedLayerCamera`로 바꾸고 새 출력 경로를 지정하면 같은 실행 파일에서 공통 카메라 경로와 전체 행렬 경로를 비교한다. 둘 다 지오메트리를 재사용하며 품질을 유지한다.

`dense`는 전체 문서를 화면에 맞추고, `explore`는 큰 문서의 일부를 확대한다. 측정은 카메라만 변경, 엔티티 편집, 유휴 상태를 각각 전체 갱신/변경 갱신으로 비교한다. 최초 프레임을 제외한 뒤 1초 이상 워밍업한다. 자동 측정 중에는 조작 버튼으로 조건이 바뀌지 않는다. 결과 JSON, raw frame CSV, 독립 stdout/stderr, SDK와 샘플 해시를 보존한다. 대형 문서에서 표본 수가 적으면 p95/p99/1% low의 통계적 한계를 함께 판단해야 한다.

현재 첫 120개 문서의 1회 Managed 실행에서는 전체 재생성 약 14 FPS와 변경 갱신 약 1,877 FPS가 관측됐다. 변경 갱신의 카메라 이동 중 장면 재생성은 0회였고, 유휴 상태의 워밍업 이후 프레임은 0회였다. 이는 초기 확인값이다. 최신 수정본의 반복 측정 및 1,200개 문서 검증을 완료한 수치로 확대하지 않는다.
