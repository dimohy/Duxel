# Tooltip 표면과 검증 범위

Last synced: 2026-11-11

`UiFluentTooltipPresentation`과 `UiFluentInvertedTooltipPresentation`은 실제 `UiTooltip<TBehavior, TPresentation>` 소유자에 Fluent 표면과 Type200 텍스트를 적용한다. 사용자 컨테이너 샘플은 컴파일된 오프셋 정책을 통해 기본 표현을 사용한다. `Arrange<TOffset>`이 이 확장점을 유지한다. 새 `Fluent.Tooltip` 팩터리나 카탈로그 항목은 없으며 전체 컨트롤은 미완료다.

테두리 상자의 최대 폭은240, 반경은4이며 투명1단위 테두리와 CSS 패딩4/11/6/11을 사용한다. 따라서 텍스트는 왼쪽12·위5단위에서 시작하며 아래7단위를 남긴다. 확정 폭에서 실제 줄바꿈을 재측정하고 본문/전체 콘텐츠 영역을 구분하며, 소유자의 스크롤 오프셋과 루트 클립을 그리기에 적용한다. 화살표를 사용하는 위치 계산에는 높이6·정사각형 변8.484가 필요하며 다른 명시 높이/변은 실패한다. 둥근 화살표는 정사각형과 테두리만큼 확장한 삼각 클립 가상 요소를 합친다. 향하는 축의 중심은 본문 경계 안쪽1단위에 놓인다. 위치 계산은 기존 충돌·오프셋·자동 크기 수명주기를 계속 사용한다.

기본 Light는 배경255·전경36, 기본 Dark는 배경41·전경255다. 반전 배경은 Light51·Dark61이며 전경은255다. 고정 [Fluent 스타일](https://github.com/microsoft/fluentui/blob/8830c10bfb2f4c1bdd540287b09713b9679cd1ad/packages/react-components/react-tooltip/library/src/components/Tooltip/useTooltipStyles.styles.ts)이 이 표면 규칙과 토큰을 제공한다. 본문/화살표를 합친 알파에 먼저 표준편차2·불투명도0.12/0.24인 검은 주변 그림자를 적용하고, 이어 표준편차8·세로 오프셋4·불투명도0.14/0.28인 검은 주 그림자를 적용한다. 주 그림자는 첫 결과 전체를 입력으로 받는다. [Filter Effects](https://www.w3.org/TR/filter-effects-1/#funcdef-filter-drop-shadow)는 세 번째 길이를 표준편차로 정의하고 필터 목록을 순서대로 적용한다.

구현은8x8 커버리지 표본과 표준편차4배에서 자르는 분리형 가우스 커널로 합성 RGBA 표면 하나를 래스터화한다. 물리 콘텐츠 배율과 원점의 소수 픽셀 위상을 캐시 키에 포함한다. 표시 중인 Tooltip마다 제한된 슬롯 하나가 같은 모양/정수 이동을 재사용하고, 모양 변경 때 교체하며, 소유자 해제·누락·폐기 때 텍스처를 해제한다. 같은 슬롯의 한 프레임에서 두 번째 다른 모양은 해당 프레임 텍스처를 파괴하기 전에 명시적으로 실패한다. 어느 축이든4096 초과 또는4,194,304픽셀 초과는 명시적으로 실패한다. 기존 이미지 경로로 업로드하는 CPU 래스터 구현이며 대체 렌더러나 셰이더를 추가하지 않았다. 최초 래스터 비용과 전체 앱 성능은 측정하지 않았다.

창 소유 색 텍스처 ID는 글꼴 마스크 경계보다 작은1,000,000,002~1,099,999,999를 예약한다. 아이콘은1,000,000,001을 사용한다. 앱은 이 예약 범위에 직접 이미지 ID를 배정하지 않아야 한다. 범위 소진은 명시적으로 실패한다. 처음 DirectText ID 할당기를 사용했을 때 색을 ClearType 커버리지로 해석해 Dark 표면이 밝아졌으며, 화면 검토로 이 오류를 발견했다. 수정 경로는 네 배경색과 배경을 어둡게 만드는 그림자를 독립 GPU 바이트로 검사한다.

근거는 `artifacts/tooltip-surface-2026-11-11`에 있다. 고정 .NET11 RC3 빌드는 경고/오류0개이며 CPU4,045·Tooltip GPU740개가 통과했다. 소비 샘플은15초·30회 상태 전환 후 정상 종료했다. CPU는 캐시 재사용/교체·색/알파·배율·줄바꿈 측정·상한·프레임 내 텍스처 안전성·실제 소유자 수명을 검사한다. GPU는 Light/Dark·MSAA1/4에서 실제 소유자 위치/텍스트/패딩을 명시 리터럴 장면과 비교하고, 독립 색 바이트와 그림자 방향을 검사한다. 리터럴 장면도 같은 표면 래스터화기를 공유하므로 **그 비교는 CSS 픽셀 일치의 근거가 아니다**. 고정 core1.6.8 실행이 옆쪽 정렬에서 본문이-0.242 이동함을 독립 확인한다. 기존 Tooltip 읽기 결과1,049개를 모두 보존한다.

격리한12개 사례의 브라우저 계산 CSS로 크기·색·필터 순서·가상 요소 상자/클립 규칙을 확인했다. 브라우저는 명목8.484 변을 레이아웃에서8.46875로 양자화한다. Ego 스크린샷은 data/file URL 모두 시간 초과였으며 Windows 앱 목록에는 캡처 가능한 Ego 창이 없었다. 네이티브 DOM 스크린샷 비교는 여전히 불가하다.

독립 브라우저 래스터는 확보했다. 고정 CSS의 본문/화살표/필터 규칙을 Chromium SVG `foreignObject`에 옮겨 Canvas로 래스터화하며, 내보내기 전에 본문/배경의 불투명 색과 검은 그림자를 확인한다. 기준은 텍스트 없는96x28 테두리 상자·명시 화살표 위치·기록한 공식 토큰 색을 사용하며 전체 React/DOM 위치 계산을 실행하지 않는다. RGBA 기준12개를 `Fixtures/TooltipSurface`에 그대로 복사했으며 검사는 브라우저 없이 소비한다. MSAA1/4의24비교가 미리 정한 RGB RMSE2.5 이하·16바이트 초과 차이 픽셀 비율0.5% 이하를 고정192x128 본문/그림자 영역에서 통과했다. 최대 관측 RMSE는2.0054, 큰 차이 픽셀 비율은0.0692%이며 화살표 경계의 단일 채널 최대 차이는119다. 이는 허용 범위 내 시각적 일치이며 **픽셀 동일성이나 foreignObject와 네이티브 DOM 화면의 동등성 증명은 아니다**. 네이티브 DOM/앤티앨리어싱 동등성·DPI/브라우저 배율 비교·전체 DOM 조상 해석·전체 포인터/스크롤바 동작·UIA 속성/창 종료 알림·현재 NativeAOT/런타임 이미지는 남아 있다. 이 기준을 전체 Fluent 준수로 확대하지 않는다.
