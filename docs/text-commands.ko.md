# 공통 텍스트 키보드 명령

한 줄·다중 행 입력의 Ctrl+Backspace/Delete와 누른 키 반복은 기존 Ctrl+Left/Right의 단어 경계를 사용합니다. 선택이 없으면 뒤로 삭제는 앞 공백을 건너 앞 단어 또는 문장부호 묶음을 지우고, 앞으로 삭제는 뒤 공백을 건너 다음 묶음을 지웁니다. 삭제 양끝은 온전한 .NET `StringInfo` 텍스트 요소로 확장합니다. 선택한 범위가 있으면 그 범위를 우선 삭제하며 Shift가 삭제 범위를 늘리지는 않습니다. 읽기 전용 변경 금지와 undo/redo는 유지합니다. 기존 BMP 문자·숫자·결합 기호 휴리스틱을 사용하며 언어별 UAX29 단어 구분과 전체 네이티브 동작 일치는 미완료입니다.

다중 행의 일반 Left/Right는 선택을 논리적 앞/뒤 끝으로 접습니다. 역방향·여러 행 선택과 누른 키 반복에도 같습니다. Shift는 활성 끝의 선택 확장을, Ctrl은 단어 이동을 유지합니다. 선택 접기는 이전 시각적 행·세로 이동 선호 위치를 해제하여 이후 이동이 접힌 커서에서 시작하도록 합니다. 기본·자동 줄바꿈·Fluent 비줄바꿈 공통 경로를 포함하며 시각적 bidi 이동을 입증하지는 않습니다.

고정 .NET 11 RC3에서 변경 전 44개 실패를 재현했습니다. 네 가지 입력 구성의 실제 키 이벤트 신규70개를 포함한 통합 편집 CPU301 통과입니다. 입력 커널은 GPU64비교를 추가한 304검사, 다중 행은 GPU128비교를 추가한 2,336검사 통과입니다. 새 비교는 명시한 표시 문자열과 별도로 측정한 커서 기하를 래스터/벡터·Light/Dark·MSAA1/4·획득 이미지 재사용 4회에서 확인합니다. 최종 이미지 유지·관련 회귀·샘플 근거는 `artifacts/text-commands-2026-11-11/verification.json`에 있습니다.

확대 수명 검사에서는 기존 Progress/Slider/Toggle 동일 값 대입의 콜드 할당 측정이 독립 실행 3회 모두 12,336바이트로 실패했습니다. 같은 독립 루프를 최소 0.25초 예열한 뒤 측정하면 독립 실행 3회 모두 0바이트·추가 프레임 요청 0회입니다. 엄격한 판정과 제품 setter는 유지합니다. 정상 상태 테스트 교정이며 전앱 성능 개선이나 기존 할당 스택 규명은 아닙니다. [할당 검증](allocation-validation.ko.md)을 참고합니다.

`fluent_input_elements_fba.cs`에 단어 삭제 키 안내를 추가했으며 명시적 이모지 글꼴 선택을 유지합니다. 실제 OS 키보드/IME·외부 Windows UIA·셰이핑/bidi 외형·현재 NativeAOT/런타임 이미지 비교·통합 성능은 미검증입니다. 기존 전체 목표의 완료 수와 리사이즈 보류를 유지합니다.
