# SVG 백엔드 의존성 교체 기록

- 목적: Skia를 제거하고 Windows에서는 외부 SVG 폰트·이미지 DLL 없이 DirectWrite·WIC를 사용하며 Linux에서는 HarfBuzz를 유지한다.
- 가설: SVG를 한 번 해석해 기하·채색·글자 윤곽선으로 보관하면 기존 자원·크기별 래스터·GPU 텍스처 재사용 계약을 유지하면서 플랫폼 의존성을 분리할 수 있다.
- 변경: 자체 경로·곡선·획·채색·CSS·기본 효과 처리, 명시적 폰트 보관과 배치, 시스템 메모리 비트맵 디코더를 연결했다. `SvgStore`의 제한형 LRU·버전·소유권은 유지했다.
- 검증: .NET11 관리형 SVG 계약114개, Vulkan GPU76개, Observer CPU288개/실제 창7개, Windows 플랫폼18개/Linux17개를 검사했다. 독립 네이티브 글자 윤곽선과의 전체 픽셀 허용 차이1을 유지했다. 세부 명령·원본·결과는 `artifacts/svg-managed-2026-11-14/verification.json`에 연결한다.
- 재사용 관측: 같은 크기100회 요청과 동시800회 요청의 기존 읽기·XML 해석·장면 컴파일·래스터 생성 횟수 검사가 통과했다. 확대 시 폰트 선택·글자 지원 검사가 반복되지 않았다.
- Before/After: 종전 Skia 의존 경로를 Windows DirectWrite·WIC / Linux HarfBuzz 경로로 바꿨다. 벽시계 시간·메모리 최대치·평균 FPS·median/p95/p99·1% low의 동등 조건 비교는 미실행이다. 개선율은 미확인이며 속도 향상을 주장하지 않는다.
- 환경: SDK11.0.100 / runtime11.0.0 관리형 검증. 고정 RC3 NativeAOT 비교는 MSVC·Windows SDK 경로 제공 전 재시도하지 않는다. 독립 성능 실행·워밍업 조건은 아직 정하지 않았으며 기존 실행을 성능 비교로 승격하지 않는다.
- 리스크와 다음 검증: 자체 래스터의 최초 생성 비용·중간 레이어 메모리, 전체 SVG 사양과 대형 문서, 고정 NativeAOT·ARM64 검증이 남아 있다. 기존 힌팅 비트맵과 벡터 윤곽선의 안티앨리어싱 차이를 구분하며 필수 기하·GPU 검사를 완화하지 않는다.

## 브라우저 비교와 공통 이미지 보간 교정

- 가설: straight RGBA 텍스처를 그대로 보간하면 완전히 투명한 픽셀의 RGB가 확대된 가장자리에 섞인다. 색상 이미지를 업로드할 때 premultiplied RGBA로 바꾸고 보간 후 복원하면 기존 공통 블렌드 경로를 유지하며 이 결함을 없앨 수 있다.
- 변경: Core의 `UiRgba8`를 SVG와 Vulkan이 공유한다. 입력 버퍼는 유지하고 기존 스테이징 할당에 변환한다. 색상 이미지 메타데이터가 다른 업데이트는 같은 배치로 합치지 않는다. 폰트 마스크의 경로와 기존 블렌드 설정은 유지한다.
- 전후 검증: 불투명 빨강/투명 파랑 2픽셀 이미지를 흰 배경 위로 확대하는 검사는 수정 전 실제 GPU에서 실패했다. 수정 후 MSAA1/4 두 조건에서 모든 빨강 채널255·초록과 파랑 동일을 확인했다. 전체 SVG GPU86개와 Observer 실제 창11개가 통과했다. 프로덕션 fragment SPV4개는 원본 보관 후 후보 컴파일·SPIR-V 검증·실제 GPU 확인을 거쳐 반영했다.
- 측정: 동일 256개 이미지 draw, 단일 업로드 후96회 워밍업, 256개 측정 프레임, V-Sync OFF·MSAA1에서 Before4/After4/Before5/After5/Before6/After6 순으로 실행했다. 원시 `frames.csv`와 GPU timestamp·업로드량·픽셀 지문은 `L:/Cache/Duxel/linux-accessibility-2026-11-14/result-image-alpha-bench-{before,after}{4,5,6}`에 보존했다. 앞선1~3회 탐색 기록도 보존한다.
- 결과: CPU/GPU 시간의 개선 방향이 실행마다 바뀌었다. 관측 변동을 속도 향상으로 해석할 수 없어 개선율은 미확정이다. 이 검사는 보간 결함 교정과 셰이더 회귀 진단이며 앱 FPS나 고정 RC3 NativeAOT 성능 증거가 아니다. 기존 요약의 짝수 표본 중앙값은 상위 중앙 원소이므로 엄밀한 중앙값으로 인용하지 않는다.
- SVG 모듈: 획·점선 계획, paint template, coverage, RGBA8 합성, device-pixel dither, premultiplied sampling, viewport, 단일 Gaussian filter를 분리했다. XML 재해석 없는 기존 장면/래스터 재사용 검사를 유지한다. 실제 복잡한 원본2개는 직접 SVG와 이미지/Canvas 경로의 엄격 비교에서 아직0/2다. 평균 오차는 진단용이며 통과 기준을 완화하지 않는다.
- 리스크: 곡선 가장자리·패턴 해상도/위상·필터 근사의 브라우저 차이, 최초 래스터 비용과 중간 레이어 메모리가 남아 있다. 벤더별 별도 GPU 측정, ARM64와 고정 NativeAOT는 미검증이다. Linux 전체 실행은 AT-SPI 자식 종료134로 실패했으며 과거 통과 기록으로 대체하지 않는다.

## 경로 coverage와 visibility 교정

- 탐지: 복잡한 원본에서 흰 강조선 두 개를 분리해 비교하자 면적 기반 coverage와 GPU 브라우저의4샘플 coverage가 달랐다. 원래 입력을 숨겨 분리하는 과정에서는 `visibility`가 무시되는 별도 결함도 재현됐다.
- 선택·변경: 일반 경로에 표준4샘플·8비트 소수 정점 격자를 적용하고, `SvgCubicTessellation`에 Wang 식의2의 거듭제곱 균일 분할을 분리했다. 획 길이·점선 배치의 적응형 분할과 기본 도형의 부드러운 면적 경로는 유지했다. visibility는 보관 스타일과 노드에서 처리하고, 글자 span 상속·배치 간격·그룹 경계 기하도 유지한다. Skia 의존성은 추가하지 않았다.
- 독립 검증: Chromium156·ANGLE/D3D11에서 수집한 자체 입력6개의 전체 RGBA를 고정 해시로 검사했다. 삼각형·오목 다각형·곡선·사각형·숨김 상속·숨김 클립이 일치한다. 복잡한 원본에서 분리한 경로 두 개에는 각각 알파 픽셀1개 차이가 남는다. 타원도 여전히 불일치하므로 이6개를 전체 coverage 적합성으로 해석하지 않는다.
- 같은 원본·같은 브라우저 기준의 진단 비교: 이미지 경로의 불일치 픽셀 수는 Red66387→53416, Yellow64291→56295였다. 근거는 CACHE의 result-svg-browser-final-exit-contract와 result-svg-browser-grid-final이다. 허용 오차는 바꾸지 않았으며 전체 원본 통과는 계속0/2다. 평균 오차와 픽셀 수는 원인 분석용이다.
- 회귀: 관리형101개, 제품 SVG125개, GPU86개, Observer CPU290개/실제 창11개, Windows 플랫폼21개/Linux20개가 통과했다. Observer를 다시 빌드했으며 일반 사용자 창을 자동 실행하지 않는다. Linux 전체 접근성 실패134는 미해결로 유지하며 반복 실행하지 않았다.
- 성능: 이번 단계의 동등 조건 시간·할당·메모리 비교는 미실행이다. 경로 분할과 샘플 수가 바뀐 사실만으로 속도·FPS 개선을 주장하지 않는다. 다음 정확성 검증은 남은1픽셀, 기본 도형의 analytic AA와 그라데이션·합성 정밀도를 대상으로 한다.

## 샘플 색과 레이어 합성 교정

- 재현: 인접한 불투명 삼각형과 같은 삼각형의 중복 그리기가 모두 알파191로 나왔다. 브라우저는 각각255와127이었다. coverage를 먼저 평균해 합성하면서 샘플 위치가 사라지는 것이 원인이었다.
- 변경: `SvgCoverageRasterizer`가4비트 샘플 마스크를 전달하고, `SvgSamplePixel`·`SvgRasterSurface.Samples`가 서로 다른 샘플 색만 별도로 보관한다. 기존 배열은 현재 합쳐진 RGBA8 색을 제공한다. 그룹 불투명도와 기하 클립은 샘플을 유지하고, 이미지 마스크와 공간 필터는 합쳐진 색을 입력으로 사용한다. alpha/luminance 마스크도 구분한다. 픽셀당4개의 전체 Vector4 배열을 무조건 추가하는 설계는 사용하지 않았다.
- 독립 증거: 브라우저에서 그룹·클립·마스크·stdDeviation0 필터를 포함한 입력8개를 수집해 원본과 전체 RGBA 해시를 고정했다. 기존 실패2개는 전체 RGBA가 일치한다. 이전 기본 예제6개를 포함해 Windows/Linux 관리형109개씩, 제품128개, GPU86개, Observer CPU290개/실제 창11개, Windows 플랫폼21개/Linux20개가 통과했다. 옵저버의 흰 마름모를 삼각형4개로 구성해 실제 샘플에서도 조각 경계를 확인한다.
- 전체 원본: 같은 브라우저 기준의 이미지 경로 평균 RGB 오차는 Red0.3705→0.2181, Yellow0.3314→0.1712로 변했다. 이는 진단 수치이며 전체 픽셀 일치 통과는 계속0/2다. 원본·기준·허용 오차는 바꾸지 않았다. 세부 결과는 result-svg-browser-grid-final과 result-svg-browser-samples-final에 남긴다.
- 한계: 이번 단계의 동등 조건 최초 생성 시간·할당·메모리 비교는 미실행이다. 속도 개선을 주장하지 않는다. 큰 도형의 샘플 상태 분포, 색 정밀도·기본 도형·패턴·blur의 남은 차이와 원래 NativeAOT/실기기 검증은 계속 필요하다. Linux 전체 접근성 실패134를 이번 headless SVG 검사로 대체하지 않는다.

## 디더링과 paint server 불투명도 교정

- 탐지·변경: 독립적인 선형·방사형 그라데이션과 불투명도 입력을 비교했다. `SvgOrderedDither`의 XOR 순서를 Morton 순서로 교정하고, 정규화된 8비트 디더링 값을 사용한다. `SvgCompositing.PaintServerOpacity`가 패턴과 그라데이션의 불투명도를 반올림된 RGBA8 값으로 준비한다. 단색·그룹 불투명도와 구분해 소비 경로를 유지했다. 외부 렌더러 의존성은 추가하지 않았다.
- 독립 검증: 패턴 fill-opacity0.1/0.5/0.9의 전체 RGBA가 브라우저와 일치하며 고정 해시 예제로 추가했다. 별도로 수집한 9개 입력 중 단색0.9와 그라데이션3개는 여전히 불일치한다. 64×16 그라데이션6개에도 각각46/104/86/96/99/136픽셀, 최대1바이트 차이가 남는다. 통과한 부분 예제로 실패한 범위를 대체하지 않는다. 반정밀도와 단순 보간 산술 가설도 원시 결과와 함께 보존했다.
- 전체 원본: 직접 SVG·이미지 경로4개 모두 엄격 비교에 실패해 문서 통과는0/2다. 이미지 경로 평균 오차는 직전 Red0.2181185→0.2118085, Yellow0.1712023→0.1375651이다. 원본·브라우저 기준·허용 오차는 바꾸지 않았다. 브라우저의 투명 SVG→흰색 합성과 먼저 비트맵으로 만든 뒤 흰색으로 합성한 진단3개가 같아 기존 이미지 비교 경로를 유지했다.
- 회귀: Windows/Linux headless 관리형112개씩, 제품 SVG128개, 실제 GPU86개(MSAA1/4), Observer CPU290개·실제 창11개가 통과했다. 원래 Observer의 관리형 실행 파일을 경고·오류 없이 다시 빌드했다. 일반 사용자 창은 실행하지 않았다. Linux 전체 접근성 종료134와 최초 창 파괴 원인은 미해결이다. 사용자는 창을 닫지 않았다고 확인했다.
- 측정·리스크: 동일 조건 시간·할당·메모리 비교는 미실행이므로 속도 개선율은 미확정이다. 현재 수치는 정확성 진단이다. 색 저장 정밀도·기본 도형·패턴·필터의 나머지 차이, 실제 Linux 앱·화면 읽기·ARM64·고정 RC3 NativeAOT 검증이 남아 있다. 근거는 `artifacts/svg-paint-precision-2026-11-14/verification.json`에 보존한다.

- 관찰 : 오른쪽 상단의 전역 갱신 영역 강조가 실제 Vulkan 보수 사각형을 표시한다. 자신의 테두리는 내용 지문에 들어가지 않으며, 이미지/MSAA 이력의 제거 비용을 분리한다. 진단 만료만으로 깨어난 프레임은 강조를 연장하지 않는다.
