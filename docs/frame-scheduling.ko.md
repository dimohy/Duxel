검증 정책 변경(2026-11-06): 이후 개발·기능·회귀·성능 검증은 .NET11만 사용합니다. .NET9·.NET10은 최종 완료 시 배포용 컴파일만 확인합니다. 아래의 기존 .NET10 결과는 보존 근거이며 반복 요구가 아닙니다. 고정 RC3 NativeAOT 성능 기준은 유지합니다.

`UiImmediateContext.RequestFrameAt(double)`과 `UiControlContext.RequestFrameAt(double)`은 `GetTime()` / `TimeSeconds`가 반환하는 UI 시계의 절대 시각을 예약합니다. 렌더링 중 호출하며 타이머·콜백·백그라운드 작업을 만들지 않습니다. 유한하지 않거나 음수인 시각은 거부하며 여러 요청 중 가장 이른 시각을 사용합니다.

예약 선언의 수명은 현재 프레임입니다. 다음 프레임에서 다시 선언하지 않으면 사라지고 위젯 제거 후에는 새 예약을 남기지 않습니다. 컨텍스트 해제 시에도 예약을 지웁니다. 외부 프레임 요청·입력·크기 변경·종료는 기존 이벤트 대기를 깨웁니다. 예약 시각에 도달하면 프레임을 생성하며 활성 텍스트 입력의 커서 깜빡임도 독립적으로 유지합니다.

예를 들어 `ui.RequestFrameAt(ui.GetTime() + 0.25)`는 대기를 허용하면서 나중의 갱신을 요청합니다. 렌더링한 상태에 여전히 필요할 때만 다시 선언합니다. 현재 UI 시각과 같거나 이전인 시각은 즉시 처리합니다.

Fluent Spinner는 표시 지연 중 이 공통 경로를 사용합니다. 표시된 뒤의 모션은 연속 애니메이션을 요청합니다. 생성된 위젯과 직접 호출·사용자 구현이 같은 엔진을 사용합니다.

정적·버전 지정 캐시 레이어는 가장 이른 예약을 보관하고 재생할 때 다시 선언합니다. 시각이 된 레이어는 다시 구성하며 연속 애니메이션 레이어는 자식 요청이 끝날 때까지 다시 구성합니다. 관계없는 정적 레이어는 계속 재사용합니다. 이 예약 의존성만으로 수동 캐시 그리기 본문의 입력·접근성 의미 정보까지 보존하는 것은 아닙니다. 화면 밖 애니메이션 생략도 별도 미완료 항목입니다.
