Code and table-header backgrounds use Canvas; table borders and thematic rules use the foreground role. Native paragraphs, segmented runs and table cells use the same resolver. Accessible source paint uses that resolver too, and its cache key includes the forced palette and enabled state, so changing LinkText alone updates both pixels and metadata without reparsing. The shared frame/text paths, option rows and selection paint are covered by the separate checkpoints above. Ordinary input layout and editing behavior are retained; the styled background-order correction is described separately above.

`IPlatformThemeProvider.ForcedColors` optionally publishes a `UiForcedColorPalette`. Null means inactive or not supplied by that provider. `UiTheme.ForcedColors` preserves that state separately from the light/dark scheme. The palette contains Canvas/CanvasText, GrayText, Highlight/HighlightText, LinkText and ButtonFace/ButtonText. `Apply(theme)` maps shared color roles while retaining the design's layout and typography.

`DuxelAppOptions.RespectSystemForcedColors` defaults to true, including explicitly supplied designs. Set it to false only when the application intentionally manages these accessibility colors itself. Deactivation restores the original authored design. The session observes palette changes independently of light/dark changes, and retained layers and Avatar paint groups include palette identity in invalidation.

Windows reads SPI_GETHIGHCONTRAST and system colors at startup and relevant WM_SETTINGCHANGE/WM_SYSCOLORCHANGE/WM_THEMECHANGED notifications. It never changes system settings. Integrated chrome follows the same palette and opt-out. The flag-only native query follows [Windows Forms' implementation](https://github.com/dotnet/winforms/blob/main/src/System.Windows.Forms/System/Windows/Forms/SystemInformation.cs); the returned scheme pointer is not freed by this getter. [Windows guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/high-contrast-parameter).

This is the shared platform/theme foundation, not full Fluent forced-color conformance. Component-specific hardcoded palettes, RatingDisplay's original-path stroke, Linux desktop palette detection and real OS contrast-mode transitions still require qualification. The existing Linux provider returns no palette. No system-wide contrast setting was toggled during validation. Tests cover eight contracts including actual Win32 reads and changed GPU pixels under a stable dark scheme. Observer retains its explicit dark base design while accepting system contrast colors when active.

Badge and CounterBadge now consume the active Canvas/CanvasText roles for their background, text, icons and border. The authored background alpha is preserved, so Ghost and Outline remain transparent, while their one-pixel system-colored border stays visible. This follows the [CSS forced-color adjustment model](https://www.w3.org/TR/css-color-adjust-1/#forced-colors-properties) and the pinned Fluent Badge transparent-border intent. Six real-GPU contracts cover four appearances across eight semantic colors, equal output over both base schemes and a Ghost CounterBadge; the existing eight foundation contracts remain separate. OS-mode transitions and other component palettes remain unverified.
