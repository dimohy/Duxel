# Shared accessible text state

`UiAccessibilityNode.TextInfo` describes committed text, its caret and selection. Standard single-line, multiline, SearchBox, Combobox editor and SpinButton kernels publish the state actually used by editing. Numeric SpinButton ranges remain independent of draft text. Reconciled clear/option/stepper actions update text and metadata in the same frame. IME preedit is not added to committed text.

Custom behaviors/presentations can read `UiInputEditResult.AccessibilityText` and `UiMultilineEditResult.AccessibilityText`. These payloads are optional and are not constructed when no accessibility tree is attached. The standard kernels mark `CanSetSelection`; independently constructed text states default to read-only observation capability.

`UiAccessibilityTextContent` is immutable. `CharacterCount`, `GetText`, `GetUnicodeScalar` and character offsets use Unicode scalars, not UTF-16 units or graphemes. `GetUtf16Offset` and `GetCharacterOffset` convert exact insertion boundaries and reject split surrogate pairs. Invalid UTF-16 and unordered ranges fail explicitly. For example, `가😀` contains2 scalars and3 UTF-16 units; a combining sequence may contain several scalars in one editor grapheme.

`UiAccessibilityTextInfo.CaretUtf16` and `AnchorUtf16` preserve direction. Character-offset projections are available separately. Old snapshots remain readable after later edits or tree disposal. Unchanged frames reuse the state object; caret-only changes reuse its content/map. BMP text needs no offset array. The cache uses the existing published entry; no global dictionary or editor cache fields were added. This is a cache/lifetime contract, not a measured throughput claim.

During rendering, call `ui.GetAccessibilityTextInfo(id)` after the input in the same ID scope. It reads only this frame's staged state and returns null when absent, unrendered or unattached to accessibility. It never substitutes an earlier frame. The Linux sample's bottom line displays current scalar count, caret and selection without scheduling updates.

For cross-thread actions, use the published tree snapshot and its runtime ID:

```csharp
var element = tree.CaptureSnapshot().Elements.Single(e => e.Node.Id == id);
var current = element.Node.TextInfo ?? throw new InvalidOperationException();
var end = current.Content.GetUtf16Offset(2);
var desired = new UiAccessibilityTextInfo(current.Content, end, 0);
var admission = tree.RequestTextSelection(id, element.RuntimeId, desired, wait: false);
```

`wait: false` reports admission, not completion. The default synchronous form must run off the render thread and returns the editor result. Requests require `CanSetSelection` and the exact published content object. Old or independently reconstructed content is rejected. The render kernel rechecks text and availability before applying positions, so model changes or disabling after admission cannot apply stale offsets. Readonly selection is allowed; text and keyboard focus are preserved. Requests inside an editor grapheme or unavailable styled boundary return InvalidArgument instead of silently moving elsewhere.

Current managed .NET11 control189 checks cover offsets, malformed text, immutable snapshots, reuse, real caret/selection changes, stale/disabled requests, readonly/multiline behavior, scoped queries and clear/option/stepper reconciliation. Linux driver 59 checks combine 38 application/session checks with 21 boundary-module checks; independent native clients pass101 per runner against the actual product renderer. Evidence: `artifacts/linux-accessibility-2026-11-14/text-boundaries-verification.json`.

## Linux native Text

The bridge exports a partial eighth interface, [AT-SPI Text](https://github.com/GNOME/at-spi2-core/blob/main/xml/Text.xml), only for nodes publishing TextInfo. It supports CharacterCount/CaretOffset, GetText, GetCharacterAtOffset, GetNSelections/GetSelection and SetCaretOffset/AddSelection/SetSelection/RemoveSelection. Native positions use Unicode scalars; GetText accepts an exclusive end and -1 for the document end. Invalid queries return a protocol error; invalid changes return false. There is one contiguous selection: AddSelection refuses a second selection, SetSelection modifies the existing selection, and RemoveSelection collapses at its caret. Reversed anchor/caret remain directional internally while queries return ordered bounds. SelectableText is separate from child Selection.

Changes use the existing guarded render-thread request. TextCaretMoved and TextSelectionChanged follow published positions. TextChanged emits removed content before inserted content with scalar start/length and exact UTF8 payload. Unchanged snapshots emit no text events; a replacement retains the common scalar prefix/suffix. The independent libatspi client verifies actual Korean/emoji queries, selection direction/refusals, focus preservation, caret/selection events and actual Backspace/undo deletion/insertion payloads without clearing its cache.

## Published painting geometry

`UiAccessibilityNode.TextLayout` optionally publishes an immutable `UiAccessibilityTextLayout` tied to the exact TextInfo.Content instance. GetCharacterExtents/GetRangeExtents use client coordinates, GetOffsetAtPoint checks the painting clip, and GetLineRangeAt returns scalar source bounds for actual visual lines. Character boxes are logical grapheme boxes, not glyph ink: combining scalars share one box, and a point inside it returns its first scalar. Empty ranges return a zero-width insertion rectangle. Range boxes enclose the covered rows. Scrolling translates boxes while retaining Content; unchanged text, measurement environment, origin, clip and visual-line version reuse the same layout. Older layouts survive reflow and tree disposal.

Single-line layout follows the exact editing bounds, content origin, line height, scroll and prefix advances used by the editor. Plain wrapped multiline layout reuses its real visual-line map, including soft wraps and hard newline source intervals. SearchBox clearing, accepted Combobox options and SpinButton steps capture the final reconciled text. A late numeric focus commit removes geometry painted for an older draft. Clicking actual single/multiline text establishes the same accessible keyboard focus; the native test clicks the reported character box through X11 and verifies the resulting editor caret.

AT-SPI adds GetCharacterExtents/GetRangeExtents/GetOffsetAtPoint in screen/window/parent coordinates and GetStringAtOffset for character/actual-line granularity. Pixel conversion keeps zero-width insertion boxes at zero rather than expanding a fractional x coordinate to one pixel. Off-clip point queries return -1; invalid ranges return protocol errors. Geometry is not published for active IME preedit, styled/Markdown multiline maps or the unwrapped legacy multiline path yet; geometry queries return NotSupported, without fabricated coordinates. Attributes, bounded ranges/scroll, complete styled editing, protected text and physical IME/screen-reader qualification remain open. Cold single-line geometry uses the editor's existing prefix measurements; large-document build cost has not been performance-qualified. This is partial native text integration and does not complete the original platform or full goal.

## Guarded range editing and Linux EditableText

`UiAccessibilityTextInfo.CanEditText` advertises the common range-edit kernel independently of ReadOnly. The original four-argument selection-state constructor remains available; the explicit five-argument overload also accepts this capability. Standard single-line and plain multiline editors publish it. Styled/Markdown multiline does not yet advertise range editing. `UiAccessibilityTextEdit` contains the exact published Content, a Replace/Copy/Cut/Paste kind, ordered UTF16 source boundaries and replacement text only for Replace. Paste takes an insertion range. Insert and delete are Replace with equal bounds or an empty replacement.

Off the render thread, use the current snapshot/runtime ID and request an edit:

```csharp
var element = tree.CaptureSnapshot().Elements.Single(e => e.Node.Id == id);
var content = element.Node.TextInfo!.Content;
var edit = new UiAccessibilityTextEdit(content, UiAccessibilityTextEditKind.Replace, 0, 0, "정");
var result = tree.RequestTextEdit(id, element.RuntimeId, edit);
```

The render kernel rechecks current text, enabled/visible state, permission and grapheme boundaries before clipboard access or mutation. Old/independent Content, invalid controls/UTF16, forbidden boundaries and overlong results fail explicitly. Payloads are not truncated. Multiline CR/CRLF uses the existing canonical LF contract; tab and single-line newline controls are rejected. The existing buffer/history produces one undo step and a collapsed insertion-end caret without stealing focus. Successful mutations are checked against the final published text before synchronous completion; a later binding rejection returns Failed. `wait: false` still reports admission only.

Readonly Copy preserves selection/caret/text; other readonly edits fail before clipboard reads. Operations use the application's configured IUiClipboard, not a separate native clipboard. Known clipboard IO failures/timeouts return Failed/Timeout without deleting cut text or inserting partial data. Cancellation is checked before effects and after clipboard calls. An already executing synchronous clipboard call cannot be cancelled or rolled back; there is no transaction across clipboard, editor and external binding.

The ninth partial AT-SPI interface, [EditableText](https://github.com/GNOME/at-spi2-core/blob/main/xml/EditableText.xml), implements all six defined content methods: SetTextContents, InsertText, DeleteText, CopyText, CutText and PasteText. Positions/ranges use scalars; InsertText length uses UTF8 bytes. A complete prefix is inserted, a length larger than the payload uses the whole payload, and negative lengths or a byte count splitting a scalar return false. CopyText has no boolean wire reply, so refusal is a D-Bus failure. Capability does not override ReadOnly/disabled permissions.

Common tests cover stale/admission races, readonly copy, full-length refusal, grapheme boundaries, malformed clipboard text, IO/timeouts, canonical newlines, binding refusal and actual Ctrl+Z/Y. Independent libatspi tests exercise all six methods in the real app, exact UTF8 prefixes, forbidden controls, limits, history and focus. Tests share only a named private clipboard selection. This does not qualify full styled/preedit editing, physical screen readers/IME or all remaining Text APIs.

## Unicode word, sentence and paragraph queries

GetStringAtOffset now supports all five granularities: scalar character, word, sentence, actual painted line and paragraph. Word/sentence ranges start at or before the requested scalar offset and end at the next start, retaining intervening punctuation/spaces. A nonprinting separator or emoji between lexical words belongs to the preceding word-start interval. At document end, word/sentence queries return the preceding interval; character queries retain the existing empty end range. Paragraph delimiters include CRLF and Unicode paragraph separators, while U+2028 remains a line separator. A trailing delimiter preserves the final empty paragraph; empty text returns empty ranges for all units.

Native AT-SPI startup now requires the Pango 1.0 ABI library libpango-1.0.so.0; qualification used 1.52.1. The library's Unicode/language segmentation and paragraph scanner supply the boundaries. Each complete paragraph is processed with its context, UTF8 byte results are checked at complete scalar boundaries, and the retained table stores scalar offsets. The current UI culture is the language tag; invariant culture uses the explicit undetermined tag `und`. No English-language or punctuation-only substitute is used.

Each live native text node retains one immutable table for its published Content/language. Caret-only refreshes carry that table forward. Changing content releases the node's old table, and changing language rebuilds it on query. Queries do not request UI frames. There is no global dictionary keyed by every text ever seen. Internal identity tests verify reuse and invalidation, and independent native queries check stable results across a caret refresh and actual content replacement; no measured speedup is claimed.

The Linux driver now has 59 checks: 38 application/session checks plus 21 boundary-module contracts. Native clients pass 101 checks each. Boundary contracts include Korean/English, combining marks, emoji/ZWJ, Hebrew/Arabic, punctuation-only text, CRLF/U+2029, empty/trailing paragraphs and invalid offsets. Multiple-paragraph source segmentation is tested directly against the native module; real RPC checks exercise a single-line editor. Shared Windows control189 results are reused only when Core/control source hashes remain unchanged. This does not qualify deprecated before/at/after boundary APIs, text attributes, styled/preedit geometry/editing, bounded-range scrolling or physical screen readers.

The missing-Pango startup contract is also checked in an owned child with only that native import deliberately blocked. Eight attempts leave no owner thread and no per-attempt descriptor increase after preparation. No installed library is removed, renamed or replaced, and no alternative implementation is used. The original unreachable-bus failure contract remains separate.
