# 유지되는 이미지 위젯

[English](image-widgets.md)

`Fluent.Image`는 한 번 디코딩한 픽셀을 일반 위젯 레이아웃에서 표시합니다. PNG와 SVG에 같은 이미지 소스 API를 사용합니다. 이 경로의 SVG는 비트맵 스냅샷입니다. 벡터 장면 유지와 해상도에 맞춘 확대·회전에는 `UiSvg`를 사용하세요.

```csharp
using Duxel.Core;
using Duxel.Platform.Windows;
using Duxel.Svg;

using var store = new SvgStore();
var decoder = new SvgImageDecoder(store, WindowsUiImageDecoder.Shared);
var source = new UiImageSource(decoder.Decode("artwork.svg")); // PNG uses the same path.
using var image = Fluent.Image(source);
image.Size = new(160, 100);
// In the existing render callback:
image.Render(ui);
```

이미지 소스는 RGBA 픽셀을 한 번 복사하고 변경 가능한 저장 공간을 노출하지 않습니다. 디코딩이 끝난 소스는 디코더·store보다 오래 유지할 수 있습니다. 같은 소스 객체를 공유하면 같은 컨텍스트에서 텍스처도 공유합니다. 플랫폼 디코더가 이미 `UiImageTexture.ImageDecoder`에 등록됐다면 `UiImageSource.LoadFromFile(path)`로 기존 형식 검증과 명시적 등록을 사용할 수 있습니다. 파일 로딩·디코딩은 렌더링 전에 수행하세요. 그리는 동안 파일 감시·디코더 자동 설치·실패 대체를 실행하지 않습니다.

`Size = default`는 원본 픽셀 크기를 논리 레이아웃 크기로 사용합니다. 양수·유한 크기로 뷰포트를 지정하며 부모 제약이 실제 할당 크기를 바꿀 수 있습니다. 전체 이미지는 뷰포트에 맞춰 늘어납니다. `Tint`는 straight-alpha RGBA에 곱해집니다. 뷰포트·부모 할당·위치·색을 바꿔도 원본을 다시 디코딩하거나 업로드하지 않습니다. 새 픽셀을 표시하려면 `Source`를 명시적으로 교체하세요. 같은 소스·크기·색을 다시 대입하면 프레임을 요청하지 않습니다. 장식용 위젯이므로 포인터 동작·포커스 정지·호버 애니메이션·접근성 이미지 역할은 제공하지 않습니다. 전체 Fluent 이미지 스타일·접근성 검증은 남아 있습니다.

각 렌더링 컨텍스트가 원본 해상도로 업로드하고 GPU 식별자를 소유합니다. 위젯의 임대 참조가 살아 있는 의존성을 보호합니다. SVG와 비트맵은 같은 캐시 구현을 사용하되 통계를 분리합니다. 각 캐시의 한도는 128개·RGBA 64MiB이며 합산 설정 용량은 128MiB입니다. CPU 소스 저장 공간·렌더러 부가 비용·처리 중인 자원은 별도입니다. 완전히 잘린 이미지는 업로드하지 않습니다. 모든 항목이 사용 중이면 용량 오류를 명시적으로 냅니다. 위젯 해제는 임대 참조와 소스 참조를 놓고, 미사용 캐시는 용량 압박 때 퇴거합니다. 렌더러 종료가 네이티브 자원을 해제합니다. 위젯은 한 컨텍스트가 종료된 뒤 다른 컨텍스트에서 다시 표시할 수 있습니다. 이미 제출할 프레임의 픽셀 메모리는 바뀌지 않습니다.

`ui.ImageTextureStatistics`는 비트맵의 업로드 요청 수·바이트와 캐시 보유량을 표시합니다. `ui.SvgTextureStatistics`는 SVG 작업만 계속 집계합니다. GPU 완료나 전체 프로세스 메모리를 뜻하지 않습니다.

위젯을 해제해도 명시적으로 유지한 정적 레이어의 화면은 자동으로 지워지지 않습니다. 내용을 없앨 때는 레이어를 무효화해 다시 구성하거나 제거하세요. 위젯 임대 참조가 해제돼도 유지 레이어가 참조하는 텍스처는 보호되며, 레이어 제거 후 캐시에서 퇴거할 수 있습니다. 대기 중인 CPU 프레임은 순서대로 제출하고 소비가 끝난 뒤 각각 해제하세요. `raster-lifetime` GPU 검사는 원본·128개 캐시 채우기·보호된 재생·레이어 제거/퇴거의 CPU 프레임 네 개를 모두 만든 뒤 제출합니다. Image와 SVG 모두 이전 프레임의 기하·명령·픽셀이 바뀌지 않습니다. 프레임 자원 2개·3개를 검사하지만 GPU 읽기 완료를 기다리므로 GPU 동시 처리나 메모리 증가 벤치마크는 아닙니다.

저장소 루트에서 `./run-gallery.ps1` 실행 후 **SVG** 탭으로 이동하세요. 왼쪽 비트맵은 이제 `Fluent.Image`, 오른쪽은 `UiSvg`를 사용하며 각각의 업로드 지표를 표시합니다. 변환 조절과 탭 왕복으로 재사용을 관찰하고, 바뀐 파일을 명시적으로 다시 읽어 스냅샷을 교체할 수 있습니다. 반복 가능한 관리 빌드·검사는 [위젯 계약 검증](widget-contract-validation.ko.md)을 참고하세요. 현재 근거는 `artifacts/image-widget-2026-11-12/`에 있습니다.

## 둥근 뷰포트와 이미지 맞춤

`image.CornerRadius = 24`로 할당 영역을 분석적 둥근 사각형으로 자릅니다. 반경은 짧은 변의 절반까지만 적용합니다. `image.Fit`은 기본값 `UiImageFit.Stretch`(늘이기), `Contain`(가운데 전체 맞춤·투명 여백), `Cover`(가운데 채우기·원본 일부 자르기)를 지원합니다. 원본 텍스처는 원래 해상도를 유지합니다. 반경·맞춤 변경은 디코딩·CPU 리샘플링·원본 재업로드를 유발하지 않습니다. 반경0·Stretch는 기존 삼각형 경로를 유지합니다.

`UiSvg.CornerRadius`도 같은 GPU 뷰포트 마스크를 사용합니다. 고정 영역 안에서 회전·이동에 맞춰 UV를 변환하며 기존 래스터를 재사용합니다. 확대는 화질을 위해 새 해상도를 그릴 수 있지만 XML은 컴파일된 캐시를 사용합니다. 원본 바깥 UV는 투명합니다. 저수준 `UiDrawListBuilder.AddImageRounded`는 `UiImageUvTransform`을 받으며 인스턴스마다 기존32바이트 레코드 두 개를 사용합니다. 정점 ABI나 기기 기능을 추가하지 않습니다.

Implementation Observer의 **SVG** 탭에서 모서리 슬라이더를1px씩 조절할 수 있습니다. 방향키도1px씩 이동합니다. **이미지 늘이기 / 이미지 전체 맞춤 / 이미지 채우기**로 일반 이미지 맞춤을 선택하고, 초기화로 반경0·늘이기로 돌아갑니다. 지표는 주기 프레임을 요청하지 않습니다. 저장소 루트에서 `./run-gallery.ps1`로 실행하세요.

검증 근거는 `artifacts/rounded-image-2026-11-12/`입니다. MSAA1/4, UV 회전, 소수 픽셀 AA, 실제 유지 레이어 컴파일 경로, 겹치는 앞뒤 깊이의 제출 순서 반전, 투명 코너 뒤의 도형과 재질 반투명을 검사합니다. 대기 프레임 수명은 자원2/3개로 검사하지만 읽기 완료를 기다리므로 GPU 동시 처리·장시간 증가 검사는 별도입니다. 셰이더 진단은 한 기기에서 기존 둥근 사각형 부하를 사용하며, 관리 실행을 세 번 교대 측정하고 매번64프레임 준비·256프레임을 측정합니다. 원래 고정 RC3 NativeAOT 성능 기준이나 양 벤더 실측을 대신하지 않습니다.

사용자 프레젠테이션은 UiControlContext.Image(image,bounds,tint,cornerRadius,fit)로 UiImage를 빌려 지정 영역에 그릴 수 있습니다. 별도 배치·입력 항목은 만들지 않고 텍스처 획득 전에 영역·반경·맞춤을 검증합니다. 이미지 수명을 유지하고 빌린 Avatar 내용을 변경·해제하지 마세요. 소유권·부모 할당은 fluent2-avatar.ko.md를 참고하세요.
