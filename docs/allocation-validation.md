# Managed allocation validation

The button same-value allocation test now warms and measures the same isolated loop for at least 0.25 seconds before its final measurement. The strict requirements remain unchanged: 10,000 identical label/size assignments allocate zero bytes and request no additional frames. `NoInlining` applies only to this test measurement boundary. Product setters and runtime configuration remain unchanged.

This follows the repository warmup policy. The old large test method mixed its cold execution and loop transitions with the allocation interval. Its qualified build failed two of three repeats with 12,336 bytes, while the baseline passed three. A matching standalone frame probe also reproduced 6,192 bytes in two of three cold runs. Per-operation probes changed the timing and reported zero; disassembly confirmed instrumented Tier0 and Tier1 OSR code. These observations show measurement sensitivity but do not prove the precise allocation source.

The isolated, warmed standalone path passed three independent default-JIT runs with zero bytes. The corrected full lifetime suite then passed 101 checks in each of three independent default-JIT runs, also with zero measured assignment bytes and exactly two initial invalidation requests. No tiered compilation or PGO switch was needed for these final runs. The multiline regression passed 17 checks.

Evidence: `artifacts/jit-allocation-2026-11-11/verification.json`. Earlier failures and runtime disassembly are retained. This qualifies the steady managed allocation test; it does not establish zero cold-start allocation, identify the original runtime allocation stack, or replace current NativeAOT and whole-app performance qualification. The [runtime's Dynamic PGO design](https://github.com/dotnet/runtime/blob/main/docs/design/features/DynamicPgo.md) explains instrumentation and profiling; attributing the observed bytes specifically to those mechanisms remains an inference.

Progress/Slider/Toggle now use the same isolated-loop warmup rule. Before correction, three independent default-JIT runs each reported 12,336 bytes and zero extra requests. After correction, three runs each passed all 101 lifetime checks with zero bytes and zero extra requests for these setters. Product setters, runtime settings and strict assertions are unchanged; allocation-stack attribution remains unproven. Evidence: `artifacts/text-commands-2026-11-11/verification.json`.
