# Markdown 위젯 (구현 진행 중)

Checkbox와 Markdown 작업 목록 지표가 `UiFluentCheckboxPalette.Resolve(context, state, value)`를 공유합니다. 시스템 대비 모드에서는 활성 라벨·테두리·마크에 CanvasText, 비활성 상태에 GrayText를 적용합니다. 선택된 배경은 Canvas이며 선택되지 않은 상태와 혼합 상태의 배경은 투명하게 유지합니다. 호버·누름에서도 같은 시스템 색상 역할을 사용합니다. 컨텍스트의 비활성 상태를 작업 목록에도 적용해, 일반 테마에서 활성 마크 색상이 남던 네 화면을 고쳤습니다. 기존 스킴 전용 오버로드는 원래 팔레트 계약을 유지합니다. GPU 화면 400개를 오차 없이 비교하며 세 값·네 상태·두 크기·모양·라벨 위치, 밝음·어두움과 실제 Markdown 작업 목록을 다룹니다. 같은 최종 검사 DLL로 이전 제품을 실행하면 204개가 실패합니다. 일반 테마 화면 200개 중 196개는 같고 비활성 작업 목록을 고친 네 개만 달라졌으며, 기존 Markdown 화면 677장은 모두 같습니다. 기존 포함 전체 검사 1,387개가 통과했습니다. [공식 Checkbox 스타일](https://github.com/microsoft/fluentui/blob/master/packages/react-components/react-checkbox/library/src/components/Checkbox/useCheckboxStyles.styles.ts)과 분리된 Chromium CSS 진단을 근거로 색상 역할을 정했습니다. 실제 Fluent 구성요소 전체를 실행하거나 브라우저 픽셀 전체와 비교한 검증은 아닙니다. 근거: `artifacts/checkbox-system-colors-2026-11-17/verification.json`.

선택되지 않은 스타일 텍스트도 공통 팔레트를 사용합니다. 본문·표시된 문법 기호는 CanvasText, 링크는 LinkText, 비활성 글자·링크는 GrayText를 사용합니다. 코드·표 머리글 배경은 Canvas, 표 테두리·구분선은 전경색 역할을 따릅니다. 네이티브 문단·분할 그리기·표 셀이 같은 색상 해석을 사용합니다. 접근성 원문 색상도 같은 경로로 게시하며 캐시 키에 시스템 팔레트와 활성 상태를 포함했습니다. LinkText만 바꿔도 원문을 다시 파싱하지 않고 화면과 접근성 정보가 함께 갱신됩니다. GPU 검사 45개가 통과했고, 같은 최종 검사 어셈블리로 이전 제품을 검사하면 30개가 실패합니다. 투명 전경으로 고정 색상을 분리한 화면 전체를 오차 없이 비교하며, 같은 불투명 색상의 GPU 합성이 비트 단위로 상쇄된다고 가정하지 않습니다. 일반 Markdown 검사312개와 화면677장 일치, 전체 대비 검사987개, Windows 표시64개와 Linux 호스트 빌드를 확인했습니다. 사용자 자식 슬롯·전체 브라우저 및 OS 적합성·Linux 실제 실행 검증은 남아 있습니다. 근거: `artifacts/styled-system-colors-2026-11-17/verification.json`.

IME 조합 입력은 공통 UTF-16 원문·표시 좌표 변환을 사용합니다. 원문 선택 방향은 유지하고 삽입한 조합 문자열은 선택에서 제외합니다. 글리프 텍스처의 사각형과 UV를 소수점 클립 경계에서 잘라 인접한 정수 GPU 시저가 같은 가장자리를 두 번 그리지 않게 했습니다. 저장된 글리프를 재사용하며 새 래스터라이저나 셰이더를 추가하지 않습니다. GPU 검사 72개로 Input, 명시적 분할 백엔드, Textarea, 줄바꿈 Textarea, 고정 행 입력과 Markdown의 양방향 선택·취소·반투명 가장자리 색상을 독립 기준과 대조했습니다. 전체 대비 검사 942개, 일반 입력 400개·Markdown 312개·여러 줄 입력 2560개가 통과했습니다. 일반 Markdown 화면 677장도 체크포인트430과 정확히 같습니다. 조합 절별 스타일, 실제 OS 전환, 양방향 전체 동작과 삼각형 메시의 선택 경계는 미검증입니다. 근거: `artifacts/ime-selection-colors-2026-11-17/verification.json`.

`Dux.MarkdownView`는 마크다운 문서를 읽기 전용으로 표시합니다. `Dux.MarkdownEditor`는 원문 버퍼, 선택 영역과 되돌리기 이력을 하나로 유지합니다. 현재 편집 중인 블록만 기호를 드러내고 제목·본문 스타일을 유지합니다. 다른 블록은 렌더링된 모습으로 표시합니다.

스타일 편집기는 배경·선택 영역·내용을 공통 단계로 나눠 그립니다. 코드와 표 머리글의 배경 위에 선택 영역을 합성하므로 일반 테마의 반투명 선택 색상도 유지됩니다. 시스템 대비 모드에서 선택된 글자와 링크·취소선은 원래 조판된 행의 물리 구간을 겹치지 않게 나눠 HighlightText로 그립니다. 네이티브 문단, 표와 섞인 문서, 분할 그리기 모두 글꼴·위치와 저장된 기하 정보를 유지합니다. 일반 글자는 한 번만 그려 소수점 위치의 선택 경계에서도 안티앨리어싱을 유지합니다. [W3C 선택 영역 그리기 초안](https://www.w3.org/TR/css-pseudo-4/#highlight-painting)을 참고했으며 전체 브라우저 동등성과 플랫폼·양방향 전체 검증은 남아 있습니다. 근거: `artifacts/styled-selection-colors-2026-11-16/verification.json`.

새 GPU 검사 25개와 기존 포함 870개, 일반 Markdown 312개·입력 커널 400개 검사가 통과했습니다. 기존 RGB 화면 677장 중 673장은 정확히 같으며, 표 머리글 선택을 고친 네 장은 별도 GPU 알파 합성 기준으로 확인했습니다. Windows 표시 시나리오 64개와 Linux 호스트 빌드도 통과했으며 Linux 실제 실행은 제외했습니다.

코드 블록도 같은 규칙을 따릅니다. 코드 블록을 편집할 때만 여닫는 펜스와 언어 이름을 표시합니다. 다른 블록으로 이동하거나 미리보기로 전환하면 코드 본문만 표시하므로, 한 줄짜리 코드는 한 줄로 렌더링됩니다. 아직 닫지 않은 펜스는 문법 분석 결과에 따라 처리하며 코드 본문에 들어 있는 백틱을 임의로 지우지 않습니다.

기본 강조·굵은 기울임·취소선과 꺾쇠 자동 링크를 표시합니다. 작업 목록은 Fluent 체크박스 모양으로 표시하며 체크 상태는 원문의 `[ ]`·`[x]`로 편집합니다. 가로 구분선도 같은 Fluent 테마 색상을 사용합니다. 아래·위 첨자, 삽입·형광 강조 확장 문법은 활성화하지 않아 `~text~`, `^text^`, `++text++`, `==text==`를 원문 그대로 표시합니다.

파이프 표는 머리글·테두리·왼쪽/가운데/오른쪽 열 정렬과 빈 셀을 표시합니다. 셀 내용의 원문 위치는 파서 결과로 보관하며 표를 편집할 때 같은 버퍼의 원문 전체를 드러냅니다. 셀 내부는 줄을 나누지 않고, 넓은 표는 문단 줄바꿈을 유지하면서 편집 영역에서 가로로 스크롤합니다. 여러 곳에서 같은 원문을 표시할 때 입력 변경은 후속 프레임을 한 번 예약하므로 먼저 그린 미리보기도 이벤트 대기 모드에서 갱신됩니다.

문서 분석과 미리보기는 LF·CRLF·CR 줄바꿈을 해석합니다. 편집기는 공통 여러 줄 입력 정책에 따라 줄바꿈을 LF로 정규화합니다.

```csharp
var markdown = new UiState<string>("# 제목\n\n**굵은** 본문입니다.");
using var editor = Dux.MarkdownEditor("문서", markdown.Binding, new(Height: 480));
using var view = Dux.MarkdownView("미리보기", markdown.Binding, new(Height: 480));
```

옵션으로 폭·높이·원문 길이 제한·자동 줄바꿈·테두리·읽기 전용 편집을 지정합니다. 폭0은 부모가 제공한 영역을 채웁니다. 기본 높이는420이며 기본 길이 제한은 UTF-16 기준1,048,576자입니다. 고정 문서는 `Dux.MarkdownView(markdown)`으로 표시할 수 있습니다.

`./run-gallery.ps1` → **추가 샘플 → Markdown → 문단 조판 예제**에서 **스마트 편집**을 선택한 뒤 Ctrl+A나 Shift+방향키로 굵은 글자·코드·링크에 걸친 선택을 확인하세요. **표 셀 예제**에서는 표 머리글 선택도 확인할 수 있습니다. 시스템 대비 색상은 플랫폼에서 받으며 샘플이 OS 설정을 바꾸지 않습니다.

미리보기의 링크에 마우스를 올리면 손 모양 커서를 표시하고, 눌렀다 놓으면 시스템 웹·메일 처리기로 이동합니다. 일반·참조·자동 링크와 표 안의 링크는 보관된 원문·화면 위치 정보를 함께 사용합니다. 드래그, 링크 밖에서 놓기, 비활성화·숨김, 문서 변경은 이동을 취소합니다. `MarkdownEditor`에서 링크를 누르면 기존처럼 원문을 편집합니다.

앱에서 이동을 직접 처리하려면 `view.Navigate = uri => ...`를 지정합니다. 상대 주소에는 `new UiMarkdownOptions(BaseUri: new Uri("https://example.com/docs/"))`를 지정합니다. 기준 주소가 없으면 사용자 콜백에 상대 URI를 전달합니다. 기본 `UiLinkNavigation.OpenExternal`은 절대 HTTP·HTTPS·mailto 주소를 지원하며 실행 오류는 예외로 알립니다. 앱 내부 경로나 다른 스킴은 사용자 콜백으로 처리합니다.

Tab·Shift+Tab으로 문서의 텍스트 선택 영역 다음에 있는 링크를 순서대로 탐색하고 Enter로 이동합니다. 여러 줄의 링크도 하나의 탐색 항목이며 표시된 각 부분에 포커스 테두리를 그립니다. 문서 화면 밖의 링크에 포커스하면 문서 내부를 스크롤해 보여줍니다. Space는 이동을 실행하지 않고 드래그는 텍스트를 선택합니다. Windows 접근성에는 일반 텍스트 이름·Invoke·읽기 전용 주소 Value를 가진 Hyperlink 자식을 제공하며 스크롤이 가능하면 ScrollItem도 제공합니다. 클릭 좌표는 실제 보이는 글자 영역 안에 두며 이동이 실행되면 확정된 Invoked 이벤트를 한 번 알립니다. 원문·기준 URI가 바뀌면 이전 링크 식별자를 해제합니다. 실제 화면 읽기 프로그램 사용은 추가 검증이 남아 있습니다.

포커스가 바뀌면 상위 `Dux.ScrollView`에도 링크가 보이도록 안쪽부터 바깥쪽으로 스크롤 요청을 전달합니다. 접근성 트리가 없어도 동작하며 다음 요청 프레임에서 조정한 위치를 그립니다. 포커스가 그대로면 수동 스크롤을 보존하고 형제 스크롤 영역은 바꾸지 않습니다. 이 계약은 소유한 ScrollView에 적용하며 기존 창 스크롤은 별도 구현입니다.

고정 버전 Markdig1.4.0의 원문 위치 정보를 사용합니다. 원문이 바뀔 때만 문서를 다시 분석하고 같은 블록 안의 커서 이동은 표시 결과를 재사용합니다. 원문과 화면 위치를 대응시켜 마크다운 원문을 기준으로 편집합니다. 한글 조합은 별도 표시 상태를 사용해 아직 확정하지 않은 입력이 문서를 덮어쓰지 않습니다. 글자 크기에 따른 줄 높이를 그리기·선택·클릭 위치·커서 스크롤·IME 사각형에서 함께 사용합니다.

이미지는 뷰어와 편집기에서 `![대체 텍스트](주소)`로 표시합니다. `ResolveImage`에 URI를 불변 `UiImageSource`로 연결하는 함수를 지정합니다. PNG·SVG는 기존에 등록한 이미지 디코더나 앱에서 미리 준비한 자원을 사용합니다. `BaseUri`는 상대 주소의 기준입니다. 파일·네트워크 요청은 자동으로 시작하지 않습니다. 함수가 null을 반환하거나 해석기를 지정하지 않았거나 주소가 올바르지 않으면 사용할 수 없는 이미지의 대체 텍스트를 표시합니다. 예상하지 못한 콜백 예외는 호출자에게 전달합니다.

```csharp
var picture = UiImageSource.LoadFromFile("figure.svg"); // Decode before rendering; configure the SVG decoder in the host.
view.ResolveImage = uri => uri.OriginalString == "figure.svg" ? picture : null;
editor.ResolveImage = view.ResolveImage;
```

같은 기준 주소로 정규화한 목적지는 문서에서 참조하는 동안 한 번만 해석하며 사용할 수 없는 결과도 보관합니다. 다른 본문을 편집해도 기존 이미지 자원은 유지합니다. `InvalidateImages()`는 원문을 다시 분석하지 않고 이미지 해석을 재시도하며 프레임을 요청합니다. 공유 SVG 저장소도 분석한 XML을 유지합니다. 참조가 사라지거나 문서를 해제하면 이미지 자원의 사용권을 반환합니다. 일반 이미지는 본문 폭에 맞춰 비율을 유지하며 축소하고, 표 안의 이미지는 고유 폭과 표의 가로 스크롤 계약을 따릅니다. 편집 중인 블록은 이미지 원문을 표시하며 다른 블록은 그림을 유지합니다. 이미지 자식 노드와 링크 부모 관계를 지원합니다. 네이티브 Image 인터페이스·원격/비동기 로딩 정책·이미지가 많은 큰 문서 검증은 남아 있습니다.

조합 입력은 확정할 때 한 번만 원문에 반영하며 취소와 되돌리기를 지원합니다. 제목 끝의 IME 글꼴도 현재 줄의 제목 크기를 사용합니다. 비활성·읽기 전용 입력은 확정 입력을 버리고, 편집기를 숨기거나 다른 컨텍스트로 옮기면 이전 IME 소유권을 해제합니다. `Dispose()`는 원문·편집·스크롤 상태와 콜백을 해제하며 이후 콜백 재설정은 예외를 발생시킵니다. 자동 검사는 조합 이벤트를 주입해 실행하며 실제 Windows IME 후보창 조작은 별도 검증 대상입니다.

실행: `./run-gallery.ps1` → **Markdown** → **스마트 편집 / 미리보기**. **이미지 예제**는 캐시된 SVG·메모리 비트맵·사용할 수 없는 이미지의 대체 표시를 엽니다. 미리보기에서 예제 링크에 마우스를 올리고 눌러 이동할 수 있습니다. 두 모드는 같은 원문을 사용하며 페이지를 바꿔도 유지합니다. 현재 구현은 검증 중입니다. 표의 추가 적합성·접근성, 불완전한 문법, 실제 Windows IME 후보창과 큰 문서 렌더링 검증이 남아 있습니다. 기존 사용자 정의 Markdown 위젯은 이전 작업이 끝날 때까지 유지합니다.

### 이미지 의미와 키보드 선택

렌더링한 이미지에 일반 대체 텍스트와 실제로 보이는 영역의 좌표를 가진 비대화형 Image 자식 노드를 게시합니다. 화면 밖의 이미지도 조회할 수 있으며 공통 항목 이동으로 가져올 수 있습니다. 사용할 수 있는 빈 대체 텍스트 이미지는 장식으로 처리해 생략하고, 사용할 수 없는 이미지는 화면의 안내 문구를 이름으로 사용합니다. 뷰에서 이미지로 만든 링크의 부모는 실제 Link 노드입니다. 편집 중인 블록은 정확한 원문을 보여주고 그 블록의 이미지 노드는 잠시 제거했다가 렌더링으로 돌아오면 다시 게시합니다. 좌표는 그리기와 같은 투영 이미지·배치 함수를 사용하며 바깥 구분선 문자가 없는 표 첫 칸의 안쪽 여백도 유지합니다. 이미지 주소 해석과 Markdown 분석 결과는 계속 재사용합니다.

키보드가 숨겨진 이미지 주소 안으로 들어가 한 번의 Shift+Right가 원문 위치8에서 이미지 끝24로 가지 않고9에 머무는 결함을 재현했습니다. 렌더링한 이미지는 전체 원문 경계를 한 번에 지나도록 좌우 이동과 위치 조회를 수정했고, 보이지 않는 문법 기호도 건너뜁니다. 편집 중인 원문 블록에서는 기존 문자 이동을 유지합니다. 선택 색을 불투명 이미지 위에 표시해 Shift 선택이 보이며, 선택을 해제하면 원래 그림으로 돌아옵니다. 이미지의 행은 줄바꿈 경계의 커서 방향 상태와 분리해 계산합니다. CPU84건으로 뷰·편집기, 일반·링크 이미지, 큰 이미지의 좌우·상하 이동과 Shift 조합을 확인했습니다. 실제 X11 Shift+Right·Left 입력과 소유 창의 픽셀 캡처로 이미지 전체 선택, 선택 색, 선택 해제와 원문 유지를 검증했습니다. 이미지 크기 조절 같은 객체 편집 기능을 추가한 것은 아닙니다.

기본 이미지 의미는 CPU31건과 실행 방식별 독립 네이티브21건으로 역할·이름·링크 부모·좌표·위치 조회·원문 이동·실제 키보드와 픽셀 변화를 검사했습니다. 최종 관리형 .NET11/Linux1141건은 앱·세션74건+경계·배치1049건+폰트 선택18건이며 독립 네이티브20개 실행이 통과했습니다. 새 Windows 공통227건·복합 및 Markdown415건의 CPU 검사, 전용 클립보드35건·소유 제품 샘플의2초 자동 종료 코드0도 통과했습니다. 네이티브 Image 인터페이스와 일반 Component.ScrollTo, 실제 화면 읽기·입력기, 원격 이미지 정책, 하드웨어·ARM64·고정 RC3 NativeAOT 검증은 남아 있습니다. 근거는 `artifacts/linux-accessibility-2026-11-14/markdown-image-interaction-verification.json`입니다.

## 자체 SVG·네이티브 이미지 검증 — 2026-11-14

SVG 백엔드는 자체 기하·래스터 처리와 Windows의 DirectWrite·WIC, Linux의 HarfBuzz·GdkPixbuf로 바뀌었습니다. Windows에는 Skia·HarfBuzz·외부 이미지 코덱 DLL을 배포하지 않습니다. Linux HarfBuzz 네이티브 자산은 대상 플랫폼에만 포함합니다. 기존 자원·재로드·LRU·확대·회전·폰트 보관 계약은 유지합니다. [플랫폼별 SVG 렌더링](svg-platform-rendering.ko.md)과 `artifacts/svg-managed-2026-11-14/verification.json`을 참고하세요. 앞의 Skia 검증 기록은 교체 전 결과입니다.

`UiAccessibilityNode.ImageInfo`는 `UiAccessibilityImageInfo`를 선택적으로 게시합니다. 화면에서 잘리기 전의 전체 이미지 영역, 설명, 명시한 경우의 언어를 변경하지 않는 값으로 보관합니다. 기존 `Node.Bounds`는 계속 잘린 영역입니다. 실제로 표시하는 Markdown 이미지는 이 정보를 제공하며, 장식용 이미지는 제외하고 로드 실패 안내문은 네이티브 이미지로 등록하지 않습니다. Linux는 이 정보가 있을 때만 `org.a11y.atspi.Image`를 제공합니다. 설명·언어·크기와 화면·창·부모 기준 위치·영역을 읽을 수 있으며, 언어가 없으면 빈 프로토콜 문자열을 반환합니다. 크기는 실제 렌더링 영역을 감싸는 정수 픽셀이므로 원본 비트맵 크기와 다를 수 있습니다. 원문 범위로 드러내기와 키보드 선택은 유지합니다. 일반 Component.ScrollTo와 실제 화면 읽기 검증은 남아 있습니다.
