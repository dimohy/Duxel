# 혼합 굵기 인라인 텍스트

`UiInlineFlowWidget`와 텍스트 전용 `MessageBarBody`도 같은 네이티브 문단을 사용합니다. 서로 다른 굵기·폰트 사이의 양방향 문맥과 줄바꿈을 공유하면서 각 자식의 소유권·접근성 ID는 유지합니다. 회전·여백을 가진 자식이나 입력·링크 등 실제 위젯도 네이티브 객체 영역을 차지하며 각자의 렌더링·입력·포커스 경로를 유지합니다. `UiInlineFlowWidget.RightToLeft`는 문단 기준 방향이며 기본값은 false입니다. 같은 값은 캐시를 유지하고 변경된 값은 배치를 갱신합니다. 명시적 RTL에는 네이티브 문단과 직접 텍스트가 필요합니다. MessageBar의 표준 본문에도 옵션의 기준 방향이 전달됩니다. 타이포그래피 탭의 **자식을 소유한 문단**에서 예제를 확인하세요. 새 경로의 Linux 검증은 Ubuntu 복구 후 필요합니다.

`UiInlineText.RightToLeft`는 문단 기준 방향이며 기본값은 `false`입니다. 초기화할 때 지정하거나 기존 위젯에서 바꿀 수 있습니다. 원문과 소유한 문자열 목록은 유지됩니다. 값이 달라지면 네이티브 문단을 다시 만들고, 같은 값이면 재사용합니다. 물리적인 좌우 정렬은 부모 배치가 담당합니다. 명시적 RTL은 네이티브 문단 백엔드와 직접 텍스트가 필요하며, 지원되지 않는 요청은 조용히 무시하지 않고 예외로 알립니다.

```csharp
using var paragraph = new UiInlineText([
    new("abc אב ", UiInlineTextWeight.Bold), new("גד regular 123")
]) { RightToLeft = true };
paragraph.RightToLeft = false;
```

타이포그래피 옵저버의 **오른쪽에서 왼쪽 문단** 스위치로 확인하세요. 현재 Windows는 요청·네이티브·Core70개, 정확한 네이티브 GPU128쌍과 스위치를 드러내 실제로 전환하는 옵저버40개가 통과했습니다. Linux 소스도 연결했지만 Ubuntu 파일시스템 I/O 오류로 새 NativeAOT 검증은 대기 중입니다. 이전 검증본 `e529777d`를 유지하며 이 전달본에는 새 스위치가 없습니다. [현재 실행 상태](../artifacts/fluent-messagebar-2026-11-15/literal-direction-verification.json)를 확인하세요.

Windows·Linux는 일반 문자열의 배치와 그림에 [네이티브 스타일 문단 스냅샷](styled-paragraphs.ko.md)을 사용합니다. Windows는 네이티브 GPU64쌍과 요청·네이티브·Core45개, Linux NativeAOT는 스타일351개·기존 위치334개·텍스트 기준114개가 통과했습니다. Linux 전달본은 `e529777d`입니다. 두 플랫폼의 일반 실행기에서 타이포그래피 예제를 확인하세요. 다른 소비 경로는 남아 있으며 아래 이전 수치는 당시 범위의 기록입니다.

`UiInlineText`는 하나의 Body1 텍스트 영역에 일반(400), 세미볼드(600), 볼드(700)를 섞는 공통 기반 위젯입니다. MessageBar의 제목과 본문처럼 이어지는 문장을 서로 다른 굵기로 표시할 때 사용합니다. 공식 Fluent 컴포넌트 목록이나 완료 수를 늘리지 않습니다.

```csharp
using var content = new UiInlineText([
    new("연결되었습니다. ", UiInlineTextWeight.Semibold),
    new("작업을 계속할 수 있습니다.")
]);

// UiScreen.Render에서 사용합니다.
content.Render(ui);
```

텍스트를 바꾸려면 `Runs`를 새 목록으로 교체합니다. 위젯은 목록을 복사해 소유하고, `Runs`에서는 읽기 전용 스냅샷을 제공합니다. `Text`는 원문을 이어 붙인 결과입니다. `#`, `**`, 링크 문법은 마크업으로 해석하지 않습니다. 선택이나 편집을 처리하는 입력 위젯이 아니며, 접근성에서는 전체 원문을 하나의 정적 레이블로 게시합니다.

기본값은 줄바꿈 사용입니다. 부모가 배정한 실제 너비로 줄바꿈하며, 명시적인 LF/CRLF도 유지합니다. `Wrap = false`는 줄임표를 만들지 않고 자연 너비를 측정하며, 배정 영역 밖의 그림은 부모 클립을 따릅니다. 일반 위젯의 Margin, Transform, 비활성 상태, 접근성 이름을 함께 사용할 수 있습니다.

인접한 같은 굵기는 하나의 셰이핑 구간으로 합칩니다. 호출자가 나눈 문자열 경계 때문에 결합 문자나 커닝이 깨지지 않습니다. 굵기가 달라지는 경계는 Unicode 텍스트 요소 경계여야 하며, 한 이모지나 결합 문자 내부에서 굵기를 바꾸면 예외로 알립니다. 잘못된 교체는 기존 내용을 바꾸지 않습니다.

원문과 스타일 투영은 내용 변경 때만 만들고, 줄 배치는 너비·폰트·배율·리소스가 같으면 재사용합니다. 색상만 바뀌어도 배치를 다시 측정하지 않습니다. 위젯 자체는 애니메이션이나 주기적인 프레임을 요청하지 않습니다. 모든 실행의 속도 향상을 수치로 입증한 것은 아닙니다.

집중 검증은 `artifacts/fluent-messagebar-2026-11-15/inline-verification.json`에 있습니다. Windows 관리형 모델32개, 기존 텍스트 회귀64개, 독립적으로 배치한 일반/세미볼드/볼드와의 원시 GPU 픽셀32쌍을 확인했습니다. 한글·자동 줄바꿈·명시 줄바꿈·Light/Dark·MSAA1/4·반복 배치를 포함합니다. Linux 네이티브 실행, Windows NativeAOT, 문단 전체의 양방향 텍스트 적합성 및 MessageBar 전체 검증은 이 결과에 포함되지 않습니다. 기존 Linux 옵저버 전달 실행본도 이번 기반 변경으로 교체하지 않았습니다.
