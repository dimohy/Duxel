# 값 교체·길이 제한·undo

한 줄·다중 행 편집 커널에 공통으로 적용하는 규칙입니다. 편집 정확성 수정이며 전체 Unicode 셰이핑이나 Fluent 일치 완료를 의미하지 않습니다.

`MaxLength`는 들어오는 편집의 UTF-16 코드 단위 예산을 유지합니다. 붙여넣기·IME 확정 문자열이 남은 예산보다 길면 그 문자열 안에서 .NET `StringInfo` 텍스트 요소 경계로 끝나는 가장 긴 접두부를 넣습니다. 들어오는 요소 내부의 서로게이트 쌍·결합 문자·연결 이모지·국기·키캡을 나누지 않습니다. 첫 요소가 들어가지 않으면 값·선택 범위·바인딩을 유지합니다. 이미 최대 길이에 도달했어도 문자 이벤트로 선택 영역을 덮어쓸 수 있습니다. 전체 입력이 들어가는 경우 기존 빠른 경로를 유지합니다.

호출자가 대입한 값은 편집 예산으로 잘라내지 않습니다. 접근성 Value 요청은 별도의 게시 길이·제어문자 검증을 유지합니다. 이 규칙이 Unicode 편집 전체, 삽입 경계 양쪽을 합친 그라펨 의미, 양방향 배치나 브라우저 일치를 입증하지는 않습니다.

다음 렌더에서 커널의 기존 정규화를 적용한 호출자 값이 편집 버퍼와 다르면 새 undo 기준점을 만들고 기존 redo를 무효화합니다. 이 동기화 자체는 바인딩에 알리지 않지만 기존 다중 행 정규화가 호출자 텍스트를 바꾸면 그 알림은 유지합니다. 문자열 인스턴스가 달라도 내용이 같으면 이력을 유지합니다. 그 뒤 입력한 문자·IME 확정은 새 기준점으로 되돌릴 수 있습니다. 이력 초기화는 풀 배열의 이전 문자열 참조를 지우고 지나치게 큰 배열 용량을 반환합니다.

접근성 Value 요청은 편집 트랜잭션으로 유지합니다. 커널은 외부 모델 교체를 먼저 동기화하고, 대기 Value 변경을 기록한 뒤 키보드 입력을 처리합니다. 따라서 API 변경을 undo/redo할 수 있고 같은 프레임의 Undo도 이 변경을 되돌립니다. 외부 교체가 동시에 있으면 교체 값이 그 앞의 기준점입니다. `UiTextEditBuffer.Sync`도 요청 값이 이전 캐시 문자열과 같더라도 수정 중인 builder 내용을 실제로 교체합니다.

고정 .NET 11 RC3에서 수정 전 29개 실패를 재현했습니다. 확대 CPU 175검사에는 한 줄/다중 행·키보드·클립보드·대기 IME 핸들러·접근성 트랜잭션의 새 무결성 49검사가 포함됩니다. 프로세스 내부 검사로 실제 OS IME나 외부 Windows UIA를 입증하지는 않습니다. 빌드·회귀·이미지·샘플 근거는 `artifacts/text-edit-integrity-2026-11-11/verification.json`에 기록합니다. 현재 Native·런타임 비교·통합 성능은 미완료입니다.
