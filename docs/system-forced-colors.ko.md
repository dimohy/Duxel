# 시스템 강제 색상 공통 기반

Checkbox와 Markdown 작업 목록 지표가 `UiFluentCheckboxPalette.Resolve(context, state, value)`를 공유합니다. 시스템 대비 모드에서는 활성 라벨·테두리·마크에 CanvasText, 비활성 상태에 GrayText를 적용합니다. 선택된 배경은 Canvas이며 선택되지 않은 상태와 혼합 상태의 배경은 투명하게 유지합니다. 호버·누름에서도 같은 시스템 색상 역할을 사용합니다. 컨텍스트의 비활성 상태를 작업 목록에도 적용해, 일반 테마에서 활성 마크 색상이 남던 네 화면을 고쳤습니다. 기존 스킴 전용 오버로드는 원래 팔레트 계약을 유지합니다. GPU 화면 400개를 오차 없이 비교하며 세 값·네 상태·두 크기·모양·라벨 위치, 밝음·어두움과 실제 Markdown 작업 목록을 다룹니다. 같은 최종 검사 DLL로 이전 제품을 실행하면 204개가 실패합니다. 일반 테마 화면 200개 중 196개는 같고 비활성 작업 목록을 고친 네 개만 달라졌으며, 기존 Markdown 화면 677장은 모두 같습니다. 기존 포함 전체 검사 1,387개가 통과했습니다. [공식 Checkbox 스타일](https://github.com/microsoft/fluentui/blob/master/packages/react-components/react-checkbox/library/src/components/Checkbox/useCheckboxStyles.styles.ts)과 분리된 Chromium CSS 진단을 근거로 색상 역할을 정했습니다. 실제 Fluent 구성요소 전체를 실행하거나 브라우저 픽셀 전체와 비교한 검증은 아닙니다. 근거: `artifacts/checkbox-system-colors-2026-11-17/verification.json`.

선택되지 않은 스타일 텍스트도 공통 팔레트를 사용합니다. 본문·표시된 문법 기호는 CanvasText, 링크는 LinkText, 비활성 글자·링크는 GrayText를 사용합니다. 코드·표 머리글 배경은 Canvas, 표 테두리·구분선은 전경색 역할을 따릅니다. 네이티브 문단·분할 그리기·표 셀이 같은 색상 해석을 사용합니다. 접근성 원문 색상도 같은 경로로 게시하며 캐시 키에 시스템 팔레트와 활성 상태를 포함했습니다. LinkText만 바꿔도 원문을 다시 파싱하지 않고 화면과 접근성 정보가 함께 갱신됩니다. GPU 검사 45개가 통과했고, 같은 최종 검사 어셈블리로 이전 제품을 검사하면 30개가 실패합니다. 투명 전경으로 고정 색상을 분리한 화면 전체를 오차 없이 비교하며, 같은 불투명 색상의 GPU 합성이 비트 단위로 상쇄된다고 가정하지 않습니다. 일반 Markdown 검사312개와 화면677장 일치, 전체 대비 검사987개, Windows 표시64개와 Linux 호스트 빌드를 확인했습니다. 사용자 자식 슬롯·전체 브라우저 및 OS 적합성·Linux 실제 실행 검증은 남아 있습니다. 근거: `artifacts/styled-system-colors-2026-11-17/verification.json`.

IME 조합 입력은 공통 UTF-16 원문·표시 좌표 변환을 사용합니다. 원문 선택 방향은 유지하고 삽입한 조합 문자열은 선택에서 제외합니다. 글리프 텍스처의 사각형과 UV를 소수점 클립 경계에서 잘라 인접한 정수 GPU 시저가 같은 가장자리를 두 번 그리지 않게 했습니다. 저장된 글리프를 재사용하며 새 래스터라이저나 셰이더를 추가하지 않습니다. GPU 검사 72개로 Input, 명시적 분할 백엔드, Textarea, 줄바꿈 Textarea, 고정 행 입력과 Markdown의 양방향 선택·취소·반투명 가장자리 색상을 독립 기준과 대조했습니다. 전체 대비 검사 942개, 일반 입력 400개·Markdown 312개·여러 줄 입력 2560개가 통과했습니다. 일반 Markdown 화면 677장도 체크포인트430과 정확히 같습니다. 조합 절별 스타일, 실제 OS 전환, 양방향 전체 동작과 삼각형 메시의 선택 경계는 미검증입니다. 근거: `artifacts/ime-selection-colors-2026-11-17/verification.json`.

Fluent Menu의 표면·행 텍스트·선택 표시·아이콘·보조 텍스트와 비활성 상태에 시스템 색상을 적용합니다. 모든 행을 그린 뒤 항목 뷰포트의 클립 밖에서 두께 2픽셀의 바깥 Highlight 포커스 선을 그립니다. 새 GPU 검사 132개와 기존 포함 445개, 일반 Menu 216개·Dropdown 41개·Combobox 84개·스크롤 모션 44개 검사가 통과했으며 일반 메뉴 RGB 화면 281장도 일치합니다. Dropdown·Combobox 선택 항목도 별도 팔레트에서 Canvas 호버·누름, CanvasText 글자·체크·포커스, 비활성 GrayText를 받으며 다중 선택 체크박스에도 적용됩니다. 바깥 포커스는 기존의 항목 그리기 후 단계를 사용합니다. [선택 항목의 근거와 한계](fluent2-dropdown.ko.md). [API·공식 근거·범위](fluent2-menu.ko.md). 근거: `artifacts/menu-contrast-2026-11-16/verification.json`.

SpinButton 증감 버튼의 전용 팔레트는 일반 화살표에 ButtonText, 비활성·범위 끝·읽기 전용 화살표에 GrayText, 호버·누름 배경에 ButtonFace를 적용합니다. 기본·비활성 배경은 투명하게 유지합니다. Markdown 선택도 네이티브 문단·표 셀·분할 그리기의 공통 배경·내용 단계를 사용합니다. 코드와 표 머리글 배경을 먼저 그린 뒤 선택 영역을 합성하고, 글자와 링크·취소선을 그립니다. 시스템 대비 모드의 선택 글자는 HighlightText를 사용하며 원래 글자의 알파를 밑에 겹쳐 그리지 않습니다. 일반 글자는 한 번만 그려 소수점 경계의 안티앨리어싱과 원래 배경 위의 선택 알파를 유지합니다. 전체 브라우저·플랫폼·양방향 검증은 별도 작업으로 남아 있습니다. 일반 한 줄·다중 행 입력에서 선택한 글자에는 Highlight/HighlightText 쌍을 적용합니다. 원래 조판된 전체 텍스트를 유지하면서 선택 구간과 나머지 구간을 겹치지 않게 나눠 그립니다. 같은 픽셀에 글자 알파를 두 번 합성하지 않습니다. Input·Textarea·SearchBox·Dropdown·Combobox·SpinButton·Markdown 입력의 프레임과 텍스트는 이제 컨텍스트를 받는 공통 입력 팔레트를 사용합니다. 시스템 팔레트가 활성화되면 Canvas/CanvasText, 비활성 상태의 GrayText, 포커스 밑줄의 Highlight를 적용하며 비활성·Underline 배경은 투명하게 유지합니다. 입력 계열에서는 사용자 자식 슬롯 색상과 실제 OS 모드 전환 검증이 남아 있습니다. 공통 프레임·텍스트, 선택 항목과 선택 영역 그리기는 위의 개별 검증 기록에서 확인할 수 있습니다. 기존 입력 배치와 편집 동작은 유지하며 스타일 배경의 그리기 순서를 고친 내용은 위에서 따로 설명했습니다.

`IPlatformThemeProvider.ForcedColors`는 선택적으로 `UiForcedColorPalette`를 제공합니다. null이면 비활성 상태이거나 해당 제공자가 팔레트를 제공하지 않는다는 뜻입니다. `UiTheme.ForcedColors`는 밝음·어두움과 별도로 이 상태를 보존합니다. 팔레트에는 Canvas/CanvasText, GrayText, Highlight/HighlightText, LinkText, ButtonFace/ButtonText가 있습니다. `Apply(theme)`은 디자인의 배치·타이포그래피를 유지하며 공통 색상 역할을 매핑합니다.

`DuxelAppOptions.RespectSystemForcedColors`는 명시적으로 지정한 디자인에도 기본 true입니다. 앱에서 접근성 색상을 직접 관리할 때만 false를 지정합니다. 비활성화하면 원래 디자인으로 복원합니다. 세션은 밝음·어두움이 같아도 팔레트 변경을 감지합니다. 유지된 레이어와 Avatar 그리기 그룹도 팔레트가 바뀌면 다시 구성합니다.

Windows는 시작 시점과 관련 WM_SETTINGCHANGE/WM_SYSCOLORCHANGE/WM_THEMECHANGED 알림에서 SPI_GETHIGHCONTRAST와 시스템 색상을 읽습니다. 시스템 설정을 변경하지 않습니다. 통합 창 장식에도 같은 팔레트와 앱의 제외 설정을 적용합니다. 상태 플래그를 읽는 네이티브 호출은 [Windows Forms 구현](https://github.com/dotnet/winforms/blob/main/src/System.Windows.Forms/System/Windows/Forms/SystemInformation.cs)을 따르며 이 getter가 반환된 스킴 포인터를 해제하지 않습니다. [Windows 지침](https://learn.microsoft.com/en-us/windows/win32/winauto/high-contrast-parameter).

이 범위는 플랫폼·테마의 공통 기반이며 Fluent 전체의 강제 색상 적합성이 아닙니다. 위젯별 고정 팔레트, RatingDisplay의 원래 경로 외곽선, Linux 데스크톱 팔레트 감지, 실제 OS 고대비 전환 검증은 남아 있습니다. 기존 Linux 제공자는 팔레트를 제공하지 않습니다. 검증에서 시스템 전체의 고대비 설정을 켜거나 끄지 않았습니다. 실제 Win32 읽기와 동일한 어두운 테마에서의 GPU 픽셀 변경을 포함한8개 계약을 검사합니다. Observer는 원래의 명시적 어두운 디자인을 유지하며 시스템 고대비가 활성화되면 시스템 색상을 받아들입니다.

Badge와 CounterBadge는 활성 시스템 팔레트의 Canvas/CanvasText를 배경·문자·아이콘·테두리에 적용합니다. 원래 배경 알파를 유지하므로 Ghost와 Outline은 투명하며, 시스템 색상의 1픽셀 테두리는 표시합니다. [CSS 강제 색상 규칙](https://www.w3.org/TR/css-color-adjust-1/#forced-colors-properties)과 기존 Fluent Badge의 투명 테두리 의도를 따릅니다. 실제 GPU 계약6개로 네 표현·여덟 의미 색상, 밝음·어두움 기본 디자인의 동일 출력과 Ghost CounterBadge를 확인했습니다. 기존 공통 기반8개 계약과 구분하며, 실제 OS 모드 전환과 다른 구성요소의 팔레트는 미검증입니다.
