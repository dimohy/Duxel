# 화면 갱신 관찰

**오른쪽 상단 전역 토글** : 갱신 영역 강조는 기본 꺼짐이며 모든 탭·팝업에 적용되고 탭 이동 후에도 유지됩니다. 갱신 관찰 탭은 고정/변경 콘텐츠를 비교하는 샘플입니다. [Linux 실행](../samples/Duxel.Gallery.Linux/README.ko.md).

마지막 갱신 2026-11-19

저장소에서 `./run-gallery.ps1`을 실행한 뒤 **갱신 관찰** 탭을 선택합니다. 이미 열린 옵저버는 이전 실행 파일이므로 새로 빌드한 실행 파일에서 확인하세요. 상단의 V-Sync와 이벤트 대기 옵션은 Fluent Switch이며, V-Sync는 기본적으로 꺼져 있습니다.

1. **한 번 변경**을 누르거나 **갱신 관찰 입력**을 편집합니다.
2. **갱신 영역 강조**를 켜면 Vulkan이 화면 이미지에서 실제로 다시 그린 범위에 초록 테두리가 0.2초 동안 나타납니다.
3. **텍스트 자동 변경 (60Hz)**으로 반복 변경을 확인합니다. 끄면 강조 제거를 마친 뒤 이벤트 대기로 돌아갑니다. 입력창에 포커스가 있으면 캐럿 깜박임은 계속 필요합니다.
4. 성능을 비교할 때는 강조를 끕니다. 자동 변경을 멈추고 **측정값 확인**을 누르면 직전 페이지 구성 시간, Draw, 업로드, 재사용, 갱신 범위와 진단 추가 갱신을 확인할 수 있습니다.

**측정 재사용**은 자식의 배치 계산을 다시 하는지 확인하는 기존 탭입니다. **갱신 관찰**은 CPU 콘텐츠 구성과 실제 GPU 갱신을 함께 비교하는 별도 탭입니다. 정적 패널 구성 수가 유지되어도 다른 변경과 합쳐진 영역을 GPU가 다시 그릴 수 있습니다.

초록 테두리에는 오래된 스왑체인 이미지와 MSAA 표면을 복구하기 위해 다시 그린 영역도 포함됩니다. 화면을 그대로 재사용하면 새 테두리가 생기지 않습니다. 강조 중에는 상단 지표를 고정하며 테두리 자체를 지우는 데 드는 작업은 따로 기록합니다.

## 공통 엔진 경로

- `ui.SetRepaintHighlights(enabled)`가 프레임의 `UiDrawData.RepaintHighlights`로 전달됩니다. 배처와 복제도 이 값을 유지합니다.
- `UiRendererFrameMetrics.RepaintBounds`는 내용을 다시 그린 범위를 프레임버퍼 픽셀로 기록합니다. 그 범위 밖에서 초록 선 때문에 추가로 그린 부분이 있으면 `RepaintDiagnosticRedraw`가 켜집니다.
- Vulkan은 내용의 캐시 지문에 영향을 주지 않도록 초록 테두리를 마지막에 그립니다. 스왑체인 이미지나 공유 MSAA 표면에 남은 테두리가 내용 갱신 범위 밖에 있으면, 그 선이 지나간 부분만 복원합니다. 프로파일의 `overlayStrips`와 `overlayPixels`로 추가로 그린 띠의 수와 픽셀 수를 확인할 수 있습니다.
- 평면 위젯을 확대하거나 회전하면 이전 위치와 새 위치를 화면 좌표로 계산하고 부모의 클립 밖을 제외합니다. 스왑체인 이미지에 처음 그릴 때는 전체를 채웁니다. 원근 투영이나 깊이 쓰기를 사용하는 장면은 전체 갱신을 유지합니다.
- 호스트는 `RepaintHighlightDeadlineTicks`까지 기다립니다. 진단 만료만으로 깨어난 프레임은 `UiFrameInfo.RepaintDiagnosticCleanup`을 전달하여 보수적인 전체 재그리기가 강조를 다시 시작하지 않게 합니다. 직접 호스트 루프를 구현할 때도 이 계약을 유지해야 합니다.
- 텍스처 생성·갱신·제거마다 전체 화면을 무효화하던 경로를 변경했습니다. 기존 텍스처 버전 원장을 재사용하고, 각 그리기 명령의 텍스처와 backdrop 버전을 비교하여 실제 참조 영역을 보수합니다. 보이는 곳에서 사용하지 않는 텍스처는 화면을 다시 그리지 않습니다. PaintGroup의 별도 전체 무효화 경로는 유지합니다.

## 측정 범위

`Duxel.Graphics.Tests <결과 폴더> repaint`는 실제 MSAA1/4 픽셀, 테두리 제거, 내용과 진단 비용 분리, 텍스처 부분 갱신을 검사합니다. 이어서 네이티브 Fluent 텍스트의 동일 길이 고정/변경 값을 3회 교대로 측정합니다. 각 구간은 96회 준비 후 256회를 기록하며 강조와 V-Sync는 꺼져 있습니다.

`text-update.csv`의 `buildMs`는 CPU 구성, `submitReadbackMs`는 동기 픽셀 읽기까지 포함한 제출 시간입니다. `gpuUs`는 GPU 타임스탬프이며 지연된 표본입니다. 이 진단의 FPS 환산을 실제 옵저버 입력 FPS나 고정 RC3 NativeAOT 성능으로 보고하지 않습니다. `scheduling-session repaint`는 실제 파이프라인 호스트의 강조 종료와 후속 외부 변경, 다시 대기하는 동작을 검사합니다.
