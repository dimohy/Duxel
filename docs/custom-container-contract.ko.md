# 사용자 정의 컨테이너 계약

레이아웃이 반환하는 루트 `Size`는 두 축 모두에서 부모가 준 제약을 지켜야 합니다. 범위를 벗어난 크기는 캐시에 저장하거나 그리기 전에 예외를 냅니다. 자식이나 표면의 사각형은 루트 바깥까지 지정할 수 있으며, 그 부분은 루트 경계에서 잘립니다.

로컬에서 만든 `Duxel.Windows.App` 패키지만 참조하는 외부 .NET 11 프로젝트에서도 의존 패키지인 `Duxel.App`의 분석기가 동작합니다. 생성된 Footer와 클리핑 예제로 배치 크기, 편집기 초점과 되돌리기, 클리핑, 해제를 포함한 15건을 통과했습니다. 빌드 산출물 경로를 따로 지정해도 패키지 안의 분석기는 그 빌드에서 생성한 파일과 일치합니다.

두 패키지를 담은 로컬 피드만 사용해 원본 `layout_custom_contract_fba.cs`도 그대로 빌드하고 실행했습니다. SDK 11.0.100에서 `dotnet build layout_custom_contract_fba.cs -c Release -p:RestoreSources=<로컬-피드> -p:PublishAot=false -p:SelfContained=false`로 관리 빌드를 재현할 수 있습니다. `DUXEL_SAMPLE_EXERCISE=1`을 지정해 실행하면 샘플의 콜백이 자동으로 실행됩니다. 첫 Vulkan 화면 제출, 조작 단계 4개, 종료 코드 0을 확인했습니다.

2026-11-11 Footer 툴팁은 Description 관계를 명시한다. 별도 Windows UIA 클라이언트로 실제 Footer 도움말·이름과 이웃 Inset 의미 분리를 확인했다. [대상 접근성 계약](tooltip-accessibility.ko.md)을 따른다.

2026-11-11 샘플 확장: Footer 버튼에 생성된 사용자 Tooltip 래퍼를 연결했다. 컨테이너 계약 정의는 유지하며 [Tooltip 대상 계약](tooltip-targets.ko.md)의 지연·소유권·포커스 동작을 함께 보여 준다. 사용자 표면이며 공식 Fluent Tooltip 완료를 뜻하지 않는다.

`layout_custom_contract_fba.cs`는 `IUiSingleChildLayout<TOptions>`, `IUiContainerPresentation`, `UiWidgetStyle`을 사용하는 외부 생성 컨테이너 예제입니다. 여백과 푸터를 예약한 나머지 영역을 tight 제약으로 기존 편집기에 측정시키고 루트 할당 하나를 반환합니다. 소스 생성기가 닫힌 제네릭 기반 클래스의 생성자와 옵션을 전달하므로 friend assembly나 런타임 리플렉션이 필요하지 않습니다.

측정은 자식을 측정하기 전에 메타데이터와 유한 부모 기하를 검증합니다. 그리기, 커서 이동, 입력 바인딩 읽기, 소유권 변경을 수행해서는 안 됩니다. `CanRetainMeasurement`는 명시적 선택이며 옵션 변경은 자식·포커스·undo를 유지하면서 레이아웃을 무효화합니다. 잘못된 옵션은 이전 값을 교체하기 전에 실패하고, 알 수 없는 기하는 명시적으로 거부합니다.

루트 할당은 사용자 표현의 그리기와 자식 입력·렌더를 함께 제한합니다. `Surface`는 표현 사각형이자 자식 클립 경계이며 루트 밖으로 확장해도 할당이 늘어나지 않습니다. 호출자 클립은 루트와 교차하고 표현이 예외를 던져도 호출자 클립이 복원됩니다. 면적 0인 교차 영역의 좌표는 루트 밖에 남을 수 있지만 픽셀을 그리거나 입력을 받을 수 없습니다.

## 검증 — 2026-11-10

독립적인 공개 API 소비 프로젝트에서 기존 그리기·입력 누출을 재현한 후 공통 루트 클립 적용으로 15개 검사를 통과했습니다. 샘플에서 정확히 추출한 계약 정의와 생성자를 컴파일하고 실제 편집 입력·undo·옵션 변경·해제·표현 예외를 검증합니다. 초기 기하 검사는 무해한 높이 0 교차도 거부했으므로 양의 면적 클립을 판정하도록 수정했으며 실패 출력을 별도로 보존했습니다.

고정 .NET 11 RC3 관리 검증은 컨테이너 237개(MSAA 1/4·획득 프레임 4개의 신규 GPU 비교 8개 포함), 좌표 회귀 2,317개, ScrollView 47개, 가상 목록 43개, 수명 101개를 통과했습니다. 신규 GPU 검사는 루트보다 큰 사용자 표현과 독립적으로 클립한 그리기를 비교합니다. 정확성 근거이며 성능 개선·외부 Windows UIA·수동 OS 입력 검증을 뜻하지 않습니다.

FBA 패키지 지시문은 배포 패키지 관례를 사용합니다. 로컬 검증은 저장소 프로젝트 참조로 교체하고 생성기를 분석기로 명시하므로 기존 배포 패키지에서의 사용 가능성을 입증하지 않습니다. 원래 컨테이너 진행 상태는 3/6입니다.

## Linux 런타임 비교 — 2026-11-19

외부 프로젝트에서 샘플 본문을 그대로 컴파일해 `ConsumerFooter`와 `ConsumerTooltip`을 생성했습니다. 프로젝트 지시문과 Windows 실행부만 Linux에 맞게 바꿨습니다. SDK 11.0.100으로 빌드한 x64 .NET 11.0.0 관리형과 NativeAOT에서 Footer·Inset·Tooltip의 네 상태를 같은 순서로 실행했고 모두 정상 종료했습니다. WSLg에서 각 런타임을 두 번 실행해 820×520 X11 창의 초기 화면을 총 여덟 번 캡처했고, 픽셀이 모두 일치했습니다. 실행 근거는 `W:/Cache/Duxel/gallery-source-20261117/custom-container-linux-2098`에 있습니다.

별도 실행에서는 네 상태를 하나씩 유지하고 Vulkan 제출을 확인한 뒤 X11 창을 두 번씩 캡처했습니다. 각 런타임에서 서로 다른 화면 네 장이 나왔고, 상태별로 비교한 픽셀 네 쌍이 모두 일치했습니다. 마지막 상태는 앞선 초기 화면과도 일치했습니다. 이 검사는 WSLg에서 샘플 콜백을 실행해 화면 결과를 확인한 것입니다. 물리 입력, 현재 Windows NativeAOT, 컨테이너 통합 성능은 검증이 남아 있습니다. 실행 근거는 `W:/Cache/Duxel/gallery-source-20261117/custom-container-states-2099`에 있습니다.
