# Duxel 갤러리

Nav 목적지에 `UiNavSecondaryAction`으로 보조 버튼을 붙일 수 있습니다. 호버·포커스 시 표시하고 접근성 트리에는 항상 남기며, 우클릭·Shift+F10·메뉴 키로 같은 작업을 엽니다. `동작과 탐색 → Nav → 개요 고정`에서 선택 유지와 실행 횟수를 확인하세요. [API와 입력 규칙](../../docs/gallery-navigation.ko.md).

왼쪽 탐색은 공통 `Fluent.Nav`를 사용합니다. 그룹별 설명·아이콘과 미구현 배지를 유지하고 제목을 눌러 접고 펼칠 수 있습니다. `동작과 탐색 → Nav`에서 키보드·RTL 예제를 확인하세요. 테마 전환은 고정 헤더의 **밝은 테마** 토글입니다.

Windows에서는 `./run-gallery.ps1`을 실행하세요. 오른쪽 상단에서 밝음·어두움을 바꿀 수 있습니다. 왼쪽 메뉴는 구성요소를 기능별로 묶고, 그룹 안에서 알파벳순으로 표시합니다. 아직 없는 항목은 **미구현** 배지로 표시합니다. 본문 제목은 왼쪽 메뉴와 같으며, 각 예제의 설정과 미리보기 아래에서 해당 코드를 볼 수 있습니다. 아래에 나온 일부 한국어 이름과 실제 메뉴 이름의 대응은 [탐색 안내](../../docs/gallery-navigation.ko.md)를 참고하세요.

순서 입력 묶음은 모든 입력 순회를 유지하며 최종 그리기 하나를 구성합니다. **갱신 관찰 → CPU 구간 측정 → 측정값 확인**에서 입력 단계와 그리기 구성 수를 비교하세요. FPS는 표시 단계만 집계합니다. [공통 단계·커스텀 그리기·한계](../../docs/input-event-batches.ko.md#입력과-표시-단계).

공통 그리기 경로는 콜백 실패 후 미종료 레이어를 정리하고 이미 가져간 프레임을 유지합니다. 빌더 사용자는 출력을 소비하는 [Build 소유권 계약·집중 검사](../../docs/input-event-batches.ko.md#미게시-그리기의-소유권)를 확인하세요. 공통 입력/표시 단계는 위 계약으로 활성화되어 있습니다.

**갱신 관찰 → CPU 구간 측정 → 측정값 확인**에서 직전 종료 Render의 입력·그리기 구성 수, 준비·UI 구성·마무리 시간과 현재 스레드 할당량을 확인합니다. 측정 기본값은 꺼짐이고 결과 문구는 자동 갱신하지 않습니다. [범위·반복 가능한 진단](../../docs/input-event-batches.ko.md#cpu-처리-구간-측정).

Windows **입력·IME**에서 방향키를 누른 채 다른 앱으로 전환해 그곳에서 놓고 돌아오면 새 눌림 전까지 해제되어야 합니다. [소유 숨김 창 검사·한계](../../docs/input-event-batches.ko.md#windows-포커스-상실과-눌린-키)는 전역 입력 주입 없이 반복 마감과 눌림/상실/눌림 순서를 확인합니다.

Windows는 운영체제가 전달한 키 반복을 사용합니다. **입력·IME**에서 방향키를 길게 누르면 실제 반복에 따라 이동하며 유휴 렌더가 별도의 엔진 이동을 추가하지 않습니다. [반복 주체 검사](../../docs/input-event-batches.ko.md#반복-주체-선택)는 시각을 고정한 유휴 프레임과 전환으로 플랫폼·수동 엔진 호스트를 비교합니다. 마우스로 누른 스핀 버튼은 자체 반복을 유지합니다.

**입력·IME**에서 일반 문자나 방향키를 길게 누른 뒤 대기 입력이 처리된 텍스트·커서를 확인하세요. [네이티브 반복 검사](../../docs/input-event-batches.ko.md#네이티브-반복-횟수)는 소유한 숨김 창에 합쳐진 횟수를 직접 전달해 65535회와 분리 UTF-16도 재현합니다. 전역 키보드 입력을 바꾸지 않고 메타정보·실제 편집기·반복하지 않는 질의를 검사합니다.

`./run-gallery.ps1` 실행 후 **입력·IME**에서 개별 클릭·더블 클릭·방향키 길게 누르기를 비교하고 **숫자 입력**에서 스핀 버튼을 길게 눌러 보세요. 같은 호스트 묶음에 모인 이벤트도 입력 시각과 프레임·애니메이션 시각을 구분합니다. 큐 시각을 고정한 재현은 [시간 처리 검사](../../docs/input-event-batches.ko.md#이벤트-시간과-프레임-시간)로 실행합니다. 입력 전용 CPU 최적화나 실측 FPS 개선 완료를 뜻하지 않습니다.

`./run-gallery.ps1`로 새 Windows Observer를 열면 네이티브 입력을 순서대로 전달합니다. **입력·IME**에서 입력창을 바꾸며 문자와 복귀 커서를 확인하고 다른 탭으로 이동했다 돌아와 살아 있는 숨김 입력의 보존도 확인하세요. [네이티브 입력·수명과 App 검사](../../docs/input-event-batches.ko.md#windows-네이티브-순서-수집)는 각각 363개·37개가 통과했으며 실제 편집기 제거와 배율 1·2의 실제 작업 스레드·Vulkan 소비를 포함합니다. 소유한 입력의 폐기는 필수 `ReleaseInput` 계약으로 IME 대기 큐를 해제합니다. [사용자 정의 처리기 갱신](../../docs/windows-ime-routing.ko.md#제거한-입력과-숨긴-입력)도 확인하세요. 이미 실행 중인 창은 기존 바이너리를 유지합니다. 실제 키보드/TSF·후보 창 픽셀은 별도 수용 검증이 필요하며 Linux 수집은 아직 집계 방식입니다.

**입력·IME**에서 입력창 사이를 이동하며 조합·확정 결과와 원래 입력창의 복귀 커서를 확인하세요. 네이티브 메시지 전달 검사와 실제 키보드·TSF 서비스 전체 수용 검증은 구분합니다. [범위](../../docs/windows-ime-routing.ko.md).

**입력·IME → 한 줄 커서 예제**에서 일반 문자 입력과 Ctrl+V도 확인하세요. 선택 영역을 교체하거나 입력 길이 제한에 도달해도 최종 삽입 위치의 커서를 유지합니다. [검증 범위](../../docs/windows-text-shaping.ko.md).

**입력·IME → 한 줄 커서 예제**에서 문장 중간에 한글을 조합한 뒤 확정 전후 커서·후보 창 위치를 확인하세요. 조합 중 클릭·Shift 클릭·드래그 선택도 함께 확인할 수 있습니다. 양방향 문장의 확정 커서와 조합이 포함된 가로 스크롤 범위를 공통 입력 경로에서 수정했습니다. [검증 범위](../../docs/windows-text-shaping.ko.md).

Windows 접근성 글자 크기와 Linux X11 데스크톱의 DPI·글꼴 크기를 자동 적용합니다. `./run-gallery.ps1`로 새 창을 열고 **타이포그래피**를 위아래로 스크롤해 글자 가장자리를 확인하세요. 래스터 텍스트는 완성된 비트맵을 물리 픽셀에 맞추며 배율에 따라 배치 크기도 갱신합니다. [OS별 설정과 검증 범위](../../docs/system-typography.ko.md).

Windows 실행기는 증분 빌드 캐시와 실행 복사본을 분리합니다. 기존 창을 켜 둔 채 다시 실행해도 사용 중인 DLL을 덮어쓰지 않습니다. 실행별 경로는 콘솔의 `Observer runtime`에 표시되며 새 창에서 수정 내용을 확인할 수 있습니다.

상단 **V-Sync·이벤트 대기 모드** 라벨의 Windows 세로 정렬을 수정했습니다. **입력·IME → 한 줄 커서 예제**에서는 문장 중간에 커서를 두고 한글을 조합해 전체 문장·밑줄·커서·가로 스크롤을 확인하세요. 확정 전 원문 바인딩은 유지됩니다.

## 독립 아이콘

`Fluent.Icon(painter, new(24, 24), foreground)`로 장식용 위젯을 만듭니다. 컴파일된 글꼴·벡터 painter는 `UiMenuIcon.Create<TRegular, TFilled>()`, 기존 `UiSvgIcon`은 `svgIcon.MenuIcon`을 전달합니다. 독립 아이콘은 기본 regular 표현을 사용하며 포인터 동작·포커스 정지·호버 애니메이션을 등록하지 않습니다. 전경색은 명시적으로 전달합니다. SVG 원본 색은 painter에서 `MultiplyForeground`를 선택한 경우에만 전달한 전경색과 곱해집니다.

위젯은 painter를 빌려 씁니다. 위젯 → `UiSvgIcon` → 문서/store 순서로 해제하세요. SVG 파일 갱신은 기존 SVG 텍스처 경로를 통해 프레임을 요청합니다. 그대로 다시 그릴 때는 주기 프레임을 요청하지 않고 래스터·텍스처를 재사용합니다. `Size`·`Color`·`Icon` 변경은 프레임을 요청하며 잘못된 크기와 빈 painter는 오류로 처리합니다. 크기는 논리 레이아웃 단위이고 부모 제약에 따라 실제 할당 크기가 달라질 수 있습니다. 접근성 이미지 역할이나 버튼은 제공하지 않으므로 동작에는 이름이 있는 컨트롤을 사용하세요.

## 활동 링과 갤러리 스크롤

`avatar.Options = avatar.Options with { ShowActivityRing = true };`로 활동 링을 켭니다. `avatar.ActivityText = "활동 중";`으로 접근성 문구를 지정할 수 있습니다. 기본 이름에 활동 문구를 더하며 `AccessibleName`을 지정하면 그 값이 우선합니다. 이름은 속성 변경 때 저장합니다. 링을 표시해도 동작·포커스·호버·애니메이션 타이머가 없는 Image 하나입니다.

자연 크기에서는 본체가 선택한14개 크기를 유지합니다. 네이티브 레이아웃은 전체 시각 영역을 측정합니다. 본체48px 이하는 선2px,64px 이하는3px,그보다 크면4px이며 각 방향에 선 두께의2배를 예약합니다(본체32px→전체40px). 장식을 이웃 할당 영역에 덧그리지 않도록 공간을 확보합니다. 부모 영역이 작으면 본체와 간격을 같은 비율로 줄입니다. 원형·사각형과 밝음·어두움의 링 색은 기존 analytic 테두리 전용 primitive와 고정된 persona 팔레트를 재사용합니다. 간격에는 아무것도 칠하지 않아 아래 픽셀을 보존합니다. 크기·링 전환은 기존 이미지 텍스처 임대를 재사용합니다. `ShowActivityRing=false`는 일반 아바타로 돌아가며 Fluent의 비활동 표현 구현을 뜻하지 않습니다.

### 드래그로 이동하는 탭

`UiTabListOptions.Scroll = new UiTabListScrollOptions()`로 가로 헤더 스크롤을 켭니다. 기존 `Overflow` 메뉴 할당 방식과는 별도 선택이며 두 옵션을 동시에 켜지 않습니다. 상단 관찰 페이지는 이 스크롤 방식을 사용합니다.

탭 영역을 드래그하거나 휠로 움직입니다. 가려진 탭이 있는 쪽에만 `…`이 나타나므로 왼쪽·오른쪽·양쪽 표시가 가능합니다. 점 메뉴를 누르면 해당 방향의 탭 목록이 열리며 위치는 그대로 유지합니다. 항목을 고르면 원래 탭·본문을 선택하고 표시합니다. 가장자리 탭을 누르거나 키보드로 이동하면 선택한 탭뿐 아니라 그 방향의 이웃 탭 하나도 노출해 탐색을 이어갈 수 있습니다. 드래그를 놓는 동작은 탭 클릭으로 처리하지 않습니다.

하단 스크롤바는 별도 영역을 차지하지 않는 오버레이입니다. 기본120ms 나타남·400ms 정지 대기·160ms 사라짐을 적용하며 드래그 중에는 표시를 유지합니다. 공통 `UiScrollbarMotionOptions`로 시간·곡선·감소 모션을 설정하고, 탭별 재정의는 `UiTabListScrollOptions.Motion`으로 지정합니다. 애니메이션이 끝나면 다음 프레임 예약을 멈춥니다. [공통 전환 설계와 API](../../docs/finite-transitions.ko.md)를 참조하세요.


전체 스크롤바는 동일한 [공통 모션 모듈](../../docs/scrollbar-motion.ko.md)을 사용합니다.


접기·펼치기 헤더에 마우스를 올리면 손 모양 커서, 비활성 헤더에는 금지 커서가 나타납니다. Tab 포커스 테두리와 Enter·Space 조작도 확인하세요. 공식 기본 데모처럼 호버 배경은 투명합니다.

Markdown 이미지: **Markdown → 이미지 예제**를 누르면 캐시된 SVG·메모리 비트맵·사용할 수 없는 이미지의 대체 표시를 확인합니다. 스마트 편집으로 전환하면 현재 블록의 이미지 원문만 표시합니다.

Markdown 미리보기 링크: Tab·Shift+Tab으로 선택해 Enter로 이동하거나 손 모양 커서가 표시되는 글자를 클릭합니다. Windows 접근성에는 읽기 전용 주소와 Invoke·ScrollItem을 가진 Hyperlink 자식을 제공합니다. 드래그는 이동 없이 텍스트를 선택합니다. 남은 검증 범위는 Markdown API 문서를 참고하세요.

**중첩 링크 예제**를 누르면 같은 뷰어를 두 ScrollView 안에 넣은 **중첩 미리보기**로 전환합니다. Tab으로 처음·마지막 링크를 탐색하면 두 부모가 링크를 드러내며 Shift+Tab으로 돌아옵니다. 포커스가 같으면 수동 스크롤을 보존합니다. 일반 미리보기·스마트 편집도 같은 원문을 유지합니다.

공통 변환 팝업: **위젯 배치**에서 회전·확대·여백을 조절한 뒤 **변환 팝업**, **변환 메뉴**, **변환 도구 설명**을 사용하세요. 트리거는 변환되지만 팝업은 화면 좌표로 바로 서서 열립니다. 부모의 회전·클립·포인터·접근성·IME 좌표를 공통 범위에서 분리하고, 닫으면 이전 위젯 좌표를 복원합니다. 지연 Tooltip도 화면 앵커를 보관하며 마우스가 창 밖에 있어도 호출자 표시 상태를 유지합니다. 선언형 Popover·메뉴·Tooltip과 기존 BeginPopup·BeginTooltip·모달·Combo·메뉴 경로를 검증했습니다. 임의 3D 카메라의 모든 조합과 화면 읽기 적합성은 남아 있습니다.

위젯 배치 → 기존 팝업 API에서 공통 회전·확대를 적용한 채 열기·실행·닫기를 확인합니다. 기존 Combo의 세 오버로드는 공통 화면 앵커 계산을 사용합니다. 팝업 너비는 원래 본문 너비와 변환된 트리거 너비 중 큰 값이며, 부모의 회전 클립을 벗어나 화면 안에 배치합니다. 화면 팝업은 부모의 벡터 텍스트 강제를 상속하지 않습니다.

메시지 표시: 스크롤 가능한 페이지에서 **표시할 때 자동 공지**와 **차분한 공지로 고정**을 전환하고 공지 요청 수를 확인하세요. 실제 제목 관계와 표시·우선순위 변경에 따른 한 번의 공지를 지원하며, 재정렬·삭제는 공지를 반복하지 않습니다. 요청 수는 발화 완료 수가 아닙니다. MessageBar 12/13, 전체 적합성은 구현 중입니다. [API·범위](../../docs/fluent2-messagebar.ko.md).

메시지 표시 → **오른쪽에서 왼쪽 배치**로 실제 슬롯과 액션 배치를 전환합니다. 공통 `UiWrapOptions.RightToLeft`는 자식의 X 위치를 반전하며 탐색·행 순서는 유지합니다. 임의 자식의 문단 양방향 조판을 보장하는 옵션은 아닙니다. 전체 MessageBar 12/13은 유지합니다.

MessageBar 현재 계약은 12/13입니다. 실제 제목 연결과 자동 공지를 Windows UIA 클라이언트 검사 8개·호스트 검사 1개, Linux 고정 RC3 NativeAOT AT-SPI 클라이언트 검사 9개·호스트 검사 3개로 확인했습니다. 전체 문단 RTL은 남았고 Windows NativeAOT는 별도 관문입니다. 기존 검증된 Linux 옵저버는 유지합니다.

메시지 표시의 여러 행·각진 모서리·방향·공지 옵션은 새 동적 메시지에도 동일하게 적용됩니다. 실제 조작 34개와 Windows 38·Linux 41·전달 실행기 38개 표시 시나리오를 확인했습니다. 현재 MessageBar 12/13, 전체 RTL·줄바꿈은 남았습니다.

## 독립 예제와 동등한 소스

각 메뉴는 서로 다른 페이지를 유지합니다. 같은 페이지를 가리키는 메뉴가 생기면 시작 검사에서 실패합니다. 종합 화면을 공유하던 구성요소 21개를 독립 예제로 나누고, 기존 종합 화면은 **종합·회귀 예제** 그룹으로 옮겼습니다. 각 페이지 하단에는 선택·복사할 수 있는 읽기 전용 C# 소스를 표시합니다. 소스 영역은 본문과 별도로 가로·세로 스크롤합니다.

독립 예제의 소스는 실제 실행하는 팩터리 식을 `CallerArgumentExpression`으로 가져옵니다. 기존 복합 예제는 빌드할 때 포함한 실제 `.cs` 파일을 표시합니다. 실행할 때 저장소 파일을 읽지 않습니다. 복합 예제의 원본 파일은 갤러리 프로젝트의 보조 타입과 참조를 함께 사용합니다. 미구현 메뉴에는 실행 가능한 소스가 없음을 명시합니다.

`UiViewHost`는 호출자가 소유하는 `IUiView`를 유한한 배치 영역에 담습니다. 순서대로 그리는 화면의 각 위젯이 전체 영역을 상속하지 않게 하며 자식 클리핑·팝업 계층·중첩 창의 좌표를 구분합니다. 인라인 Drawer는 공통 `UiFloatTransition`으로 차지하는 공간과 보이는 영역을 함께 바꿉니다. 내용 크기는 유지하고 반대 방향으로 전환하면 현재 크기부터 이어갑니다. 닫히는 즉시 입력과 접근성 노드는 제거합니다. 처음부터 열린 인라인 패널은 바로 배치하고 이후 변경을 애니메이션으로 표시합니다. `MotionEnabled`가 false이면 즉시 반영합니다. [검증 기록](../../artifacts/gallery-source-2026-11-17/verification.json).

갤러리 예제 코드에서는 공통 네임스페이스인 `using Duxel.Core;`만 생략합니다. 실제 프로젝트 파일과 범용 `UiCodeView`의 원문은 변경하지 않습니다. 다른 using과 문자열 안의 같은 문구는 보존합니다. 예제를 별도 앱에 옮길 때는 프로젝트 수준에서 `Duxel.Core`를 가져오세요.

`GallerySample.BindSource`는 현재 설정의 형식 있는 스냅샷을 비교하고 바뀐 경우에만 해당 코드 블록을 갱신합니다. Rating의 색상·모양·방향·선택 값·리뷰 수는 실제 설정과 동기화됩니다. 현재 예제별 소스 배치는 카드·타이포그래피·Rating·Avatar에 적용했으며, 다른 복합 페이지의 분리와 설정 동기화는 계속 진행 중입니다.

탐색 메뉴는 Fluent 컨트롤, Duxel 위젯, 통합·개발 도구를 별도 영역으로 구분합니다. 이름의 한글·영문 여부로 분류하지 않습니다. `Fluent.Nav`는 Fluent 2의 Nav 디자인과 동작을 Duxel 엔진에서 구현한 구성요소이며 Fluent 영역에 유지합니다. 범용 기반 타입 `UiNav<TPresentation>`과 해당 스타일 구현을 구분합니다. SVG·Markdown·배치·가상화는 Duxel 영역에, 갱신·측정·렌더링 관찰은 개발 도구에 배치합니다.
